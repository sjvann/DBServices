# Epic 2 Context: 林可只依已確認註記包定義檢視

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

系統分析師在模組設計工具定義檢視時，左側只來自目前唯一啟用的已確認註記包，不再讀活庫結構。空白欄註必須被看見；包外的表欄與自造關聯都不能存進去。檢視文件的形狀、發布、樣式、Chat 與生成紀錄維持不變，執行期讀列仍只走已發布檢視。同一份啟用包另經 MCP 給後續設計引用，且該表面不讀業務列。

## Stories

- Story 2.1: 設計清單只讀已確認註記包
- Story 2.2: 多張來源表必須用已聲明關聯
- Story 2.3: 檢視契約維持，已確認包經 MCP 引用

## Requirements & Constraints

設計清單只含啟用包的表、欄、型別、註解與已聲明關聯。草稿、已退出啟用的包、包外的表或欄都不出現。沒有啟用包時清單是空的，文案是「資料來源尚未註記」，不能從這裡選表或欄。欄註空白標成「尚未註記」；這兩句不能互換，空白也不阻擋把該欄選為輸出欄。再讀來源但尚未再次確認時，清單仍是上一份啟用包。組清單不連二代平台、不連待轉庫、不讀業務列、不含連線字串，也不呼叫結構圖或待轉庫的結構端點。

只有一張來源表時不要求關聯。兩張以上時，每一段的兩端表與欄必須等於啟用包內某一條已聲明關聯；方向對調仍算同一條，理由不必相同。一段對不上就整次拒絕保存，既有檢視、已確認包與草稿都不變。分析師沒有另造關聯的操作。可選關聯只來自這份包。

檢視仍含名稱、目的、來源表、關聯、輸出欄與參數，不含業務列與連線字串。文件欄位不增不減，既有的確認旗標意義不變。未發布不進 MCP 目錄；發布後才出現。沒有啟用註記包時，既有已發布檢視仍留在目錄。執行期讀列仍走已發布檢視，不改走註記包，也不提供自由 SQL。樣式範本、Chat 報表生成器與報表生成紀錄維持不變，只消費已發布檢視。

啟用包同時經 MCP 給後續設計階段：回傳表、欄、型別、註解與已聲明關聯，不含草稿、非啟用包、連線字串與業務列。沒有啟用包時不回退成即時結構或表級工具。該表面不讀列、不接受 SQL、不寫入來源庫。

這一輪不做 AI 輔助建立檢視，不在設計階段另造關聯，不做註記站的 Discovery 或 MCP 工具畫面。資料治理與模組設計不併成同一套左軌。新錯誤用繁體中文，含穩定代碼，不含連線字串、密碼、堆疊秘密或業務列。保存失敗時已保存的檢視不變。

## Technical Decisions

設計清單與 MCP 引用讀同一個目錄方法，對象是 `confirmed` 且 `active` 的那一份，同時最多一份。檔仍在 `McpService` 內容根的註記目錄，由 `DbServices.Mcp` 寫入；工作台 SQLite 不放註記包。檢視文件仍只在 `DbServices.Mcp`。`Workbench.Web` 不直接呼叫結構圖；啟用包讀取是 `/mcp` 之外的 `GET /annotations/active`。沒有啟用包時回空結果，不是錯誤。

Discovery 的名稱等於已發布檢視，並且只在有啟用包時加上保留名 `source_annotation`。這是「只列已發布檢視」的唯一例外。工具沒有參數，不接受連線識別或 SQL；唯讀、非破壞。沒有啟用包時該名不在 Discovery，呼叫回 `unknown_tool`，不讀結構、不回退成 `tables`、`fields`、`get`、`query`、`count`、`exists`。檢視名稱不得與 `source_annotation` 相同，比對不分大小寫。回傳不含 `draft` 與 `active` 為 false 的包。

註記包關聯是 `from`、`fromColumn`、`to`、`toColumn`、`origin`、`note`。`origin` 只許 `foreign-key` 或 `declared`。寫入檢視時前者的 kind 為 `foreign-key`，後者為 `accepted`。不新增第三種 kind。比對是否已聲明只看兩端表與欄。檢視文件欄位仍是 id、name、purpose、confirmed、published、sources、links、parameters、columns。目錄寫入沿用既有呼叫者標頭與工作台標頭。

設計站這次拒絕的代碼是 `link_undeclared`，訊息是「這段關聯不在註記包裡。」錯誤鍵是 `code` 與 `message`。不要用既有 MCP 工具錯誤清單來表示它。不新增套件、不升版。

## UX & Interaction Patterns

模組設計工具是系統分析師入口既有的「檢視」。左側改接啟用包；編輯器其餘行為維持現況。沒有另造關聯的控制。

沒有啟用包時左側只顯示 empty-catalog：「資料來源尚未註記」，次要文字色，沒有插圖。欄註空白用 unmarked-badge，文字固定「尚未註記」：警示色字在下凹表面上，全圓角。徽章必須有文字。不要用危險色表示空白欄註。

關聯不在包裡而保存被拒時，用既有 status-message：`role="alert"`，人讀的句子在上、代碼在下。不要畫成進行中或成功。視覺只沿用工作台既有色票，不做深色模式。資料治理的「註記」不與檢視、樣式、產生報表排在同一組。

## Cross-Story Dependencies

本史詩只消費上一史詩留下的唯一啟用包，不實作匯入、再讀或確認。未確認草稿與已退出啟用的舊包不進設計清單，也不進 `source_annotation`。

Story 2.1 的清單是 2.2 的比對來源，也是 2.3 對外暴露的同一份包。2.2 不改檢視欄位；2.3 維持文件形狀與發布閘門，並讓 Discovery 在有啟用包時多出該保留名。

再次確認若會把已保存檢視的來源表、輸出欄或關聯端點擠出新包，由上一史詩拒絕，且不改寫、不取消發布。通過後設計端才改看新包。本史詩不因啟用包切換而下架或改寫既有檢視。樣式、Chat 與生成紀錄不讀註記包。AI 輔助建立檢視與新關聯留到後續。

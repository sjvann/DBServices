## What the inputs require

### 檢視與報表 PRD（2026-10-12）— 規劃期目錄

- 模組設計工具的規劃期目錄是二代平台資料源的表與欄，不是待轉庫。「系統分析師在規劃期可看到二代平台資料源的資料表與欄位。」「這份結構不來自待轉資料庫，也不要求先完成轉置。」（FR-4）
- 旅程寫法相同：「她看到二代平台的資料表與欄位，不是待轉資料庫。」（UJ-1）
- 畫面上沒有連線字串；不提供自由 SQL；不對二代平台來源庫做新增、更新、刪除。沒有資料表時清單是空的。（FR-4）
- 三個入口都不讓人選擇連線或 Web API。（第 4.2 節說明、第 9 節）
- 兩張以上來源表時，每一段關聯要麼是目錄裡的外鍵，要麼是分析師寫明並接受的關聯；否則拒絕保存，不產生笛卡兒積。（FR-5）

### 檢視與報表 PRD — 開放問題 8

「規劃期讀取二代平台表結構的通道仍未定。定案前不得用待轉資料庫的 `GET /meta` 充當，也不得為了這份結構讀業務列，也不把連線字串帶進模組設計工具。」（第 8 節問題 8）

同句約束還寫在第 11 節執行邊界：「規劃期的表結構通道未定，不得用待轉資料庫充當。」十月附錄（2026-10-20）仍把「規劃期表結構通道」列為未定。

### 檢視與報表 PRD — 二代平台資料源

「二代平台資料源：規劃期的表結構從這裡來。讀取通道留給架構。這一讀不經過待轉資料庫。」（第 13 節）

待轉庫是 ETL 寫入端。web API 是「待轉資料庫的結構讀取與轉置通道」，「這一輪不用它產生動態報表，也不用它充當規劃期的表結構。」（詞彙、第 13 節）

第 12 節：「系統分析師在規劃期看得到二代平台的表結構。」業務列不在這次規劃讀取裡。

### 檢視與報表 PRD — 檢視文件含什麼

詞彙與 FR-5：一筆檢視含名稱、目的、來源表、關聯、輸出欄與參數。參數是等值篩選的欄位與標籤，不含值。定義在模組資料庫，沒有業務列與連線字串。

十月附錄的文件形狀是 `id`、`name`、`purpose`、`published`、`sources`、`links`（`from`／`to`／`by`）、`parameters`（`field`／`label`）、`columns`。「沒有 `connectionString`，也沒有 `rows`。」

名稱在模組資料庫內不重複。尚未被樣式範本引用者可修改、取消發布與刪除。仍被引用者不能刪除、不能取消發布，也不能改名稱、輸出欄或參數；目的文字可以改。（FR-5）

### 檢視與報表 PRD — 發布

「系統分析師發布檢視之後，MCP 的目錄才出現它。」發布表示分析師確認目的、來源表、關聯、輸出欄與參數。「資料平面所稱的解說就是這些欄位，不另寫第二份文件。」（FR-6）

「MCP 目錄的名稱集合等於已發布檢視的名稱集合。」未發布不在目錄裡。「目錄是空的時候，不改列資料表工具。」發布與呼叫都不修改二代平台來源庫的結構。（FR-6）

UJ-1：發布就是分析師確認這筆定義。未發布前目錄裡沒有它。

這一輪已發布檢視的列由 MCP 依定義即時讀取，不先落地。（FR-7）Chat 讀列只在意圖就緒後，恰好呼叫該檢視一次；人不選連線；恰有一筆具名連線才綁定，零筆或多筆則不呼叫、讀列次數為 0。（FR-13）三個入口不以 `anonymous` 呼叫 MCP。（FR-1）

### 資料平面 PRD — 誰可以讀列

公開表面只讀已發布模組視圖的列。「執行時依該定義唯讀取出列。」未發布不在 Discovery。視圖名稱未知時拒絕，「不改落到表級 `query`。」（FR-16、FR-18、FR-21）

表級 `get`／`query` 等仍能取列，但「不是 Agent 的公開目錄」；若宿主仍實作，只在與 Discovery 分開的營運除錯路徑。（FR-3、FR-6、FR-7）空的 Discovery 不回退成表級工具。

誰可以叫：呼叫者是傳輸層識別；沒有識別時記為 `anonymous`，且「呼叫仍可執行」。（UJ-1、第 9 節）「完整登入與授權」不在此增量。「正式授權模型未決。」（第 6.2 節、第 8 節問題 2、第 13 節）稽核含呼叫者、連線名稱、列數或錯誤碼，「不含列內容。」（FR-21）

### 資料平面 PRD — 連線字串放哪

具名連線在伺服器組態，含名稱、`ServerType`、連線字串。工具只接受名稱。（詞彙、FR-10）

「只有伺服器進程讀得到連線字串。」「連線字串只存在伺服器組態與既有連線工廠。工具結構、錯誤、稽核不攜帶它。」（FR-10、第 12 節）參數不得提供連線字串。（FR-11）附錄：「連線字串不進工具、錯誤、稽核、側車輸入。」

未帶名稱時：恰有一個具名連線就用它；零個或多個則要求指定名稱。（FR-12）這與十月工作台「人不選連線、多筆則不呼叫」不是同一條規則。資料平面允許一筆以上具名連線，Agent 用名稱選定。（第 4.3 節、UJ-2）

### 資料平面 PRD — 設計期目錄是否在範圍

不在此增量。非目標與第 6.2 節：在第一條人手寫視圖證明 Discovery 之前，不交付拖拉設計應用，也不抽出關聯讀取程式庫。「設計器真正要讀目錄關聯時，再在資料表 Web 上加唯讀端點。」

第 10 節（無 FR 編號）：拖拉設計「在那之前不做。它讀資料表 Web 的結構。」附錄：ExportData 的目錄關聯讀取「是設計時的輸入，不是服務表面。」「在手寫視圖證明 Discovery 之前先做拖拉設計器」是被拒絕的做法。

資料平面自己的「產品目錄」是已發布模組視圖定義，不是規劃期表目錄。表級工具不是那個目錄。

## Covered by the new PRD

- **開放問題 8 的三條禁令。** 附錄「明確不做」：不用待轉庫 `GET /meta` 充當二代平台結構。FR-2、FR-3、FR-6、SM-5：註記路徑不讀業務列。FR-5、FR-7 與附錄約束 2：連線字串不進註記站、草稿、已確認包、DBML、日誌與模組設計工具。
- **通道改成已確認註記包。** FR-7、第 7 節接點 4：規劃期清單只來自已確認包，不是即時連線目錄，也不是待轉庫結構端點。沒有已確認包時清單為空，並說明尚未註記。未確認草稿不進設計端。（FR-5）
- **檢視文件欄位集合。** 附錄約束 5：`ViewDocument` 仍是 id、name、purpose、sources、links、parameters、columns、published；改變的是候選來自哪裡。FR-8：仍含名稱、目的、來源表、關聯、輸出欄與參數；定義裡沒有業務列與連線字串。
- **發布行為用引用維持。** FR-8 寫明建立、修改、發布與 MCP 包裹維持十月 FR-5 至 FR-7。UJ-3：發布後 MCP 目錄才出現該檢視；未發布不在目錄。附錄：註記包不是 MCP 工具。空目錄不回退表級工具因此仍靠十月 FR-6，新 PRD 沒有另寫一條相反規則。
- **註記站不讀列。** 附錄約束 1、3：確認包只供給設計期目錄；從資料庫只讀表、欄、型別、鍵、外鍵。這沒有把註記包放進 Discovery。
- **連線字串仍只在伺服器。** 新 PRD 第 1 節與附錄約束 2 延續「不進客戶端表面」。人不能在註記站選擇連線；零筆或多筆具名連線則不讀結構。（FR-3）
- **不改樣式、Chat、報表生成紀錄。** FR-8 後果寫明不改這三塊。十月對「就緒後才讀列、一次已發布檢視、私有紀錄只有擁有者」的規則沒有被新文字撤銷。

## Gaps

### G1 — 規劃期結構仍須來自二代平台，且不經過待轉庫

- **引文：** 「規劃期的表結構從這裡來。讀取通道留給架構。這一讀不經過待轉資料庫。」（十月第 13 節）「這份結構不來自待轉資料庫。」（FR-4）「她看到二代平台的資料表與欄位，不是待轉資料庫。」（UJ-1）
- **新 PRD：** 把通道定成已確認註記包，並禁止用待轉庫 `GET /meta` 充當。FR-3 改從「恰有一筆組態完整的具名連線」讀結構；這條「恰有一筆」與十月 FR-13 用來綁定執行期讀列的是同一條規則，而執行期讀的是 ETL 寫入之後的待轉資料。Excel 匯入也可以在完全不讀二代平台的情況下確認一包，並成為設計目錄（FR-2、FR-7）。
- **沉默或衝突：** 沒有寫這筆具名連線必須是二代平台資料源，也沒有寫結構讀取不得落在待轉庫。禁的是 `GET /meta` 這一個端點，不是「待轉庫結構本身」。Excel 路徑沒有要求字典必須對應二代平台資料源。
- **嚴重度：** high

### G2 — 宣稱不改寫十月正文，但 FR-4 與「通道未定」仍是 final

- **引文：** 十月 FR-4、UJ-1、第 11 節「規劃期的表結構通道未定」、第 12 節「系統分析師在規劃期看得到二代平台的表結構」、第 13 節與開放問題 8 仍是 final 正文。新 PRD 附錄：「不改 FR-5～FR-16 正文。本 PRD 回答其開放問題 8。」新 PRD 第 9 節：「不改寫檢視與報表 PRD 的檢視／樣式／Chat 契約正文。」
- **新 PRD：** FR-7 已經換成另一份規劃目錄（已確認註記包，含註解與人手關聯），系統分析師不再看到即時二代平台結構。這改的是 FR-4 與第 11、12、13 節，不是 FR-5～FR-16。
- **沉默或衝突：** 沒有列出十月 final 裡哪些句子因此失效。兩份同時有效時，規劃目錄仍是「未定通道下的二代平台即時結構」，同時又是「已確認註記包」。
- **嚴重度：** high

### G3 — 誰可以讀列：新 PRD 只指向資料平面

- **引文：** 資料平面：「沒有識別時記為 `anonymous`，呼叫仍可執行。」「正式授權模型未決。」表級 `query` 在營運除錯路徑仍可取列。（UJ-1、第 13 節、FR-3、FR-7）十月更嚴：三個入口不以 `anonymous` 呼叫；業務列只在就緒後經一次已發布檢視出現；私有報表生成紀錄只有擁有者可讀。（FR-1、FR-12、FR-13、第 12 節）
- **新 PRD：** 開宗明義「資料怎麼被安全讀取，仍以資料平面 PRD 為準。」附錄：「執行期讀列與工具目錄規則不變。」註記站讀列次數為 0 寫清楚了。FR-8 只說不改 Chat 與報表生成紀錄，沒有重申呼叫者是誰。
- **沉默或衝突：** 兩份上游對「誰可以讀到列」不一致。新 PRD 把執行期讀列歸給資料平面，沒有寫十月已收緊的呼叫者（已登入、非 anonymous、就緒後的終端使用者、共享範圍）仍然優先。資料平面的除錯路徑讀列也沒有被標成與註記站無關、且不可用來補設計目錄。
- **嚴重度：** medium

### G4 — 設計期目錄在資料平面不在範圍；讀取端點也不一致

- **引文：** 「不在第一條人手寫視圖證明 Discovery 之前，交付拖拉設計應用。」「設計器真正要讀目錄關聯時，再在資料表 Web 上加唯讀端點。」（資料平面第 5 節、第 6.2 節、第 10 節）附錄把「先做拖拉設計器」列為被拒絕的做法。ExportData 的目錄關聯讀取「是設計時的輸入，不是服務表面。」
- **新 PRD：** 設計期目錄做成註記站的已確認包，並寫明註記包不是 MCP 工具、Discovery 規則不變。結構讀取改走 `SchemaGraph.Read` 與已登記連線，不是資料表 Web 的唯讀端點。（附錄「資料庫讀入與 SchemaGraph」）
- **沉默或衝突：** 「不進 MCP」對上了公開目錄約束。沒有寫這份設計期目錄是否提前了資料平面「證明 Discovery 之前不做」的範圍，也沒有寫 `SchemaGraph` 是否取代尚未決定的資料表 Web 端點。十月 2026-10-18 已把模組設計工具納入工作台，但新 PRD 沒有引用該覆寫來結束資料平面的範圍句。
- **嚴重度：** medium

### G5 — 再次確認註記包之後，已發布檢視怎麼辦

- **引文：** 十月 FR-6：MCP 目錄等於已發布檢視；發布後定義可被呼叫。FR-5：被樣式範本引用的檢視不能改輸出欄或來源側的名稱與參數。FR-7：列來自該筆已發布定義。資料平面 FR-18：呼叫若帶入未宣告的表名或欄位，宿主拒絕。
- **新 PRD：** FR-6：再次確認前，設計端仍用上一份已確認包；再次確認後改看新包。新增、刪除、型別改變只要求在註記草稿裡可見。第 10 節只保證確認失敗時已保存的檢視定義不變。
- **沉默或衝突：** 沒有寫再確認成功、且新包刪了欄或表之後，已經發布、甚至已被樣式範本引用的檢視是否仍留在 MCP 目錄、是否仍可讀列。設計端「不能選包外的表欄」（FR-7）沒有延伸到已存在的檢視文件。
- **嚴重度：** medium

### G6 — 檢視關聯欄位 `by` 與註記包的欄對欄關聯

- **引文：** 十月附錄檢視文件的 `links` 是 `from`、`to`、`by`。新 PRD 附錄約束 5 說這組欄位不變。註記包的 `links` 卻是 `from`、`fromColumn`、`to`、`toColumn`、`kind`、`note`。
- **新 PRD：** 只寫候選來源改為註記包，以及分析師另寫的關聯仍須兩端表欄都在包內。
- **沉默或衝突：** 沒有寫已聲明關聯如何收成檢視文件裡的單一 `by`。文件形狀被宣稱為不變，對照規則沒有寫。
- **嚴重度：** low

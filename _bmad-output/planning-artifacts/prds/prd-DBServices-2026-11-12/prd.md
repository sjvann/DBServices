# PRD: DBServices 資料來源註記

本 PRD 給產品、體驗、架構與後續故事拆解使用。它定義一個獨立的前置入口：**資料來源註記**。人把 Excel 資料字典或資料庫結構讀進來，補上表、欄、關聯與整體功能說明，確認後的 **DBML** 成為後續所有設計階段的結構與語意依據。

既有 [檢視與報表 PRD](../prd-DBServices-2026-10-12/prd.md) 的檢視文件形狀、發布、樣式範本、Chat 報表生成器與報表生成紀錄維持不變。本文件取代該 PRD 的規劃期目錄：系統分析師看到的是已確認註記包，不再在模組設計工具裡讀即時結構。註記包代表二代平台資料源。確認前，實體表名與實體欄名必須對上那座來源；對不上就拒絕確認，草稿維持。待轉資料庫不是這座來源。被取代的句子列在第 7 節。資料怎麼被安全讀取，仍以 [資料平面 PRD](../../../../docs/planning/agent-data-plane/prd.md) 為準。技術對應見 [addendum.md](addendum.md)。詞彙以第 3 節為準。推論標成 `[ASSUMPTION]`，並彙總在第 9 節。

## 1. Vision

二代平台的資料已由既有 ETL 寫入待轉資料庫。檢視、樣式與報表要能回答業務問題，先要有一份人能讀的來源註記：整包在做什麼、表與欄的說明、關聯為什麼這樣連。欄註可以先空白，但空白必須在設計清單上被看見。

缺的不是再疊一層查詢工具，而是一項資料治理的最基本工作：為資料來源註記。操作者從 Excel 字典或已登記連線的結構進入同一套編輯模型，補上表、欄、關聯與整體說明，匯出並確認一份 DBML。確認過的註記包成為模組設計工具的目錄。樣式範本與 Chat 仍只消費已發布檢視。空白欄註可以確認，設計清單要把該欄標成「尚未註記」。

這一輪要證明的是：設計期目錄來自已確認的註記，而不是裸的即時結構；註記站不讀業務列；確認過的實體表名與實體欄名對得上二代平台資料源。執行期讀列仍走已發布檢視。連線字串留在伺服器。

## 2. Target User

### 2.1 Jobs To Be Done

- 資料治理人員要把一份來源（Excel 或資料庫結構）註記到可交給設計使用，並確認成 DBML。
- 系統分析師要在模組設計工具只看到已確認註記包裡的表、欄、型別、註解與已聲明關聯，據此定義檢視。
- 管理員要決定誰可以打開資料治理入口。

### 2.2 Non-Users (v1)

- 要改 ETL、或把註解寫回來源資料庫的人。
- 要在註記站輸入自由 SQL、讀業務列、貼連線字串，或選擇「走 MCP 還是走 Web API」的人。
- 報表設計師與終端使用者。他們不編輯註記，仍只消費已發布檢視。
- 要在註記站執行個資遮罩或去識別化的人。這一輪只保存 Excel 上的處理註記文字。
- 未登入的人。

### 2.3 Key User Journeys

**UJ-1. 方晴用 Excel 把清單異動表註記成可確認的 DBML。**

- **Persona + context：** 方晴負責資料治理。她手上有 `Samples.xlsx` 這類 H/S 雙側字典，要讓後面的系統分析師不用猜欄位意思。
- **Entry state：** 她已登入，且持有資料治理入口。
- **Path：** 她匯入 Excel。工具帶出 S 側實體表與欄、H 側型別與描述、唯一索引勾記、允許空白、表級說明。她補上整包功能說明，必要時改表註、欄註與關聯說明，存成草稿，再匯出 DBML 核對。確認時，工具把每個實體表名與實體欄名對上二代平台資料源。都對得上，她才確認這份註記包。
- **Climax：** 確認後，模組設計工具的資料表清單出現這份結構與註解。未確認前，設計端看不到它。
- **Resolution：** 註記包與匯出的 DBML 不含業務列與連線字串。來源庫結構沒有被改動。匯出本身不要求已對上活庫。
- **Edge case：** Excel 缺必要欄位或工作表對不上契約。工具拒絕匯入，既有草稿不變。實體名對不上二代平台資料源、或當時沒有恰好一筆可對帳的二代平台連線時，拒絕確認，草稿與已確認包都維持原樣，讀列次數為 0。

**UJ-2. 方晴從資料庫讀結構，補完註解後才交給設計。**

- **Persona + context：** 同一人。這次沒有完整 Excel，但伺服器已有一筆組態完整的具名連線。
- **Entry state：** 她已登入，且持有資料治理入口。連線數恰好一筆。
- **Path：** 她選擇從資料庫讀入。工具帶出表、欄、型別、主鍵、外鍵；註解留空。她補上整包功能說明、表註、欄註，並為庫裡沒有外鍵的關係寫明關聯。理由可以空白。她存草稿、匯出 DBML，再確認。
- **Climax：** 確認後的包含她手寫的語意與關聯，設計端看得到。
- **Resolution：** 讀結構過程不讀業務列。畫面沒有連線字串。
- **Edge case：** 零筆或多於一筆具名連線，或那一筆是待轉資料庫。工具不讀結構，讀列次數為 0，並顯示可讀錯誤。

**UJ-3. 林可只依已確認註記包定義檢視。**

- **Persona + context：** 林可是系統分析師。她要定義清單相關檢視。
- **Entry state：** 她已登入，且持有系統分析師入口。方晴已確認一份註記包。
- **Path：** 她打開模組設計工具。左側清單來自已確認註記包，含表、欄、型別、註解與已聲明關聯。欄註空白的欄標成「尚未註記」。她選來源表與關聯，寫目的與輸出欄，保存並發布檢視。
- **Climax：** 她選的來源與關聯都是註記包裡已聲明的。發布後 MCP 目錄出現該檢視，行為與既有檢視與報表 PRD 相同。
- **Resolution：** 檢視定義仍是名稱、目的、來源表、關聯、輸出欄與參數。沒有業務列與連線字串。她沒有在這一階段新造資料表關聯。
- **Edge case：** 沒有任何已確認註記包。左側清單是空的，並說明資料來源尚未註記。她不能靠即時連線結構繞過。她要的關聯不在已聲明清單裡時，保存被拒絕，既有檢視定義不變。

**UJ-4. 來源結構變了，方晴再讀一次並保留舊註記。**

- **Persona + context：** 方晴先前已確認一包。來源庫新增一欄、刪掉一欄，並改了一欄的型別。
- **Entry state：** 她已登入，且持有資料治理入口。設計端仍在用上一份已確認的包。
- **Path：** 她再讀一次來源。實體表名與實體欄名相同的註記留在草稿。新增、刪除、型別改變另列給她看。她調整後存草稿。在她再次確認之前，林可左側仍是上一份已確認的包。
- **Climax：** 再次確認時，若每一筆已保存檢視的來源表、輸出欄與關聯端點都還在新包裡，設計端改看新包。
- **Resolution：** 未再次確認前，設計目錄不變。再讀過程不讀業務列。確認成功後，新包是唯一啟用包；先前那份不再進入設計目錄，但保留不刪，已保存檢視也不改寫。
- **Edge case：** 她放棄草稿。已確認的包維持原樣。若再次確認會讓任一已保存檢視的來源表、輸出欄或關聯端點落到新包之外，拒絕確認，訊息列出這些檢視的名稱；舊包與檢視維持原樣。

## 3. Glossary

- **資料來源註記** — 本 PRD 定義的前置作業。把來源結構加上人寫的語意，產出可確認的註記包與 DBML。
- **註記站** — 資料治理入口打開的工作站。資料來源註記在這裡進行。
- **資料治理入口** — `[ASSUMPTION]` 管理員可指派的新入口。持有者可進入註記站。一人可同時持有資料治理與系統分析師等其他入口。
- **註記包** — 一份可含多張表的註記工作單位。含整包功能說明、表、欄、關聯、索引語意、草稿或已確認狀態。設計階段只消費已確認的包。
- **DBML** — 註記包的可攜帶表達。確認與匯出都以它為人與後續工具核對的格式。驗收以 `Requirements/LH_TXN_MLST.sample.dbml` 為準。
- **H 側** — Excel 字典裡來源／畫面側欄位：檔案名稱、欄位序號、欄位名稱、資料類型長度、資料描述、個資去識別化處理。
- **S 側** — Excel 字典裡實體表側欄位：檔案名稱、欄位序號、欄位名稱、資料類型／畫面格式、資料長度、唯一索引。
- **二代平台資料源** — 沿用檢視與報表 PRD 的用法：規劃期結構所代表的那座來源，這一讀不經過待轉資料庫。本文件裡，註記站只向這座來源讀結構，也只拿它做確認對帳。
- **實體表名／實體欄名** — 會進入檢視來源的名字。Excel 路徑的表名是 S 側檔案名稱，欄名是 S 側欄位名稱。S 側欄名空白時，實體欄名用 H 側欄位名稱（樣品的 `TABLE_DATE`）。
- **已聲明關聯** — 註記包內由人寫明的表間關係。可來自資料庫外鍵，也可由人補上庫裡沒有的外鍵，並可附理由。
- **確認** — 資料治理人員把草稿標成可供設計使用。整包功能說明不是空白，且至少有一張表、一個欄；實體名對得上二代平台資料源；不會把已保存檢視擠出包外。未確認的草稿不進入模組設計工具。
- **模組設計工具／檢視／樣式範本／MCP** — 沿用檢視與報表 PRD 第 3 節。本文件不重新定義它們。

## 4. Features

### 4.1 資料治理入口

**Description：** 註記站只讓已登入且持有資料治理入口的操作者使用。入口指派沿用既有管理員流程。實作 UJ-1 至 UJ-4 的進入邊界。

**Functional Requirements：**

#### FR-1: 指派資料治理入口

管理員可為操作者指派或取消資料治理入口。

**Consequences (testable)：**

- `[ASSUMPTION]` 入口代碼為 `governance`，畫面上的名稱是「資料治理」。
- 未持有該入口的人打不開註記站。
- 一人可同時持有資料治理與系統分析師等其他入口；打開某一站時，只看到該站的工作內容。
- 帳號與入口指派仍在產品自己的存放，不在業務庫。

### 4.2 讀入來源

**Description：** 兩種進入方式進同一套編輯模型。都不讀業務列。畫面不出現連線字串。實作 UJ-1、UJ-2。

**Functional Requirements：**

#### FR-2: 從 Excel 匯入

資料治理人員可匯入符合契約的 Excel 資料字典，產生註記草稿。

**Consequences (testable)：**

- 契約以 `Requirements/Samples.xlsx` 為準：同一工作表含 H 側與 S 側欄位，以及資料備註、允許空白；表級說明可出現在工作表內。
- 匯入結果帶出實體表與欄、型別、允許空白、唯一索引勾記、已有描述與備註、個資去識別化處理文字（若有）。
- 對不上契約時拒絕匯入，既有草稿不變。
- 匯入不讀業務列，也不要求資料庫連線。

#### FR-3: 從資料庫讀結構

資料治理人員可從已登記、組態完整的具名連線讀取結構，產生或更新註記草稿。

**Consequences (testable)：**

- 帶出表、欄、型別、主鍵、外鍵。註解預設空白，留給人補。
- 恰有一筆組態完整的具名連線，且該連線是二代平台資料源，才讀取。零筆、多筆，或該筆是待轉資料庫時，不讀取，讀列次數為 0，訊息可讀且不含連線字串。
- 不使用待轉資料庫的 `GET /meta`。如何判定一筆連線是二代平台資料源，留給架構；待轉庫不得被當成讀到結構或確認通過。
- 讀取過程不讀業務列。畫面上沒有連線字串，也沒有選擇連線的動作。
- 不提供自由 SQL，也不提供對來源庫的新增、更新、刪除。

### 4.3 註記與 DBML

**Description：** 人在同一套模型上補齊四層語意，可存草稿、匯出 DBML、確認後交給設計。實作 UJ-1、UJ-2、UJ-4。

**Functional Requirements：**

#### FR-4: 四層註記

資料治理人員可編輯整包功能說明、資料表註解、欄位註解與關聯。

**Consequences (testable)：**

- 一份註記包可含多張表。
- 關聯包含庫裡沒有外鍵、由人聲明的關係。理由可以空白。
- 欄註可以空白。
- 索引可保留「有勾唯一索引」的語意，並可在說明裡寫明它不是真正的唯一鍵（對齊樣本：異動 append）。
- 個資去識別化處理以自由文字保存；這一輪不執行遮罩。
- 保存後重開，四層內容仍在。空白欄註仍是空白。

#### FR-5: 草稿、匯出與確認

資料治理人員可儲存草稿、匯出 DBML，並確認註記包。

**Consequences (testable)：**

- 未確認的草稿不進入模組設計工具。
- 確認之前，註記包內每個實體表名與實體欄名都必須存在於二代平台資料源。任一對不上，拒絕確認，草稿與上一份已確認包都維持原樣，讀列次數為 0。
- 零筆或多於一筆二代平台具名連線時無法對帳，拒絕確認，草稿維持。
- 對帳通過之後，還要檢查已保存檢視。任一已保存檢視的來源表、輸出欄或關聯端點將落到新包之外時，拒絕確認，訊息列出這些檢視的名稱；上一份已確認包與這些檢視維持原樣，不取消發布，也不改寫檢視。
- 上述檢查都通過之後，這一份成為唯一啟用的已確認包，設計階段看得到它。先前的已確認包不再進入設計目錄，但保留不刪。確認成功的訊息指出被取代的包。
- 確認後的註記包以可管理的 DBML 存在資料庫裡。匯出檔是給人核對的副本，設計階段不讀確認之前匯出的舊檔。以 `Requirements/LH_TXN_MLST.sample.dbml` 作為 `Samples.xlsx` 的驗收對照。哪一座資料庫留給架構。
- 草稿、已確認包與匯出檔都不含業務列與連線字串。
- 確認還要求整包功能說明不是空白，且至少有一張表、一個欄。說明空白、零張表或零個欄時拒絕確認，狀態維持草稿，已確認包不變。
- 確認不修改二代平台來源庫的結構，也不把註解寫回來源庫。

#### FR-6: 結構變更再讀

資料治理人員可再讀一次來源，並在保留同名註記的前提下處理差異。

**Consequences (testable)：**

- 比對鍵是實體表名加實體欄名，去掉首尾空白後原樣比較，區分大小寫。Excel 再匯入與資料庫再讀用同一條規則，結果寫進目前草稿，不改已確認包。
- 草稿裡已有的同鍵註記保留。草稿沒有、上一份已確認包有的同鍵註記，抄進草稿。改名就是刪除再新增，註記不跟著搬家。
- 另列可見的差異：新增、刪除、型別、可否空白、主鍵、外鍵、唯一索引勾記。人寫過的註解不被來源蓋掉。
- 未再次確認前，模組設計工具仍使用上一份已確認的包。
- 再次確認若會使已保存檢視落到新包之外，適用 FR-5 的拒絕規則。
- 放棄草稿時，已確認的包維持原樣。
- 再讀過程不讀業務列。

### 4.4 與模組設計工具的銜接

**Description：** 系統分析師的資料表目錄改讀已確認註記包。這份包的實體表名與實體欄名已對上二代平台資料源。檢視文件本身的形狀不變。實作 UJ-3。這一段是對檢視與報表 PRD「開放問題 8（規劃期讀取二代平台表結構的通道）」的產品答案，並取代該 PRD 的 FR-4。

**Functional Requirements：**

#### FR-7: 設計目錄來自已確認註記包

模組設計工具的資料表清單只來自已確認的註記包。

**Consequences (testable)：**

- 清單含表、欄、型別、註解與已聲明關聯。這些表與欄的實體名已在確認時對上二代平台資料源。
- 欄註為空白的欄，清單上標成「尚未註記」。這與「沒有已確認包」的空狀態不是同一句話。
- 沒有已確認註記包時，清單是空的，並說明資料來源尚未註記。
- 模組設計工具不連二代平台資料源，也不連待轉資料庫，來組這份清單。
- 系統分析師不能選註記包以外的表或欄。
- 兩張以上來源表時，每一段關聯必須等於註記包內某一條已聲明關聯的兩端表與欄，否則拒絕保存，既有檢視定義不變。分析師在這一階段不另造關聯。新的資料表關聯留到下一階段：用已確認註解，以 AI 輔助建立檢視時再建立。

#### FR-8: 檢視契約維持

檢視文件仍含名稱、目的、來源表、關聯、輸出欄與參數。發布後 MCP 目錄才出現它。樣式範本、Chat 報表生成器與報表生成紀錄的行為維持檢視與報表 PRD。兩張以上來源表時，關聯怎麼算合法，以本文件 FR-7 為準。

**Consequences (testable)：**

- 一筆檢視仍含名稱、目的、來源表、關聯、輸出欄與參數。
- 定義裡沒有業務列與連線字串。
- 發布後 MCP 目錄才出現它；未發布不在目錄裡。
- 本 PRD 不改樣式範本、Chat 報表生成器、報表生成紀錄的行為。

## 5. Out of Scope

- 改 ETL，或把註解／DBML 寫回來源資料庫。
- 取代檢視、樣式範本、報表生成紀錄。
- 個資遮罩或去識別化執行引擎。
- 在註記站提供自由 SQL、選擇連線、讀取業務列。
- 用已確認註解，以 AI 輔助建立檢視與新的資料表關聯，再為檢視補註解。這是下一份 PRD。本文件的 MCP 只提供已確認註記包。
- 把三個既有入口與資料治理收成同一套左軌工作內容。
- 預印表單、分欄帶、子報表，以及對二代平台來源庫的寫入。

## 6. Success Metrics

**Primary**

- **SM-1：** 以 `Requirements/Samples.xlsx` 匯入並匯出 DBML，表名、欄名、型別、索引與 note／Note 文字對得上 `Requirements/LH_TXN_MLST.sample.dbml`。驗證 FR-2、FR-5。
- **SM-2：** 從資料庫讀入後，人補上的整包功能說明、表註、欄註與已聲明關聯出現在匯出的 DBML，重開後仍在；確認後模組設計工具看得到。驗證 FR-3、FR-4、FR-5、FR-7。
- **SM-3：** 未確認時，模組設計工具看不到該包；確認後分析師不能選包外的表或欄。整包功能說明為空白、或沒有任何表與欄時，確認被拒絕。確認後欄註為空白的欄，清單標成「尚未註記」。驗證 FR-5、FR-7。

**Secondary**

- **SM-4：** 再讀來源時，同名註記保留，新增／刪除／型別改變可見；未再次確認前設計目錄仍是舊包。驗證 FR-6、FR-7。
- **SM-5：** 註記站任一路徑的業務列讀取次數為 0；畫面與匯出不含連線字串。驗證 FR-2、FR-3、FR-6。
- **SM-6：** 實體表名或實體欄名對不上二代平台資料源，或該連線是待轉資料庫時，確認被拒絕；草稿與已確認包不變，讀列次數為 0。驗證 FR-3、FR-5。
- **SM-7：** 再次確認會使已保存檢視的來源表、輸出欄或關聯端點落到新包之外時，確認被拒絕，訊息含這些檢視的名稱；舊包與檢視不變，已發布檢視仍在 MCP 目錄。驗證 FR-5、FR-6。

**Counter-metrics (do not optimize)**

- **SM-C1：** 不以開放自由 SQL、讓人選擇連線、讓設計端直接讀即時結構繞過確認，或以待轉資料庫的表欄讓確認通過，作為 SM-2 或 SM-3 的達成方式。
- **SM-C2：** 不以把註解寫回來源庫，或在註記站執行個資遮罩，作為完成度。
- **SM-C3：** 不以合併資料治理與模組設計為同一畫面，作為完成度。

## 7. Integration with Existing Flow

```text
Excel 字典 ──┐
             ├─→ 資料來源註記（草稿）→ 確認 → DBML／註記包
已登記連線結構┘                              │
                                            ▼
                                   模組設計工具（檢視）
                                            │
                                            ▼
                              樣式範本 → Chat 動態報表
```

- **接點 1：** 新增資料治理入口與導覽；不與檢視、樣式、報表共用同一套左軌工作內容。
- **接點 2：** 模組設計工具的資料表清單改讀資料庫裡已確認的註記包。檢視文件形狀不變。已確認註記包同時經 MCP 提供給後續設計階段引用；這個 MCP 表面不讀業務列。
- **接點 3：** 從資料庫讀結構只發生在註記站。已發布檢視的執行期讀列維持現狀。
- **接點 4：** 本文件回答檢視與報表 PRD 開放問題 8。規劃期目錄是已確認註記包。註記站向二代平台資料源讀結構，並在確認時核對實體表名與實體欄名。通道不是待轉庫的 `GET /meta`，也不是模組設計工具裡的即時連線目錄。
- **接點 5：** 原始來源以資料表呈現。第一階段只做來源註記，存成可管理的 DBML。新的資料表關聯不在這一階段由分析師手寫。
- **被本文件取代的舊句：** 檢視與報表 PRD 的 FR-4（系統分析師在規劃期直接看到二代平台資料表與欄位）、其 §4.2 描述裡的同一句、UJ-1 路徑「她看到二代平台的資料表與欄位，不是待轉資料庫」、§11 執行邊界「規劃期的表結構通道未定」、§12「系統分析師在規劃期看得到二代平台的表結構」、§13「二代平台資料源：規劃期的表結構從這裡來。讀取通道留給架構」、該 PRD 附錄「規劃期的表結構」整段，以及附錄仍未定清單中的「規劃期表結構通道」。詞彙「入口」的 v1 列舉加上資料治理。下列句子繼續有效：結構不來自待轉資料庫、不為這份結構讀業務列、連線字串不進模組設計工具、檢視文件形狀、發布、樣式範本、Chat、報表生成紀錄。十月 FR-5「或是分析師寫明並接受的關聯」在本文件的第一階段不適用，改為必須使用已聲明關聯。十月 PRD 正文不改寫；拆故事時以這份取代清單為準。

## 8. Open Questions

1. 哪一座資料庫存放可管理的 DBML，留給架構。產品約束是：草稿與已確認可區分，設計端與 MCP 都只把已確認的註記包當目錄，內容不含連線字串與業務列。
2. Excel 契約若出現第二種活頁簿版型（例如獨立的「00.資料總表」工作表），總表說明進入整包功能說明；細部欄位映射見 addendum。若版型與 `Samples.xlsx` 衝突，以樣本品為準，新版型另開需求。
3. 零筆或多於一筆具名連線時，註記站錯誤碼拼法可與工作台既有未定項一併由架構收束；行為已定於 FR-3。確認被拒時的錯誤碼拼法同樣留給架構，訊息必須列出檢視名稱，且不含連線字串。

## 10. Cross-Cutting NFRs

- 操作者看得到的介面文字、空狀態與註記站自己產生的錯誤，使用繁體中文。
- 錯誤至少含穩定代碼與給人讀的訊息。訊息不含連線字串、密碼與堆疊中的秘密。
- 註記站任一路徑不讀取業務列。確認對帳只核對表名與欄名是否存在，不讀列。
- 匯入失敗、再讀失敗或確認失敗時，已確認的包與已保存的檢視定義不變。
- 不在二代平台來源庫執行結構變更，也不把註解寫回來源庫。

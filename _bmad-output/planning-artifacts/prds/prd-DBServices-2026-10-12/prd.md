# PRD: DBServices 檢視與報表

本 PRD 給產品、體驗、架構與後續故事拆解使用。它定義三個獨立入口：模組設計工具、AI 報表設計工具、Chat 報表生成器。資料怎麼被安全讀取，以 [資料平面 PRD](../../../../docs/planning/agent-data-plane/prd.md) 為準；該文件仍稱「模組視圖」，本文件的名詞是**檢視**，兩者指同一筆已發布、可被 MCP 呼叫的定義，不是第二個產品物件。技術邊界見 [addendum.md](addendum.md)。詞彙以第 3 節為準。推論標成 `[ASSUMPTION]`，並彙總在第 9 節。

2026-10-18 的體驗骨架與設計骨架、2026-10-20 的架構脊椎、`spec-report-workbench` 與報表工作台史詩，都已改寫成這份 PRD 的三個入口。契約以本 PRD 的 FR-1 至 FR-16 為產品範圍；架構 AD 與 SPEC 的 CAP-9 至 CAP-13 收束實作邊界。2026-10-13 的單一工作台不再是契約。

## 0. 2026-10-18 已改寫

2026-10-18 確認三件事，並覆寫 2026-10-12 與 2026-10-15 裡與此衝突的工作台決定。

1. 三個新程式是三個入口，不共用同一套左軌。
2. 終端使用者可把樣式範本寫回與報表設計師共用的報表樣式範本資料庫。私有或共享只標這筆樣式範本與這筆報表生成紀錄。
3. 本輪範圍包含模組設計工具。模組就是檢視。MCP 包裹已發布的檢視。報表兩站消費這筆檢視。
4. 語句就緒後直接經 MCP 產生動態報表，沒有另一張呼叫清單確認頁。
5. 報表生成紀錄保存該次動態報表的列。再開或共享時看到的是那一份，不重新讀取。

ETL 維持既有，不在本 PRD 交付。人在三個入口都不選擇 MCP、Web API 或具名連線。

## 1. Vision

二代平台的資料已由既有 ETL 寫入待轉資料庫。缺的不是再做一個把預覽、畫布與交談疊在一起的工作台，而是讓三種人各自做完一件事，把產出交到下一站。

系統分析師在模組設計工具把資料表結構定義成一筆檢視，存進模組資料庫。報表設計師在 AI 報表設計工具引用這筆檢視的欄位與參數，把版面存成樣式範本。終端使用者在 Chat 報表生成器裡說話；關鍵字不夠就繼續談；就緒之後，MCP 以那筆檢視讀出資料，產生動態報表。他可以把這次報表留下，也可以把版面存回同一座樣式庫。

這一輪要證明的是：檢視回答業務問題，樣式範本只負責版面，交談只負責把檢視填進版面。連線字串留在伺服器。三個入口都不成為第二套查詢引擎。

## 2. Target User

### 2.1 Jobs To Be Done

- 系統分析師要把二代平台的表結構定義成一筆有名稱、目的、輸出欄與參數的檢視，發布後讓 MCP 叫得到。
- 報表設計師要引用一筆已發布檢視，排出可重複使用的樣式範本，並決定這筆範本私有或共享。
- 終端使用者要用語句套到看得到的樣式範本，得到當下的動態報表，把這次結果留下或與人共享，並可把版面存回樣式庫。
- 管理員要決定誰可以打開哪一個入口。

### 2.2 Non-Users (v1)

- 要改 ETL 的人。DBA 仍是資料彙整階段的使用者，使用既有 ETL，不進入三個新入口。
- 要在畫面上貼連線字串、選擇資料庫引擎，或選擇「走 MCP 還是走 Web API」的人。
- 要輸入自由 SQL、區間條件，或在報表兩站自行組合尚未定義的檢視的人。
- 要在一個畫面裡同時設計檢視、排版與產生報表的人。
- 要把報表套印到預印表單、分欄帶或子報表的人。
- 要這三個入口直接寫入二代平台來源庫的人。
- 未登入的人。

### 2.3 Key User Journeys

**UJ-1. 林可把銷貨定義成一筆檢視。**

- **Persona + context：** 林可是系統分析師。待轉資料庫裡已有銷貨相關的表。她要讓後面的人不用自己挑表。
- **Entry state：** 她已登入，且持有系統分析師入口。她沒有打開另外兩個入口。
- **Path：** 她看到二代平台的資料表與欄位，不是待轉資料庫。她建立一筆檢視，命名為銷貨月檢視，寫下目的，選來源表與彼此的關聯，指定輸出欄與參數 `yearMonth`，存入模組資料庫並發布。發布就是她確認這筆定義。
- **Climax：** 發布後，MCP 目錄裡出現銷貨月檢視。未發布前，目錄裡沒有它。
- **Resolution：** 模組資料庫留下這筆定義。定義裡沒有業務列，也沒有連線字串。二代平台來源庫的結構沒有被改動。
- **Edge case：** 她選的來源表彼此連不起來。工具拒絕保存，目錄不變。

**UJ-2. 周寧引用這筆檢視，做成月報樣式。**

- **Persona + context：** 周寧是報表設計師。她要一份每月可重用的銷貨月報版面。
- **Entry state：** 她已登入，且持有報表設計師入口。銷貨月檢視已發布。
- **Path：** 她引用銷貨月檢視。工具依輸出欄與參數提出版面建議。她留下標題、一段文字、綁 `yearMonth` 的參數，以及一個列出該檢視輸出欄的資料表區塊，由上到下排好。她命名為銷貨月報，共享範圍選共享，存入報表樣式範本資料庫。
- **Climax：** 她再次打開這筆樣式範本，看到的是版面與繫結。畫面上沒有業務列。
- **Resolution：** 樣式範本只含版面、所綁的檢視與參數定義。沒有參數值，沒有連線字串。
- **Edge case：** 建議裡出現該檢視沒有的欄。她不能接受。忽略建議不會改動已排好的版面。

**UJ-3. 陳安用語句得到十月的動態報表。**

- **Persona + context：** 陳安是終端使用者。他要看 2026-10 的銷貨月報。他沒有系統分析師入口，也沒有報表設計師入口。
- **Entry state：** 他已登入，且持有終端使用者入口。銷貨月報是共享樣式範本，參數是 `yearMonth`。
- **Path：** 他在 Chat 報表生成器說「銷貨月報，年月 2026-10」。工具抓到樣式範本與參數值。意圖就緒後，MCP 呼叫銷貨月檢視，產生動態報表。他把這次結果存成私有的報表生成紀錄。
- **Climax：** 動態報表上的列來自這次 MCP 呼叫。就緒之前，沒有讀取業務列。
- **Resolution：** 報表生成紀錄屬於陳安，共享範圍是私有。他之後再開這筆紀錄，看到的是當時那份動態報表，不會重新讀取。
- **Edge case：** 句子對不到樣式範本，或對不到 `yearMonth`。工具繼續交談，指出缺什麼。這段交談的 MCP 讀列次數是 0。

**UJ-4. 私有的留在擁有者，共享的才能被別人套用。**

- **Persona + context：** 周寧另有一筆私有的薪資樣式範本。陳安也有一筆私有的報表生成紀錄。
- **Entry state：** 兩人都已登入。陳安持有終端使用者入口。周寧持有報表設計師入口。
- **Path：** 陳安在交談裡找薪資。周寧打開陳安的報表生成紀錄。接著周寧把薪資樣式範本改成共享。陳安再次交談。
- **Climax：** 改成共享之前，陳安的候選裡沒有薪資樣式範本。周寧看不到陳安的私有報表生成紀錄。改成共享之後，陳安可以套用薪資樣式範本，但不能修改它。
- **Resolution：** 陳安若把一次交談的版面存回樣式庫並標成共享，周寧在 AI 報表設計工具裡看得到這筆樣式範本，也不能修改。
- **Edge case：** 陳安直接指定薪資樣式範本的識別去產生報表時，在它仍是私有的情況下被拒絕，MCP 讀列次數是 0。

## 3. Glossary

- **待轉資料庫** — ETL 寫入的資料庫。三個入口都不讓人選擇它的連線。
- **檢視** — 一筆模組。具名，有目的、來源表、關聯、輸出欄與參數。定義存在模組資料庫。已發布之後，MCP 把它包成一個可呼叫工具。不是畫面區塊，也不是權限名稱。
- **模組資料庫** — 檢視的定義，以及這些檢視供 MCP 讀取的資料。不是二代平台來源庫。
- **模組設計工具** — 系統分析師的入口。在此建立、修改、發布檢視。
- **樣式範本** — 名稱、所綁的恰好一筆檢視、由上到下的區塊、共享範圍、擁有者。只含版面與繫結，不含業務列、參數值與連線字串。
- **報表樣式範本資料庫** — 全部樣式範本的存放處。報表設計師與終端使用者共用這一座庫。
- **AI 報表設計工具** — 報表設計師的入口。在此引用已發布檢視並保存樣式範本。
- **Chat 報表生成器** — 終端使用者的入口。在此交談、套用或載入樣式範本、產生動態報表、保存報表生成紀錄，以及把版面存回樣式庫。
- **動態報表** — 一次就緒交談產生的報表。版面來自當時的樣式範本，列來自該次 MCP 對所綁檢視的呼叫。
- **報表生成紀錄** — 一次動態報表的保存：擁有者、共享範圍、當時的動態報表。不含連線字串。再開時不重新讀取。
- **共享範圍** — `私有` 或 `共享`。標在樣式範本與報表生成紀錄上。私有只有擁有者可讀。共享對持有對應入口的其他人可讀。只有擁有者可改內容或改共享範圍。
- **入口** — 一個人被允許打開的站。v1 有系統分析師、報表設計師、終端使用者。各站只做該站的事。
- **操作者** — 可登入的人。每個人有穩定識別。
- **管理員** — 可建立操作者並指派入口的操作者。
- **區塊** — 樣式範本裡的一個由上到下的項目。v1 只有標題、文字、參數、資料表。
- **參數** — 檢視已宣告的一個等值篩選。樣式範本只保存欄位與標籤。值由交談在執行時提供，是純量。
- **關鍵字** — 從語句抽出的樣式範本候選與參數值。
- **就緒** — 恰好一筆此人可讀的樣式範本，且該範本每個參數都有一個純量值。
- **MCP** — 已發布檢視的呼叫包裹。Chat 報表生成器經它讀取檢視。它不是人在畫面上選擇的通道。
- **web API** — 待轉資料庫的結構讀取與轉置通道。它不是人在畫面上選擇的通道。
- **轉置** — 依已發布檢視的定義，把待轉資料庫的資料經 web API 準備成模組資料庫裡可供 MCP 讀取的檢視資料。

## 4. Features

### 4.1 身分與入口

**Description：** 三個入口都只讓已登入的操作者使用。帳號與入口指派在產品自己的存放，不在業務庫。`[ASSUMPTION]` 沒有公開自助註冊；管理員建立其他操作者；第一個管理員由安裝設定建立。一個人可以同時持有多個入口。打開某個入口時，只看到該站。實作 UJ-1 至 UJ-4 的進入邊界。

**Functional Requirements：**

#### FR-1: 未登入不可進入

未登入的人不能使用模組設計工具、AI 報表設計工具或 Chat 報表生成器。

**Consequences (testable)：**

- 未帶有效登入狀態的請求不回傳檢視、樣式範本、報表生成紀錄或業務列。
- 三個入口都不以 `anonymous` 呼叫 MCP。

#### FR-2: 管理員指派入口

管理員可建立操作者，並指派或移除系統分析師、報表設計師、終端使用者入口。

**Consequences (testable)：**

- 非管理員不能建立操作者，也不能變更入口指派。
- 同一操作者可同時持有一個以上的入口。
- 持有哪個入口，就只出現哪個站。沒有把三站收成同一套導覽。

**Out of Scope：**

- 企業目錄、SSO、公開自助註冊。

#### FR-3: 沒有入口就不能打開該站

操作者只能打開自己被指派的入口。

**Consequences (testable)：**

- 只有終端使用者入口的人，打不開模組設計工具與 AI 報表設計工具。
- 直接指定另一站的位址時拒絕，不建立檢視、不修改樣式範本、不產生動態報表。

### 4.2 模組設計工具

**Description：** 系統分析師在規劃期讀取二代平台的表結構，定義檢視，發布後 MCP 才看得到。實作 UJ-1。設計這站不要求先讀業務列。這一輪的執行期由 MCP 依檢視定義即時讀取，不先落地成另一份資料表。三個入口都沒有選擇 Web API 或選擇連線的動作。

**Functional Requirements：**

#### FR-4: 讀取資料表結構

系統分析師在規劃期可看到二代平台資料源的資料表與欄位。

**Consequences (testable)：**

- 這份結構不來自待轉資料庫，也不要求先完成轉置。
- 畫面上沒有連線字串。
- 這一站不提供自由 SQL，也不提供對二代平台來源庫的新增、更新、刪除。
- 沒有資料表時，清單是空的。

#### FR-5: 定義檢視

系統分析師可建立、修改與刪除尚未被樣式範本引用的檢視。

**Consequences (testable)：**

- 一筆檢視含名稱、目的、來源表、關聯、輸出欄與參數。參數是等值篩選的欄位與標籤，不含值。
- 只有一張來源表時，不需要關聯。兩張以上時，每一段關聯要麼是目錄裡的外鍵，要麼是分析師寫明並接受的關聯。沒有這種路徑時拒絕保存，不產生笛卡兒積，既有定義不變。
- 保存寫入模組資料庫。定義裡沒有業務列與連線字串。
- 名稱在模組資料庫內不重複。
- 尚未被樣式範本引用的檢視可以修改、取消發布與刪除。
- 仍被樣式範本引用的檢視不能刪除、不能取消發布，也不能改名稱、輸出欄或參數。目的文字可以改。

#### FR-6: 發布後 MCP 才包裹它

系統分析師發布檢視之後，MCP 的目錄才出現它。

**Consequences (testable)：**

- 發布表示分析師確認這筆檢視的目的、來源表、關聯、輸出欄與參數。資料平面所稱的解說就是這些欄位，不另寫第二份文件。
- MCP 目錄的名稱集合等於已發布檢視的名稱集合。目錄用檢視的穩定識別對上樣式範本，不靠事後改名。
- 未發布的檢視不在目錄裡。目錄是空的時候，不改列資料表工具。
- 發布與呼叫都不修改二代平台來源庫的結構。

#### FR-7: 檢視的列來自一次已發布呼叫

這一輪，已發布檢視的列由 MCP 依檢視定義即時讀取。先落地成另一份資料表不在這一輪；要改成落地，先改架構 AD-3。

**Consequences (testable)：**

- Chat 報表生成器讀到的列來自該筆檢視的一次呼叫，不來自人選定的資料表，也不用 Web API 的列組成動態報表。
- 呼叫失敗時，不產生動態報表，並顯示可讀錯誤。
- 連線字串不進入三個入口。

### 4.3 AI 報表設計工具

**Description：** 報表設計師引用一筆已發布檢視，排出樣式範本，存入與終端使用者共用的報表樣式範本資料庫。實作 UJ-2 與 UJ-4。建議只使用檢視的輸出欄與參數，不讀業務列。

**Functional Requirements：**

#### FR-8: 樣式範本綁一筆檢視

報表設計師可建立由標題、文字、參數、資料表四種區塊組成的樣式範本。一筆樣式範本綁定恰好一筆已發布檢視。

**Consequences (testable)：**

- 標題與文字保存操作者輸入的字串。
- 參數區塊綁該檢視已宣告的一個參數，並有標籤。樣式範本不保存參數值。
- 資料表區塊的欄來自該檢視的輸出欄。
- 區塊順序是由上到下。重新開啟時，順序與繫結保持為上次保存的結果。
- 不提供這四種以外的區塊，也不提供圖表。筆數若要出現，必須是該檢視的一個輸出欄。

#### FR-9: 依檢視提出版面建議

報表設計師選定一筆已發布檢視後，工具提出區塊建議。設計師可接受、修改或忽略。

**Consequences (testable)：**

- 建議不含業務列與參數值。
- 建議中的欄與參數都屬於該檢視。至少包含一個資料表區塊，其欄名全集等於該檢視的輸出欄。
- 接受會把區塊加入順序的末尾。忽略不改變既有版面。
- 含有未知欄名的建議不能被接受。建議失敗時，既有版面不變。

#### FR-10: 存入共用的樣式庫並標共享範圍

報表設計師保存樣式範本時，寫入報表樣式範本資料庫，並指定私有或共享。

**Consequences (testable)：**

- 保存結果沒有業務列、連線字串、具名連線與參數值。
- 關閉後再打開，不需要連線仍可看到版面與繫結。
- 擁有者可修改、刪除與變更共享範圍。其他人不能。
- 共享的樣式範本，持有報表設計師或終端使用者入口的其他人可讀。私有的只有擁有者可讀。

### 4.4 Chat 報表生成器

**Description：** 終端使用者用語句套用看得到的樣式範本。就緒後經 MCP 呼叫所綁檢視，產生動態報表。實作 UJ-3 與 UJ-4。這一輪的比對只在核心做關鍵字，不啟動側車。側車專案留在倉儲。關鍵字規則達到這裡的行為即算完成。

**Functional Requirements：**

#### FR-11: 語句抓成關鍵字

終端使用者提交語句後，工具給出樣式範本候選與參數值。

**Consequences (testable)：**

- 候選只來自此操作者可讀的樣式範本：自己擁有的，以及共享的。
- 參數欄位必須是該樣式範本所綁檢視已宣告的參數。值是純量。
- 結果不含連線字串與業務列。
- 一句話裡的時間範圍，只有在能對到某個參數的一個等值時才成為值。不能對到時，該參數保持缺少，工具也不另造區間查詢。

#### FR-12: 未就緒時繼續交談，不讀列

意圖不是就緒時，工具不呼叫 MCP 讀取業務列。

**Consequences (testable)：**

- 多筆樣式範本時，列出候選，讓操作者收到剩一筆。
- 缺少參數值時，指出缺的欄位或標籤。
- 對不到任何樣式範本時，說明對不到，候選為空。
- 上述情況在就緒之前，該段交談的 MCP 讀列次數是 0。
- 改選候選本身不讀取業務列。

#### FR-13: 就緒後經 MCP 產生動態報表

意圖就緒後，工具呼叫該樣式範本所綁的那一筆已發布檢視，並產生動態報表。

**Consequences (testable)：**

- 就緒後直接呼叫，不另顯示一張呼叫清單確認頁。
- 一次產生恰好呼叫該檢視一次。參數是純量，且屬於該檢視已宣告的參數。人不選擇具名連線。
- 伺服器恰有一筆具名連線時，呼叫綁定該連線。多於一筆時，不產生動態報表，顯示可讀錯誤，該次 MCP 讀列次數是 0。
- 不呼叫資料表工具，也不另發計數。
- 實際呼叫的檢視名稱與參數，和該次就緒的樣式範本一致。
- 呼叫失敗時，不產生動態報表，並顯示可讀錯誤。不用舊列湊成一份成功報表。

#### FR-14: 保存報表生成紀錄

終端使用者可把這次動態報表存成報表生成紀錄，並指定私有或共享。

**Consequences (testable)：**

- 紀錄含擁有者、共享範圍與該次動態報表。不含連線字串。
- 私有紀錄只有擁有者可讀。共享紀錄對持有終端使用者入口的其他人可讀。
- 再開時顯示保存的那份動態報表，不重新呼叫 MCP。
- 其他人不能修改或刪除這筆紀錄。

#### FR-15: 把版面存回樣式庫

終端使用者可把這次使用的版面存回報表樣式範本資料庫，並指定私有或共享。

**Consequences (testable)：**

- 寫入的是樣式範本：版面、所綁檢視與參數定義。不含業務列、參數值與連線字串。
- 新樣式範本的擁有者是這位終端使用者。之後的讀取與修改規則與 FR-10 相同。
- 存回樣式庫不重新呼叫 MCP。

### 4.5 匯出與列印

**Description：** 目前這份動態報表，或已開啟的報表生成紀錄，可以匯出與列印。實作 UJ-3 的後段。

**Functional Requirements：**

#### FR-16: 匯出與列印使用這份動態報表

操作者可對目前開啟的動態報表匯出 PDF、列印，並把其中的資料表區塊匯出 CSV。

**Consequences (testable)：**

- PDF、列印與 CSV 中的數字和文字等於這份動態報表，包含空結果。
- 匯出與列印不發出新的 MCP 呼叫。
- 列印依區塊由上到下換頁，不提供預印表單對位。

**Feature-specific NFRs：**

- 同一份動態報表連續匯出兩次，兩份 PDF 的業務數字相同。

## 5. Non-Goals (Explicit)

- 不把三個入口收成一個報表工作台。
- 不交付 ETL。資料彙整維持既有工具。
- 不成為第二套查詢引擎，也不自製跨廠商 SQL planner。
- 不接受自由 SQL、區間條件，或在報表兩站臨時組合檢視。
- 不在三個入口、樣式範本、錯誤或紀錄中放置連線字串。
- 不讓人選擇 MCP、Web API 或具名連線。
- 不把業務列寫進檢視定義或樣式範本。
- 不做像素級報表引擎：沒有預印表單、分欄帶、子報表或絕對座標排版。
- 不做圖表、結果敘事、跨來源簡報與寫入提案。
- 不把 GraphQL 當作這三個入口的資料通道。
- 不綁定單一語言模型廠商。關鍵字規則只要滿足第 4.4 節即可完成驗收。
- 不在二代平台來源庫建立或修改結構。
- 不做企業目錄、SSO 與公開自助註冊。

## 6. MVP Scope

### 6.1 In Scope

- FR-1 至 FR-16。
- UJ-1 至 UJ-4。
- 三個入口：模組設計工具、AI 報表設計工具、Chat 報表生成器。
- 檢視的定義與發布，以及 MCP 只包裹已發布檢視。這一輪讀列是一次即時呼叫，不先落地成另一份資料表。
- 報表樣式範本資料庫與報表生成紀錄，兩者都有私有與共享。

### 6.2 Out of Scope for MVP

- **ETL 與 DBA 的資料彙整。** 理由：架構圖標為既有。
- **人在畫面上換資料庫引擎。** 理由：換庫屬於 ETL 與伺服器組態，不屬於這三個入口。
- **區間篩選、圖表、敘事與像素級套印。** 理由：不阻擋四條旅程。
- **GraphQL。** 理由：這三站的讀取是 web API 轉置與 MCP 檢視。
- **企業目錄與 SSO。** 理由：v1 的邊界是入口指派。

## 7. Success Metrics

**Primary**

- **SM-1：** 林可發布一筆檢視前後，MCP 目錄的名稱集合分別等於發布前與發布後的已發布檢視。陳安就緒後的那次呼叫使用這筆檢視並得到列。驗證 FR-6、FR-13。
- **SM-2：** 抽樣一筆樣式範本與一筆報表生成紀錄。樣式範本找不到業務列與連線字串。報表生成紀錄找不到連線字串。驗證 FR-10、FR-14、FR-15。
- **SM-3：** 對 UJ-3 一句尚未就緒的語句，MCP 讀列次數是 0。就緒後實際呼叫的檢視與參數等於該筆樣式範本。驗證 FR-12、FR-13。

**Secondary**

- **SM-4：** 私有樣式範本與私有報表生成紀錄對其他人不可讀。共享樣式範本可被另一個持有對應入口的人套用，但不能被修改。驗證 FR-3、FR-10、FR-14。
- **SM-5：** 匯出的 PDF 與 CSV 等於該次開啟的動態報表，而且匯出過程沒有新的 MCP 呼叫。驗證 FR-16。

**Counter-metrics (do not optimize)**

- **SM-C1：** 不以開放自由 SQL、把資料表工具放進 MCP 目錄，或讓人選擇連線，作為 SM-1 或 SM-3 的達成方式。
- **SM-C2：** 不以把三個入口收成同一套導覽、圖表數量或預印表單對位，作為完成度。
- **SM-C3：** 不以綁定某個模型廠商，作為 FR-11 的完成條件。關鍵字規則達到 SM-3 即算該行為完成。

## 8. Open Questions

1. 第一個管理員的格式已由架構 AD-6 收束：零個操作者時讀 `Workbench:InitialAdmin:DisplayName` 與 `Password`，寫入恰好一個管理員。沒有公開自助註冊。
2. 存放已由架構 AD-5 與 AD-15 收束：工作台 SQLite 放操作者、入口指派、樣式範本與報表生成紀錄；檢視定義只在 `DbServices.Mcp`。產品約束仍見 FR-5、FR-10、FR-14。
3. 這一輪只走關鍵字，比對在 `Workbench.Core`，不啟動側車。側車專案留在倉儲。見架構 AD-8、AD-11。
4. 檢視定義已由架構 AD-15 收束為目錄文件，不在來源庫執行 `CREATE VIEW`。MCP 目錄只出現已發布檢視。
5. MCP 稽核的保留天數仍未定。本 PRD 不另定保留政策，三個入口也不實作保留。
6. PDF 已定為 QuestPDF、預設 A4，換頁以區塊為界。CSV 的具體寫法仍未定。匯出時不得再查資料。
7. 體驗骨架、設計骨架、架構脊椎、`spec-report-workbench` 與報表工作台史詩已在 2026-10-20 對齊本 PRD。2026-10-13 的單一工作台不再是契約。
8. 規劃期讀取二代平台表結構的通道仍未定。定案前不得用待轉資料庫的 `GET /meta` 充當，也不得為了這份結構讀業務列，也不把連線字串帶進模組設計工具。
9. 零筆或多於一筆具名連線時，工作台自己的錯誤碼拼法仍未指定。行為已定：不呼叫，讀列次數為 0，訊息可讀且不含連線字串。

## 9. Assumptions Index

- 第 4.1 節 — 沒有公開自助註冊；管理員建立操作者；第一個管理員來自安裝設定；一人可持有多個入口。
- 第 4.2 節 — 三個入口都不讓人選擇連線或 Web API。這一輪讀列是一次即時檢視呼叫，不先落地。恰有一筆具名連線才呼叫，這條已寫進 FR-13。
- FR-10、FR-14 — 共享對持有對應入口的其他人可讀；只有擁有者可改。
- 第 4.4 節 — 這一輪只走關鍵字。側車不啟動。
- 第 8 節 — PDF 預設 A4，不對位預印表單。
- 第 0 節 — 資料平面文件裡的「模組視圖」就是本文件的已發布檢視。

## 10. Cross-Cutting NFRs

- 操作者看得到的介面文字、空狀態與這三個入口自己產生的錯誤，使用繁體中文。MCP 已回傳的訊息維持宿主原文。
- 錯誤至少含穩定代碼與給人讀的訊息。訊息不含連線字串、密碼與堆疊中的秘密。
- 密碼不以明文存放。
- 關鍵字或建議步驟失敗時，不讀取業務列，已保存的檢視、樣式範本與報表生成紀錄不變。
- 單一檢視轉置失敗時，其他檢視仍可被呼叫。

## 11. Constraints and Guardrails

- **資料邊界：** 連線字串只存在既有伺服器組態。三個入口的請求、存放、匯出檔與畫面都不新增這個欄位。
- **執行邊界：** Chat 的讀列只經 MCP，且只呼叫已發布檢視一次。這一輪不用 Web API 的列組成動態報表。規劃期的表結構通道未定，不得用待轉資料庫充當。入口不改寫查詢。
- **就緒邊界：** 結構讀取可以在交談完成前發生。業務列只在意圖就緒、轉置成功、且 MCP 呼叫成功之後出現在動態報表。
- **來源邊界：** 不修改二代平台來源庫的結構，也不從這三個入口寫入該庫。
- **模型邊界：** 關鍵字步驟不組 SQL、不開連線、不讀取連線字串。執行前檢查樣式範本屬於此人此刻可讀的集合。

## 12. Data Governance

v1 的授權單位是操作者、入口與共享範圍。系統分析師在規劃期看得到二代平台的表結構。業務列出現在轉置後的檢視資料、就緒後的動態報表，以及報表生成紀錄裡的那份動態報表。

檢視定義與樣式範本不保存業務列。報表生成紀錄會保存該次動態報表的列，因為共享的是那一份報表，再開時不重新讀取。`[ASSUMPTION]` 管理員不能透過產品介面讀取他人的私有報表生成紀錄；維運備份若接觸存放檔，不因此開放產品內的跨人讀取。

三個入口的存放都在營運者自己的環境，不寫進二代平台來源庫，也不預設外送到第三方分析平台。

## 13. Integration and Dependencies

- **ETL：** 既有。負責把二代平台資料寫入待轉資料庫。本 PRD 不改它。
- **二代平台資料源：** 規劃期的表結構從這裡來。讀取通道留給架構。這一讀不經過待轉資料庫。
- **web API：** 這一輪不用它產生動態報表，也不用它充當規劃期的表結構。不是人選擇的通道。先落地的轉置另案，要改先改架構 AD-3。
- **MCP 宿主：** Chat 報表生成器依賴已發布檢視目錄，並以操作者識別填入呼叫者。目錄裡沒有資料表工具。恰有一筆具名連線時才綁定該連線。
- **資料平面 PRD：** 公開目錄、唯讀與稽核仍以該 PRD 為準。該 PRD 的「模組視圖」在本文件稱為檢視。解說就是 FR-5 的欄位，發布就是確認。人仍不在入口選擇連線。
- **解析：** 這一輪只走關鍵字規則，比對在核心，不啟動側車。比對失敗時不讀列，已保存的檢視、樣式範本與報表生成紀錄不變。

# PRD: DBServices 報表工作台

本 PRD 給產品、體驗、架構與後續故事拆解使用。它定義業務人員日常使用的報表工作台。資料怎麼被安全讀取，仍以 [資料平面 PRD](../../../../docs/planning/agent-data-plane/prd.md) 的 P0 為準；本文件不修改那些 FR。技術邊界、儲存形狀與解析契約見 [addendum.md](addendum.md)。詞彙以第 3 節為準。推論標成 `[ASSUMPTION]`，並彙總在第 9 節。

工作台要三片驗收都通過才算完成。片 1 是活資料預覽，片 2 是編輯器與範本庫，片 3 是交談套版、常用清單、匯出與列印。前一片是下一片的閘門，不是可單獨交付的產品。

## 1. Vision

DBServices 已經能用同一套 Session 讀取 SQLite、SQL Server、MySQL、Oracle 與 PostgreSQL，並把唯讀能力露出成 MCP 工具。缺的是業務人員自己的表面：把報表做成可重複使用的範本，用語句叫出來，確認後才填上當下的資料，再匯出或列印。

報表工作台就是這個表面。設計者在畫布上用元件排好版面與欄位繫結，放進可授權的範本群組。業務人員說一句人話，系統從他看得到的範本裡提出建議與等值參數；他確認之後才查資料。範本與常用項目都不保存資料列。同一份範本換一個具名連線，就能換資料庫引擎。

這個增量要證明的是：AI 與畫布增加的是意圖、版面與繫結，不是第二套查詢引擎。連線字串留在伺服器。查詢仍是既有的等值篩選。人確認之前，工作台不去取業務列。

## 2. Target User

### 2.1 Jobs To Be Done

- 整合方要在畫面上確認：換了 `ServerType`，同一張表仍用同一組工具讀得到，而且畫面上沒有連線字串。
- 設計者要把欄位排成一份可重複使用的報表，依欄位得到繫結建議，並把範本放進群組交給特定的人。
- 業務人員要用語句選到對的範本與等值參數，確認後看到當下的資料，把這次叫法存成自己的常用項目，之後再叫出來、匯出或列印。
- 管理員要決定誰可以改哪一組範本、誰只能看。

### 2.2 Non-Users (v1)

- 要在畫面上貼連線字串的人。
- 要輸入自由 SQL、區間條件、跨表 join，或要工作台自行彙總出工具沒有回傳的數字的人。
- 要把報表套印到預印表單、分欄帶或子報表的人。
- 要 Agent 或工作台直接寫入業務庫的人。
- 未登入的呼叫者。資料平面 P0 允許缺識別仍呼叫 MCP；工作台不沿用這條。

### 2.3 Key User Journeys

**UJ-1. 林可換一座庫，確認工具沒有變。**

- **Persona + context：** 林可維護公司庫存的 DBServices 服務。正式庫在 SQL Server，測試庫在 PostgreSQL。她要讓同事看見兩座庫讀的是同一種工具。
- **Entry state：** 她已是登入的操作者。MCP 組態有具名連線 `inventory`（`SqlServer`）與 `inventory_pg`（`PostgreSQL`）。兩座庫都有表 `products`。
- **Path：** 她開啟活資料預覽，看到這兩個名稱與對應的 `ServerType`。她對 `inventory` 選 `products`，看欄位，設一組等值篩選，執行查詢，再看計數。然後只把連線改成 `inventory_pg`，用同一張表與同一組篩選再執行一次。
- **Climax：** 兩次都得到列與計數。畫面上的工具名稱仍是 `query` 與 `count`，參數鍵仍是連線名稱、表名與等值篩選。畫面上沒有連線字串。
- **Resolution：** 取數軌跡與 MCP 稽核對得上：呼叫者是她的操作者識別、連線名稱、工具、條件、列數或計數值。稽核裡沒有列內容，也沒有連線字串。
- **Edge case：** 她把連線改到一個 `ServerType` 無法建立的名稱。預覽顯示可讀錯誤，工作台與 MCP 宿主都仍在。先前那次成功查詢的列不會被這次錯誤覆蓋成未處理例外。

**UJ-2. 周寧做出一份不含資料列的月報範本。**

- **Persona + context：** 周寧負責銷貨報表的版面。業務庫有表 `sales`，其中一欄 `yearMonth` 以 `2026-10` 這種值表示月份。
- **Entry state：** 她對目標範本群組具有設計角色。她已能在活資料預覽看到 `sales` 的欄位。
- **Path：** 她開啟編輯器，選定 `sales`。工作台依 `fields` 的結果建議一個資料表元件，欄位都來自該結果。她接受建議，再拖曳調整順序，加上標題、一段文字、一個綁 `yearMonth` 的參數，以及一個計數元件。她把範本命名並存進群組。
- **Climax：** 她重新打開這份範本，畫布上是她留下的元件與繫結。畫面上沒有任何業務列。
- **Resolution：** 範本庫裡這份範本只含版面、繫結與參數定義。她可以把它移到另一個她具有設計角色的群組。
- **Edge case：** 建議列出一個 `fields` 沒有回傳的欄位時，她無法接受該建議。忽略建議不會改動她已經排好的畫布。

**UJ-3. 陳安用語句叫出月報，確認後才列印。**

- **Persona + context：** 陳安每月要看銷貨月報。他知道要說「庫存庫的銷貨月報，年月 2026-10」。他沒有設計角色。
- **Entry state：** 他對該範本所在群組具有檢視角色。範本已有參數 `yearMonth`。MCP 上至少有一個他可以選的具名連線。
- **Path：** 他在交談畫面輸入那句話。工作台列出對上的連線、範本與參數值。若不止一個候選，他選定一個。他按下確認。預覽出現後，他把這次叫法存成常用項目，再匯出 PDF 並列印。隔天他從常用清單再開一次。
- **Climax：** 確認之前，預覽區沒有業務列。確認之後，表與計數來自該次唯讀呼叫。PDF、列印與畫面上的數字一致。
- **Resolution：** 常用項目屬於陳安。再次開啟時工作台用範本目前的版面，套上常用項目裡的連線與參數，重新查詢，不讀舊的列。
- **Edge case：** 句子對不到連線、範本或 `yearMonth` 的值時，工作台停在候選或請他補齊，填數呼叫次數是 0。他若失去該群組的檢視角色，這份常用項目無法再執行。

**UJ-4. 陳安看不到周寧的另一組範本。**

- **Persona + context：** 周寧還維護一份薪資範本，放在陳安沒有角色的群組。兩人各自有常用清單。
- **Entry state：** 兩人都已登入。薪資群組沒有陳安的設計角色或檢視角色。
- **Path：** 陳安打開範本庫與交談建議。周寧打開自己的常用清單。
- **Climax：** 陳安的清單與建議裡沒有薪資範本。周寧的常用項目沒有出現在陳安的清單。
- **Resolution：** 直接指定薪資範本識別來預覽時，工作台拒絕，並且不執行填數呼叫。
- **Edge case：** 周寧想把銷貨範本移入薪資群組。她對薪資群組沒有設計角色，移動被拒絕，範本仍留在原群組。

## 3. Glossary

- **報表工作台** — 本 PRD 的產品。已登入操作者在此預覽資料、設計範本、用語句套版、管理常用項目、匯出與列印。
- **操作者** — 工作台儲存裡的一個可登入的人。每個人有穩定識別。
- **管理員** — 可建立操作者、建立範本群組、指派角色的操作者。
- **設計角色** — 某個範本群組上的角色。具有此角色的操作者可在該群組建立、修改、刪除與移出範本。設計角色包含檢視角色。
- **檢視角色** — 某個範本群組上的角色。具有此角色的操作者可列出、套用與預覽該群組的範本，不能修改範本。
- **具名連線** — 伺服器組態中的一筆連線，含名稱與 `ServerType`。工作台只使用名稱。定義與資料平面 PRD 相同。
- **ServerType** — `Sqlite`、`SqlServer`、`MySQL`、`Oracle`、`PostgreSQL` 之一。
- **取數表面** — 工作台這次讀資料所走的服務。v1 只有 `MCP` 與 `Web API`。
- **等值篩選** — 欄位名稱對到一個純量（字串、數字、布林或 null）。不是 SQL 片段，也不是區間。
- **結構呼叫** — 取得連線清單、資料表名稱或欄位的呼叫。不回傳業務列。
- **填數呼叫** — 會回傳業務列或計數的呼叫。v1 在 `MCP` 上是 `query` 與 `count`，在 `Web API` 上是讀取資料表列的 GET。
- **元件** — 畫布上的一個區塊。v1 只有標題、文字、參數、資料表、計數。
- **畫布** — 一份範本的元件序列，由上到下排列。拖曳改變順序。不記錄絕對座標。
- **繫結** — 元件指向的資料表名稱與欄位名稱。
- **參數** — 一種元件。綁定一個欄位，執行時提供一個等值篩選的值。範本只保存欄位與標籤，不保存值。
- **報表範本** — 名稱、所屬範本群組、畫布。只含版面、繫結與參數定義，不含資料列、不含連線字串、不含具名連線。
- **範本群組** — 範本的一個集合。每個範本恰好屬於一個群組。群組上有操作者的設計角色或檢視角色。
- **範本庫** — 工作台儲存裡全部範本群組與範本。操作者只看見自己有角色的群組。
- **建議** — 尚未寫入畫布或尚未執行的提案。設計器的建議是元件與繫結。交談的建議是意圖。
- **語句** — 操作者輸入的一段自然語言。
- **意圖** — 語句的解析結果：零個以上具名連線、零個以上報表範本、零個以上等值篩選。
- **確認** — 操作者明確同意執行一組已經列明的填數呼叫。活資料預覽裡的查詢按鈕、範本預覽按鈕、交談套版的確認按鈕，都是確認。
- **預覽** — 確認之後，用該次填數呼叫的結果填入畫布或活資料畫面。
- **預覽快照** — 該次預覽畫面上的數字與列。匯出與列印使用這份快照。
- **常用項目** — 操作者保存的一次叫法：名稱、範本、取數表面、具名連線、參數值。不含版面複本，不含資料列。
- **常用清單** — 一個操作者擁有的常用項目集合。其他操作者不可讀。
- **取數軌跡** — 畫面上一次呼叫的紀錄：操作者識別、具名連線、工具或請求種類、等值篩選、列數或計數或錯誤碼。
- **工作台儲存** — 工作台自己的帳號、群組、範本與常用項目存放處。不是業務庫。

## 4. Features

### 4.1 身分

**Description：** 工作台只讓已登入的操作者使用。帳號在工作台儲存。`[ASSUMPTION]` 沒有公開自助註冊；管理員建立其他操作者。第一個管理員由安裝設定建立。實作 UJ-4 的邊界，並讓 UJ-1 的呼叫者可被稽核辨認。

**Functional Requirements：**

#### FR-1: 未登入不可進入工作台

未登入的人不能使用活資料預覽、範本庫、交談、常用清單、匯出或列印。

**Consequences (testable)：**

- 未帶有效登入狀態的請求不回傳具名連線、欄位、業務列、範本或常用項目。
- 工作台不以 `anonymous` 呼叫 MCP。

#### FR-2: 管理員管理操作者與群組角色

管理員可建立操作者、建立範本群組，並指派或移除某個操作者在某個群組的設計角色或檢視角色。

**Consequences (testable)：**

- 非管理員不能建立操作者，也不能變更角色指派。
- 同一操作者可在不同群組具有不同角色。
- 設計角色的操作者在該群組同時滿足檢視角色的讀取能力。
- 移除角色後，該操作者再列出範本庫時不再包含該群組。

**Out of Scope：**

- 企業目錄、SSO、公開自助註冊。

### 4.2 活資料預覽

**Description：** 操作者選定取數表面與具名連線，查看資料表與欄位，以等值篩選讀取列。`MCP` 另可讀取計數。這片讓換引擎與「秘密留在伺服器」可以被看見。實作 UJ-1。`[ASSUMPTION]` 已登入操作者可對所有已登記具名連線做活資料預覽；v1 不做資料表級授權。群組角色不限制這片，只限制範本。

**Functional Requirements：**

#### FR-3: 列出可選的具名連線

操作者可看到每個可用具名連線的名稱與 `ServerType`。

**Consequences (testable)：**

- `MCP` 表面列出該宿主已登記、且名稱可解析的連線。
- `Web API` 表面只列出一個連線。`[ASSUMPTION]` 其顯示名稱為 `default`，`ServerType` 來自 WebService 組態。
- 清單、錯誤與後續請求都沒有連線字串欄位。操作者無法在工作台輸入連線字串。

#### FR-4: 選擇取數表面

操作者在 `MCP` 與 `Web API` 之間選擇這次預覽的取數表面。

**Consequences (testable)：**

- 切換表面會換掉 FR-3 的連線清單。
- 工作台不把 GraphQL 當作 v1 的取數表面。

#### FR-5: 瀏覽資料表與欄位

操作者可對選定的具名連線列出資料表，再列出選定資料表的欄位。

**Consequences (testable)：**

- `MCP` 使用 `tables` 與 `fields`。省略 `includeView` 時的行為與 MCP 宿主相同。
- `Web API` 使用 `GET /meta` 與 `GET /{resourceName}/fieldSet`。
- 這些呼叫是結構呼叫。沒有資料表時，清單是空的，畫面是空狀態。
- `fields` 回傳的每一欄至少包含名稱、型別、是否主鍵、是否不可為空。

#### FR-6: 以等值篩選預覽列

操作者設定零個以上等值篩選並確認後，可預覽符合條件的列。

**Consequences (testable)：**

- `MCP` 的確認會呼叫 `query`。多個等值篩選可同時存在。篩選值以參數傳遞。
- `Web API` 在零個篩選時讀取該表的列；在恰好一個篩選時使用 `Key` 與 `Value`。兩個以上篩選時，工作台拒絕確認，說明此表面只接受單鍵，並且不發送該請求。
- 沒有符合列時，預覽是空結果，不是未處理錯誤。
- 預覽列與同一次工具或 GET 的結果一致。工作台不另做第二次彙總。

#### FR-7: 在 MCP 上預覽計數

操作者在 `MCP` 表面可對同一張表與同一組等值篩選確認並看到計數。

**Consequences (testable)：**

- 確認會呼叫 `count`。無符合列時顯示 0。
- `Web API` 表面沒有計數動作。工作台不以讀完全表的方式自己計算筆數。

#### FR-8: 換引擎不換工具契約

同一組操作改打另一個 `ServerType` 的具名連線時，工具名稱與參數鍵不變。

**Consequences (testable)：**

- UJ-1 從 `inventory` 改到 `inventory_pg` 時，`tables`、`fields`、`query`、`count` 的名稱與參數鍵不變。
- 工作台不要求操作者另選引擎。引擎顯示來自 FR-3，不由操作者輸入。

#### FR-9: 取數軌跡對得上稽核

每次結構呼叫與填數呼叫都在畫面上留下取數軌跡。

**Consequences (testable)：**

- 軌跡含操作者識別、具名連線名稱、工具或請求種類、等值篩選、以及列數、計數值或錯誤碼。
- 對 `MCP` 的一次成功 `query`，軌跡裡的呼叫者、連線名稱、工具、篩選與列數，能在該次 MCP 稽核紀錄中找到對應。稽核的呼叫者等於操作者識別。
- 軌跡與稽核不包含業務列與連線字串。
- MCP 因稽核寫入失敗而回傳 `execution_failed` 時，工作台顯示該錯誤，並且不顯示部分列。

#### FR-10: 預覽不提供寫入與自由 SQL

活資料預覽沒有 SQL 輸入，也沒有新增、更新、刪除。

**Consequences (testable)：**

- 工作台發出的 `MCP` 工具呼叫，名稱只會是 `tables`、`fields`、`query`、`count`。
- 工作台對 `Web API` 只發出 FR-5 與 FR-6 所述的 GET。
- 操作者無法從工作台提交 `insert`、`update`、`delete`、`sql`，或 Web API 的 POST、PUT、DELETE。

#### FR-11: 可讀的失敗與空狀態

未知資料表、連線失敗與空結果都變成操作者讀得懂的狀態。

**Consequences (testable)：**

- `MCP` 的 `unknown_table`、`connection_failed`、`invalid_arguments`、`execution_failed` 以原錯誤碼與不含秘密的訊息顯示。
- 錯誤出現時，工作台頁面仍可繼續選擇其他連線或資料表。
- 空清單與零列使用空狀態，不顯示為未處理例外。

### 4.3 智慧報表編輯器與範本庫

**Description：** 設計者用五種元件組成報表範本，接受或修改依欄位提出的建議，並以群組管理範本庫。實作 UJ-2 與 UJ-4。建議只使用結構呼叫。

**Functional Requirements：**

#### FR-12: 五種元件

設計者可在畫布使用標題、文字、參數、資料表、計數。

**Consequences (testable)：**

- 標題與文字保存操作者輸入的字串。
- 參數綁定恰好一個欄位，並有標籤。範本不保存該參數的值。
- 資料表綁定恰好一個資料表，以及一個以上來自該表欄位的欄名。
- 計數綁定恰好一個資料表。
- 工作台不提供這五種以外的元件，也不提供圖表元件。

#### FR-13: 以拖曳編排畫布

設計者可加入、拖曳重排與刪除元件，並設定繫結。

**Consequences (testable)：**

- 畫布的順序是由上到下的序列。拖曳只改變這個順序。
- 重新開啟範本時，順序與繫結保持為上次保存的結果。
- 刪除元件後，保存結果不再包含該元件。

#### FR-14: 依欄位提出繫結建議

設計者選定資料表後，工作台提出元件建議。設計者可接受、修改或忽略。

**Consequences (testable)：**

- 產生建議前允許的呼叫只有結構呼叫。建議的內容不含業務列，也不含參數值。
- 建議至少包含一個資料表元件，其欄名全集等於該次 `fields` 回傳的欄名。
- 建議中每一個繫結欄名都存在於該次 `fields` 結果。類型只會是 FR-12 的五種。
- 接受會把建議的元件加到畫布末尾。忽略不改變畫布。修改後再接受，畫布採用修改後的版本。
- 含有未知欄名的建議不能被接受。

#### FR-15: 範本群組

管理員可建立與重新命名範本群組。對一個群組具有設計角色的操作者，可在該群組建立、重新命名、刪除範本，以及把範本移到另一個自己具有設計角色的群組。

**Consequences (testable)：**

- 新範本在保存時必須選入一個群組，且操作者對該群組具有設計角色。
- 範本恰好屬於一個群組。同一群組內名稱不重複。
- 移到沒有設計角色的群組會被拒絕，範本仍在原群組。
- 群組內仍有範本時，刪除該群組會被拒絕。
- 檢視角色不能建立、修改、刪除或移動範本。

#### FR-16: 範本不含資料與連線

保存範本只寫入版面、繫結與參數定義。

**Consequences (testable)：**

- 保存後的範本沒有資料列、連線字串、具名連線名稱與參數值。
- 關閉後再打開，不需要連線仍可看到版面與繫結。要看到列，必須另做預覽確認。

#### FR-17: 群組決定誰看得到範本

操作者只能列出自己具有設計角色或檢視角色的範本群組與其範本。

**Consequences (testable)：**

- UJ-4 中，陳安的範本庫與交談候選都不含薪資群組的範本。
- 以識別直接讀取或預覽無權限的範本時，工作台拒絕，且填數呼叫次數是 0。

**Feature-specific NFRs：**

- 設計器產生建議失敗時，既有畫布保持不變，並顯示可讀錯誤。

### 4.4 交談式套版

**Description：** 業務人員用語句從自己看得到的範本庫得到意圖。人確認後，工作台才依範本的繫結執行填數呼叫。實作 UJ-3。解析可以是關鍵字規則或側車，契約在附錄；兩種都必須滿足這裡的行為。

**Functional Requirements：**

#### FR-18: 語句解析成意圖

操作者提交語句後，工作台給出意圖：具名連線候選、範本候選、等值篩選。

**Consequences (testable)：**

- 候選連線只來自己列出的具名連線。候選範本只來自分操作者有檢視角色或設計角色的範本。
- 等值篩選的欄位必須是候選範本上的參數欄位。值是純量。
- 解析結果不含連線字串與業務列。
- 一句話裡的時間範圍只有在能對到某個參數欄位的一個等值時才成為篩選。不能對到時，該篩選不產生，工作台也不另造區間查詢。

#### FR-19: 未就緒時不填數

意圖不是恰好一個連線、恰好一個範本、且該範本每個參數都有值時，工作台不執行填數呼叫。

**Consequences (testable)：**

- 多個連線或多個範本時，工作台列出候選，讓操作者選到各剩一個。
- 缺少參數值時，工作台指出缺的欄位或標籤，讓操作者補上。
- 對不到任何連線或任何範本時，工作台說明對不到，候選為空。
- 上述三種情況在操作者補齊或選定之前，該次語句的填數呼叫次數是 0。
- 操作者可以改選候選。改選本身不是確認。

#### FR-20: 確認後只執行列明的填數呼叫

意圖就緒後，工作台先列出將執行的填數呼叫。操作者確認後才執行，並顯示預覽。

**Consequences (testable)：**

- 列出的呼叫與範本一致：每個資料表元件一次 `query`（或 Web API 上合法的單鍵 GET）；在 `MCP` 上每個計數元件一次 `count`。
- 這些呼叫共用該次意圖的具名連線，並帶上全部參數所組成的等值篩選。
- 確認之後實際發出的填數呼叫，與確認前列出的集合相同，沒有額外的 `query`、`count` 或 Web API 資料 GET。
- 任一資料表或計數元件的資料表缺少某個參數欄位時，整次確認被拒絕，填數呼叫次數是 0。
- 取數表面是 `Web API` 且篩選不是零個或一個時，確認被拒絕，行為同 FR-6。
- 取數表面是 `Web API` 且範本含計數元件時，確認被拒絕，工作台不改以讀取全表來產生計數。
- 任一呼叫失敗時，預覽顯示該錯誤，不用其他呼叫的舊列湊成一份成功報表。

### 4.5 常用清單、匯出與列印

**Description：** 確認後的預覽可以存成常用項目，並以同一份預覽快照匯出或列印。實作 UJ-3 的後段與 UJ-4 的隔離。

**Functional Requirements：**

#### FR-21: 保存與再次叫用常用項目

操作者可把一次就緒的叫法存成自己的常用項目，並在之後再次確認執行。

**Consequences (testable)：**

- 常用項目含名稱、範本識別、取數表面、具名連線名稱、參數值與擁有者。不含資料列、連線字串與版面複本。
- 常用清單只回傳擁有者自己的項目。
- 再次開啟時，工作台讀取範本目前的版面與繫結，套上常用項目的連線與參數，並依 FR-20 重新確認後才查詢。
- 範本已刪除，或操作者已失去該群組的檢視角色時，再次開啟被拒絕，填數呼叫次數是 0。
- 範本的參數欄位已變更，導致常用項目的參數無法對齊時，工作台指出差異並停在未確認狀態。

#### FR-22: 匯出與列印使用預覽快照

操作者可對目前的預覽快照匯出 PDF、列印，並把其中的資料表元件匯出 CSV。

**Consequences (testable)：**

- PDF、列印與 CSV 中的數字和文字等於該預覽快照，包含空結果。
- 匯出與列印不發出新的填數呼叫。
- 離開該次預覽後，舊快照不能再匯出；要匯出必須重新確認並產生新的預覽快照。
- 列印版面以元件為單位換頁，不提供預印表單對位。

**Feature-specific NFRs：**

- 同一份預覽快照連續匯出兩次，兩份 PDF 的業務數字相同。

## 5. Non-Goals (Explicit)

- 不成為第二套查詢引擎，也不自製跨廠商 SQL planner。
- 不接受自由 SQL、區間條件或跨表 join。
- 不在瀏覽器、範本、常用項目、錯誤、取數軌跡或稽核中放置連線字串。
- 不把業務列寫進範本、常用項目、解析器的持久儲存或稽核。
- 不做像素級報表引擎：沒有預印表單、分欄帶、子報表或絕對座標排版。
- 不做圖表、結果敘事、跨來源簡報與寫入提案。
- 不把 GraphQL 當作 v1 的取數表面。
- 不綁定單一語言模型廠商。關鍵字規則只要滿足第 4.4 節即可完成驗收。
- 不修改公開的 `IDbService` 與 `IDbServiceAsync` 簽名，也不修改資料平面 P0 的工具契約。
- 不做資料表級或欄位級授權。
- 不做企業目錄、SSO 與公開自助註冊。

## 6. MVP Scope

### 6.1 In Scope

- FR-1 至 FR-22。
- UJ-1 至 UJ-4。
- 三片都要通過：活資料預覽、編輯器與範本庫、交談套版與常用清單及匯出列印。
- `MCP` 上的多鍵等值篩選與計數，以及 `Web API` 上的單鍵讀取。
- 工作台儲存中的操作者、範本群組、範本與常用項目。

### 6.2 Out of Scope for MVP

- **區間篩選與跨表元件。** 理由：現有 `query` 與 `count` 沒有這個語意。要等資料平面另有 FR 才做。
- **圖表、敘事、跨來源簡報、寫入提案。** 理由：不阻擋本工作台的三片驗收。`[NOTE FOR PM]` 這些仍留在資料平面 PRD 第 10 節，本文件不把它們提前。
- **GraphQL 填數。** 理由：GraphQL 已有操作台。報表填數再接第三條客戶端會分散驗收。
- **像素級套印。** 理由：列印驗證的是快照數字與元件換頁，不是印刷對位。
- **資料表級授權。** 理由：v1 的授權單位是範本群組。活資料預覽對已登入操作者開放全部具名連線。
- **側車必須先於關鍵字規則。** 理由：行為契約相同。先用哪一種實作留給架構，不能放寬 FR-18 至 FR-20。

## 7. Success Metrics

**Primary**

- **SM-1：** 一份已保存的範本先對一個可連線的具名連線完成確認預覽，再只改連到另一個 `ServerType` 的具名連線，以相同參數完成確認預覽。兩次的 `query` 名稱與參數鍵不變，而且都得到該次工具回傳的列。驗證 FR-8、FR-16、FR-20。
- **SM-2：** 抽樣一份範本、一筆常用項目、一則錯誤、一筆取數軌跡與對應的 MCP 稽核。全文都找不到該連線的連線字串，也找不到該次業務列。驗證 FR-3、FR-9、FR-16、FR-21。
- **SM-3：** 對 UJ-3 的一句尚有多個候選或缺參數的語句，確認按鈕出現前的填數呼叫次數是 0。選定並確認後，實際呼叫集合等於畫面上列明的集合。驗證 FR-19、FR-20。

**Secondary**

- **SM-4：** 沒有角色的操作者列不出該群組範本，直接預覽被拒絕且填數呼叫次數是 0。甲的常用清單對乙的讀取結果是空的或拒絕。驗證 FR-2、FR-17、FR-21。
- **SM-5：** 匯出的 PDF 與 CSV 中的業務數字等於匯出當下的預覽快照，而且匯出過程沒有新的填數呼叫。驗證 FR-22。
- **SM-6：** 設計器建議被接受後，畫布上的資料表欄名等於該次 `fields` 的欄名；建議回應本身不含業務列。驗證 FR-14。

**Counter-metrics (do not optimize)**

- **SM-C1：** 不以開放 `sql`、增加區間查詢，或在瀏覽器掃描全表來計算筆數，作為 SM-1 或 SM-3 的達成方式。
- **SM-C2：** 不以圖表數量、絕對座標是否自由拖放、或套印預印表單，作為工作台完成度。
- **SM-C3：** 不以綁定某個模型廠商或側車已上線，作為 FR-18 的完成條件。關鍵字規則達到 SM-3 即算該行為完成。

## 9. Assumptions Index

- 第 4.1 節 — 沒有公開自助註冊；管理員建立操作者；第一個管理員來自安裝設定。
- 第 4.2 節 — 已登入操作者可預覽所有已登記具名連線；沒有資料表級授權。
- FR-3 — `Web API` 的唯一連線顯示名稱為 `default`。
- 第 4.4 節 — 關鍵字規則或側車都只須滿足意圖契約。
- 第 8 節 — PDF 預設 A4，不對位預印表單。
- FR-21 — 常用項目在再次叫用時採用範本當時的版面，不凍結保存時的版面複本。
- 第 12 節 — 預覽快照只活在該次已確認的畫面；離開後不可再匯出。

## 10. Cross-Cutting NFRs

- 操作者看得到的介面文字、空狀態、確認清單與工作台自己產生的錯誤，使用繁體中文。MCP 已回傳的訊息維持宿主原文。
- 錯誤至少含穩定代碼與給人讀的訊息。訊息不含連線字串、密碼與堆疊中的秘密。
- 密碼不以明文寫入工作台儲存。
- 解析器或建議步驟失敗時，不執行填數呼叫，已保存的範本與常用項目不變。
- 工作台不因為單一連線失敗而停止服務其他連線。

## 11. Constraints and Guardrails

- **資料邊界：** 連線字串只存在既有伺服器組態。工作台的請求、儲存、匯出檔與畫面都不新增這個欄位。
- **執行邊界：** 填數語意等於今天的 `MCP` `query`／`count`，或 `Web API` 的零鍵或單鍵 GET。工作台不改寫查詢。
- **確認邊界：** 結構呼叫可以在確認前發生。填數呼叫只發生在確認之後，而且集合必須與畫面上列明的相同。
- **相容邊界：** 不修改資料平面 P0 的工具清單、公開資料存取簽名，以及既有 REST 與 GraphQL 的路徑。
- **模型邊界：** 解析步驟不組 SQL、不開連線、不讀取連線字串。工作台在執行前檢查意圖裡的連線名稱與範本識別屬於此人此刻可選的集合。

## 12. Data Governance

v1 的授權單位是操作者與範本群組。活資料預覽是較寬的口：任何已登入操作者都能對已登記具名連線讀取結構與列。`[ASSUMPTION]` 這是為了讓 UJ-1 不必先做一份範本；資料表級授權見第 6.2 節，不在本版補上。

業務列只出現在確認後的預覽，以及由該預覽快照產生的 PDF、列印與 CSV。它們不寫入範本、常用項目、解析器持久儲存、取數軌跡或 MCP 稽核。預覽快照在操作者離開該次預覽後失效。

工作台儲存放在營運者自己的環境，不寫進業務庫，也不預設外送到第三方分析平台。常用項目裡的參數值可能是業務鍵值；它們與業務列分開存放，仍只對擁有者與管理員的維運備份可見。管理員不能透過常用清單介面讀取他人的常用項目。

## 13. Integration and Dependencies

- **MCP 宿主：** 多具名連線、換 `ServerType`、多鍵等值、計數與稽核都依賴已完成的 P0。工作台以操作者識別填入 `X-DBServices-Caller`。
- **WebService：** 只作為第二條取數表面，使用既有 `GET /meta`、`GET /{resourceName}/fieldSet` 與單鍵 `GET /{resourceName}`。
- **GraphQLService：** v1 不連接。
- **工作台儲存：** 新的存放，不復用業務庫的資料表來存範本。
- **解析：** 關鍵字規則或資料平面附錄所述的 Python 側車。側車失敗時行為同第 10 節。

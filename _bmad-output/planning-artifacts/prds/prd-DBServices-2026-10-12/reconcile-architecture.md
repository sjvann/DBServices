## 2. 圖上實際有的

左欄是「主流程」，分成「規劃期流程」與「執行期流程」；中間一列標「系統產出」。上方四個直欄是系統階段，每欄一位使用者、一個應用程式，欄與欄之間以虛線分開。

階段、人、應用程式：

- 資料彙整階段：使用者 DBA，應用程式「ETL工具（既有）」。
- 模組整合階段：使用者系統分析師，應用程式「模組設計工具（新增）」。
- 報表設計階段：使用者報表設計師，應用程式「AI報表設計工具（新增）」。
- 報表生成階段：使用者終端使用者，應用程式「Chat報表生成器（新增）」。

「既有」只標在 ETL 工具上。DBA 與另外三人同在「使用者」那一列。

規劃期：六邊形「二代平台資料源」拉出標「資料表結構」的箭頭，橫向進入模組整合階段，再以「存入模組定義」向下進入模組資料庫。這條箭不進入待轉資料庫。

執行期：另一個「二代平台資料源」經「讀取」「寫入」進入待轉資料庫。待轉資料庫右側是 web API 接口，接著「轉置模組資料」向上進入模組資料庫。模組資料庫右側另有 MCP 接口。MCP 的符號停在模組資料庫，沒有一筆畫進右側紅框。

報表設計階段：自模組資料庫「引用」，再「存入」報表樣式範本資料庫。這一站沒有交談迴路，也沒有私有／共享的標註。

四座系統產出：待轉資料庫、模組資料庫、報表樣式範本資料庫、私有/共享報表生成紀錄。

紅框在報表生成階段，框內左上有大字「AI」。框內由上到下：

- 「重複交談」：最上小框右側的迴路，貼著關鍵字那一步。
- 「抓關鍵字」。
- 「套用」：自報表樣式範本資料庫向右進入紅框。
- 「存入範本（可共享）」：紅框中段向右指出，落在私有/共享報表生成紀錄這一側，沒有畫回報表樣式範本資料庫。
- 「載入範本」：自該側垂直線向左指回紅框，位置在「讀取資料」與「產生報表」之上。該垂直線向上進入「私有/共享報表生成紀錄」。
- 「讀取資料」：長箭頭自左側資料庫一帶（待轉資料庫、web API 與模組資料庫下方）向右進入紅框下段。
- 「產生報表」向右指出旗標「動態報表」。動態報表是紅框的產出，與上方的私有/共享報表生成紀錄是兩件東西。

人只畫在自己那一欄的頂端。web API 與 MCP 畫在資料庫上，沒有畫進任何一位使用者的手上。

## 3. 落差

1. **資料彙整站的人被寫成非使用者。** 圖把 DBA 放在「使用者」列、資料彙整階段，與系統分析師、報表設計師、終端使用者並列；「既有」只標在「ETL工具」。PRD 第 2.2 節把這個人列入 Non-Users：「DBA。資料彙整仍用既有 ETL。」第 0 節把產品收成「三個新程式是三個入口」。四個人各守一站的語氣，收成三個入口加一個非使用者。

2. **規劃期看見的結構，來源被換掉。** 圖的規劃期是「二代平台資料源」箭頭「資料表結構」，不經過待轉資料庫；web API 畫在執行期，接「待轉資料庫」與「轉置模組資料」。PRD FR-4 寫「系統分析師可看到待轉資料庫的資料表與欄位」，後果寫「結構來自 web API 的表清單與欄位」。附錄寫 web API「只用來讀待轉資料庫的結構，以及依檢視定義轉置」。分析師在規劃期看見的那份表結構，被改成執行期待轉庫上的 web API。

3. **載入範本被併進套用，並且離開會讀資料的那條路。** 圖上三條箭分開：「套用」來自報表樣式範本資料庫；「載入範本」來自私有/共享報表生成紀錄一側，向左回到紅框，下面仍接著「讀取資料」與「產生報表」；「存入範本（可共享）」向右留在生成紀錄這一側。PRD 詞彙把 Chat 報表生成器寫成「套用或載入樣式範本……以及把版面存回樣式庫」。第 0 節寫「終端使用者可把樣式範本寫回與報表設計師共用的報表樣式範本資料庫」。第 0 節又寫「再開或共享時看到的是那一份，不重新讀取」；FR-14 寫「再開時顯示保存的那份動態報表，不重新呼叫 MCP」。載入被改成再拿一筆樣式範本，存回被改寫進設計師那座樣式庫，再開被改成這個人不再走進讀取與產生。

4. **私有／共享的語氣被搬到報表設計師身上。** 圖上「可共享」只出現在終端使用者紅框的「存入範本（可共享）」；「私有/共享」只出現在「私有/共享報表生成紀錄」。報表設計師那一站的箭頭是「引用」與「存入」，存入的庫名叫「報表樣式範本資料庫」，沒有私有或共享。PRD 第 2.1 節寫報表設計師「並決定這筆範本私有或共享」。UJ-2 寫「共享範圍選共享，存入報表樣式範本資料庫」。誰在哪一站決定共享，被從終端使用者與生成紀錄改到報表設計師的存入。

5. **會抓關鍵字、會重複交談的只有終端使用者那一格。** 圖上大字「AI」、迴路「重複交談」與「抓關鍵字」都在報表生成階段的紅框裡。報表設計階段沒有這個迴路。PRD UJ-2 讓報表設計師那一站「工具依輸出欄與參數提出版面建議」。第 5 節把紅框這一步寫成「不綁定單一語言模型廠商。關鍵字規則只要滿足第 4.4 節即可完成驗收。」UJ-3 邊界把「重複交談」寫成「工具繼續交談，指出缺什麼」。設計站被加上建議的語氣，終端使用者站的 AI 迴路被改成可不必是模型、並由工具指出缺什麼。

## 4. 已涵蓋

- 四個階段的名稱，以及系統分析師、報表設計師、終端使用者三個職位。
- 三個新增應用程式的名稱：模組設計工具、AI報表設計工具、Chat報表生成器。ETL 標成既有，PRD 不交付 ETL。
- 執行期：二代平台資料源經讀取、寫入進入待轉資料庫。
- 存入模組定義、轉置模組資料、模組資料庫，以及模組資料庫上的 MCP。
- 報表設計階段的引用，與存入報表樣式範本資料庫。
- 紅框內的抓關鍵字；關鍵字不夠就繼續談（PRD 願景：「關鍵字不夠就繼續談」）。
- 套用樣式範本、讀取資料、產生報表、動態報表。
- 私有/共享報表生成紀錄這座存放；終端使用者站有「存入範本（可共享）」這個動作。
- web API 與 MCP 畫在資料庫上。PRD 第 0 節：「人在三個入口都不選擇 MCP、Web API 或具名連線。」

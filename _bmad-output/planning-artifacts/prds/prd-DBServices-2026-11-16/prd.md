# PRD: DBServices 檢視輔助、樣本驗證與發布註記

本 PRD 給產品、體驗、架構與後續故事拆解使用。它定義模組設計工具的下一階段：**用已確認註記包，由 AI 協助選表與關聯、編成單句 SQL、以有上限的樣本驗證，再寫給報表 AI 看的檢視註記後才發布**。

來源結構與語意仍以 [資料來源註記 PRD](../prd-DBServices-2026-11-12/prd.md) 的已確認註記包為準。檢視文件形狀、樣式範本、Chat 報表生成器與報表生成紀錄維持 [檢視與報表 PRD](../prd-DBServices-2026-10-12/prd.md)，本文件只改多表如何提案、如何驗證、如何帶 SQL 執行，以及發布前必填的檢視註記。資料怎麼被安全讀取，仍以 [資料平面 PRD](../../../../docs/planning/agent-data-plane/prd.md) 為準。技術對應見 [addendum.md](addendum.md)。詞彙以第 3 節為準。推論標成 `[ASSUMPTION]`，並彙總在第 9 節。

## 1. Vision

資料治理已把來源註記成可確認的包。系統分析師接下來要回答業務問題：哪些表、怎麼連、輸出哪些欄、參數是什麼。缺的不是另一個自由 SQL 窗，而是一條可驗證的路徑：依啟用中的註記包提案結構，編成單一一句 SELECT，用有上限的樣本讓人眼確認 join，再寫上「一列代表什麼」與「這份檢視回答什麼問題」，才發布給其他人與報表 AI。

這一輪要證明的是：多表檢視可以從啟用包走到一次可執行的 SQL；新關聯只留在該筆檢視，不回寫來源註記包；樣本不入檔；發布後 MCP 才出現該檢視，且帶檢視註記；沒有 SQL 的舊檢視行為不變。連線字串仍留在伺服器。分析師不手打 SQL、不選連線。

## 2. Target User

### 2.1 Jobs To Be Done

- 系統分析師要把一個跨表問題收成可發布檢視：表、關聯、輸出欄、參數、已驗證 SQL 與檢視註記。
- 終端使用者與報表設計師要消費已發布檢視；報表 AI 要讀到檢視註記與欄位語意，才能就緒後呼叫一次。
- 資料治理人員要能再次確認來源註記包；檢視上的新關聯不進她的包，但端點仍受 `confirm_blocked` 保護。

### 2.2 Non-Users (v1)

- 要在設計站手打自由 SQL、選連線、或把樣本驗證當成一般查詢窗的人。
- 要把 AI 提出的新關聯寫回來源註記包或來源資料庫的人。
- 要在樣本或發布路徑執行個資遮罩的人。這一輪只沿用註記包裡的處理文字，不遮罩；樣本不留存。
- 要綁定某一家模型廠商才算完成的人。提案走可替換的埠；測試用固定提案。
- 未登入的人。

### 2.3 Key User Journeys

**UJ-1. 林可把一個跨表問題收成可發布檢視。**

- **Persona + context：** 林可是系統分析師。她要定義一份跨表清單檢視，讓後面的報表 AI 能回答業務問題。
- **Entry state：** 她已登入，且持有系統分析師入口。方晴已確認一份啟用中的註記包。
- **Path：** 她在模組設計工具輸入要回答的問題。工具只拿啟用包提案：來源表、已聲明或「僅此檢視」的關聯、輸出欄、參數、建議 SQL，以及每張表與每段關聯的理由。她接受結構。系統依已接受結構重編成單句 SELECT，對二代平台跑有上限的樣本。她看樣本後寫「一列代表什麼」與「這份檢視回答什麼問題」，必要時補欄位註解，再發布。
- **Climax：** MCP 目錄出現該檢視；多表讀列是一次已驗證 SQL，不是把每張表整表拉進記憶體再 join。
- **Resolution：** 定義裡沒有連線字串。樣本列不入檔、不進 MCP、不進報表生成紀錄。`annotations.json` 的 `links` 未被改寫。
- **Edge case：** 沒有啟用包、提案含包外的表或欄、僅此檢視的關聯理由空白、樣本失敗、列粒度或用途空白時，都不能發布；既有檢視定義不變。結構一改，先前的 SQL 與樣本作廢，必須重編、重驗。

**UJ-2. 陳安用報表 AI 消費這筆檢視。**

- **Persona + context：** 陳安是終端使用者。他用 Chat 報表生成器，依樣式範本問一句業務問題。
- **Entry state：** 他已登入，且持有終端入口。林可已發布那筆檢視，且有樣式範本綁定它。
- **Path：** 他只看到已發布檢視的名稱、檢視註記、輸出欄語意與參數。就緒後系統對該檢視呼叫一次。
- **Climax：** 動態報表的列來自那一次呼叫。
- **Resolution：** 他看不到樣本列與連線字串，也不能改 SQL。空白欄註在說明裡標成「尚未註記」。
- **Edge case：** 未就緒時繼續交談，讀列次數為 0。呼叫失敗時不產生動態報表，並顯示可讀錯誤。

**UJ-3. 方晴再確認來源註記。**

- **Persona + context：** 方晴是資料治理人員。來源結構變了，她再讀一次並準備確認新包。
- **Entry state：** 她已登入，且持有資料治理入口。林可已保存或發布檢視，其中可能含僅此檢視的關聯。
- **Path：** 她調整草稿後確認。工具檢查已保存檢視的來源表、輸出欄與關聯端點（含僅此檢視的端點）是否仍落在新包內。
- **Climax：** 都落在包內時確認成功；新包成為唯一啟用包。檢視上的 SQL 與定義不被改寫，也不重跑驗證。
- **Resolution：** 檢視上的新關聯沒有寫進她的註記包。
- **Edge case：** 任一已保存檢視會落到新包之外時，拒絕確認，訊息列出這些檢視的名稱；舊包與檢視維持原樣。

## 3. Glossary

- **啟用中的註記包** — `confirmed` 且 `active` 的那一份來源註記包。設計目錄與提案只讀它。沿用資料來源註記 PRD。
- **檢視提案** — 依啟用包與分析師問題產出的結構建議：來源表、關聯、輸出欄、參數、建議 SQL，以及每張表與每段關聯的理由。
- **僅此檢視的關聯** — AI 提出、人接受、且不在啟用包已聲明關聯清單內的表間關係。只記在該筆檢視上，不回寫註記包。必須有理由。
- **已接受結構** — 分析師接受後的來源表、關聯、輸出欄與參數。系統依它編成 SQL；建議 SQL 與它不一致時，以重編結果為準。
- **已驗證 SQL** — 依已接受結構編成、且通過樣本驗證的單一一句 SELECT。參數是綁定值。結構一改即作廢。
- **樣本驗證** — 對二代平台資料源執行已編成 SQL，帶回有上限的樣本列，供人眼確認。樣本不入檔。
- **檢視註記** — 發布前由系統分析師寫在檢視上的語意：至少含「一列代表什麼」與「這份檢視回答什麼問題」；欄位註解可空白。給報表 AI 參考，不是來源註記包的一部分。
- **提案埠** — 可替換的提案實作邊界。產品行為綁在結構、SQL 與樣本閘門，不綁模型廠商。測試可用固定提案。
- **模組設計工具／檢視／樣式範本／MCP／二代平台資料源／已聲明關聯** — 沿用十月與十一月 PRD 第 3 節。本文件不重新定義它們。

## 4. Features

### 4.1 依啟用包提案檢視

**Description：** 系統分析師用一句問題，從啟用中的註記包得到可接受的檢視結構。實作 UJ-1。

**Functional Requirements：**

#### FR-1: 提案只讀啟用包

系統分析師可對啟用中的註記包提出檢視提案。

**Consequences (testable)：**

- 沒有啟用包時不能提案，並顯示可讀錯誤；既有檢視不變。
- 提案的表、欄必須落在啟用包內。包外的表或欄使提案被拒，既有檢視不變。
- 提案必須說明每張來源表與每段關聯為何入選；依據是註記文字或已聲明關聯。
- 已聲明關聯優先。新關聯必須標成僅此檢視，並附理由；理由空白則不能接受。
- 兩張以上來源表時，每一張多出來的來源表都要有一段已接受關聯，否則拒絕，避免笛卡兒積。
- 畫面與錯誤用繁體中文，不含連線字串。
- 提案不讀業務列。

#### FR-2: 接受結構並編成 SQL

系統分析師可接受提案結構；系統依已接受結構編成單句 SELECT。

**Consequences (testable)：**

- 接受後寫入該筆檢視的來源表、關聯、輸出欄與參數。僅此檢視的關聯只寫在這筆檢視上。
- 接受成功後，`catalog/annotations.json` 內啟用包的 `links` 內容不變。
- 系統依已接受結構重編 SQL。提案裡的建議 SQL 只是建議；與結構不一致時以重編結果為準。
- SQL 是單一一句 SELECT，只投影已接受的輸出欄；參數是綁定值；篩選下推到資料庫。
- 不對來源庫做新增、更新、刪除或改結構。
- 分析師不能輸入自由 SQL，也不能選擇連線。
- 手改關聯若未經過接受提案路徑，仍依十一月 FR-7 拒絕（`link_undeclared`），既有定義不變。
- 結構一改，先前的 SQL 與樣本驗證結果作廢，必須重編、重驗後才能發布。

### 4.2 樣本驗證

**Description：** 接受結構後，對二代平台跑有上限樣本，讓分析師確認 join 結果。實作 UJ-1。

**Functional Requirements：**

#### FR-3: 有上限的樣本驗證

系統分析師可對已編成 SQL 執行樣本驗證。

**Consequences (testable)：**

- 驗證連線就是 `Annotation:PlatformConnection` 所指的那一筆二代平台來源。零筆、多筆、或名稱不符時不驗證，並顯示可讀錯誤。
- 待轉資料庫不能用來通過驗證。
- 樣本列數上限為 20，另有逾時。超過上限、語法錯誤、權限錯誤或逾時都算驗證失敗，不得發布。
- 驗證成功時，畫面可顯示樣本列；樣本不寫入 `views.json`、不進 MCP 目錄、不進報表生成紀錄、不成為報表本身。
- 驗證失敗時，既有已發布狀態不變；未發布的定義可保留已接受結構，但驗證標記為未通過。
- 錯誤訊息是繁體中文，不含連線字串、密碼與堆疊中的秘密。

### 4.3 檢視註記與發布

**Description：** 發布前必須寫檢視註記；發布後 MCP 才出現，且多表走已驗證 SQL。實作 UJ-1、UJ-2。

**Functional Requirements：**

#### FR-4: 發布前的檢視註記

系統分析師可在發布前編輯檢視註記。

**Consequences (testable)：**

- 檢視註記至少含「一列代表什麼」與「這份檢視回答什麼問題」；任一空白則拒絕發布。
- 欄位註解可以空白；空白在給報表 AI 的說明裡標成「尚未註記」。
- 檢視註記寫在檢視文件上，不寫進來源註記包。
- 寫的人是持有系統分析師入口的操作者。

#### FR-5: 驗證與註記通過才發布

系統分析師可在樣本驗證通過且檢視註記齊備後發布檢視。

**Consequences (testable)：**

- 未通過樣本驗證、或列粒度／用途空白時，拒絕發布；MCP 目錄不出現該檢視，既有已發布集合不變。
- 發布表示分析師確認目的、來源表、關聯、輸出欄、參數、已驗證 SQL 與檢視註記。
- 發布後 MCP 目錄才出現該檢視；工具說明帶上檢視註記與輸出欄語意。
- 未發布的檢視不在目錄裡。
- 發布與呼叫都不修改二代平台來源庫的結構，也不把註解寫回來源庫。
- 名稱不得與保留名 `source_annotation` 相同，比對不分大小寫。

#### FR-6: 已驗證 SQL 的執行期讀列

已發布且帶有已驗證 SQL 的檢視，執行期以該 SQL 一次查詢取列。

**Consequences (testable)：**

- 多表檢視的查詢次數是 1，不是來源表張數。
- 參數以綁定值傳入，不拼接成自由字串條件。
- 沒有 SQL 欄位（或 SQL 空白）的舊檢視維持既有 `ViewDispatch` 行為；這一輪不遷移、不改寫它們。
- Chat 仍在就緒後對該筆已發布檢視呼叫一次；讀列次數規則與十月 FR-12、FR-13 相同。
- 呼叫失敗時不產生動態報表，並顯示可讀錯誤。
- 連線字串不進入三個入口。

### 4.4 與來源註記再確認的銜接

**Description：** 僅此檢視的關聯不回寫註記包；再確認仍保護已保存檢視的落點。實作 UJ-3。

**Functional Requirements：**

#### FR-7: 新關聯不回寫註記包

僅此檢視的關聯只存在於該筆檢視。

**Consequences (testable)：**

- 接受提案、樣本驗證或發布，都不得改寫啟用中註記包或其他註記包的 `links`。
- 資料治理人員在註記站看不到這些僅此檢視的關聯被加進包內。

#### FR-8: 再確認仍檢查檢視落點

來源註記包再次確認時，已保存檢視的來源表、輸出欄與關聯端點（含僅此檢視的端點）必須仍落在新包內。

**Consequences (testable)：**

- 任一已保存檢視會落到新包之外時，拒絕確認，訊息列出這些檢視的名稱；舊包與檢視維持原樣，不取消發布，也不改寫 SQL。
- 確認成功時，不重跑樣本驗證，也不改 `views.json`。
- 行為與十一月 FR-5、FR-6 的 `confirm_blocked` 一致，並把僅此檢視的關聯端點納入檢查。

## 5. Out of Scope

- 把新關聯寫回來源註記包或來源資料庫。
- 個資遮罩或去識別化執行引擎；樣本列的遮罩。
- 分析師手打 SQL、選擇連線、或把樣本驗證做成一般查詢窗。
- 綁定模型廠商作為完成條件。
- 改樣式範本、Chat 讀列次數、報表生成紀錄的擁有者規則。
- 預印表單、把檢視落地成實體表、Avalonia 新入口。
- 自動在註記包再確認時重驗所有已發布 SQL。
- 遷移或改寫沒有 SQL 的舊檢視。
- 改寫資料來源註記站的匯入、確認、再讀、放棄流程。

## 6. Success Metrics

**Primary**

- **SM-1：** 以啟用包提案一筆兩表以上檢視；關聯理由與表欄都落在包內或標成僅此檢視；接受後 `annotations.json` 的 `links` 位元組不變。驗證 FR-1、FR-2、FR-7。
- **SM-2：** 樣本超過 20 列、SQL 錯誤、或列粒度／用途空白時不能發布；通過後 MCP 才出現該檢視，且多表查詢次數是 1。驗證 FR-3、FR-4、FR-5、FR-6。
- **SM-3：** 報表側讀得到列粒度與用途，讀不到樣本列與連線字串；空白欄註顯示「尚未註記」。驗證 FR-4、FR-5、FR-6。

**Secondary**

- **SM-4：** 沒有 SQL 的舊檢視行為與改動前相同。驗證 FR-6。
- **SM-5：** 再確認若使僅此檢視的關聯端點落到新包外，拒絕確認並列出檢視名稱；檢視 SQL 不被改寫。驗證 FR-8。
- **SM-6：** 沒有啟用包、包外表欄、或僅此檢視關聯理由空白時，接受或發布被拒，既有檢視不變。驗證 FR-1、FR-2、FR-5。

**Counter-metrics (do not optimize)**

- **SM-C1：** 不以開放自由 SQL、讓人選擇連線、或把樣本驗證變成一般查詢窗，作為完成度。
- **SM-C2：** 不以把樣本留在檔案、MCP 或報表生成紀錄，作為完成度。
- **SM-C3：** 不以把新關聯寫回註記包，或綁定某一家模型，作為完成度。

## 7. Integration with Existing Flow

```text
Excel 字典 ──┐
             ├─→ 資料來源註記（草稿）→ 確認 → 啟用中的註記包
已登記連線結構┘                              │
                                            ▼
                         模組設計工具：問題 → 提案 → 接受結構
                                            │
                                            ▼
                              編成 SQL → 樣本驗證 → 檢視註記 → 發布
                                            │
                                            ▼
                              樣式範本 → Chat 動態報表（一次呼叫）
```

- **接點 1：** 設計目錄與提案只讀啟用中的註記包；沿用十一月 FR-7 的表欄邊界與 `source_annotation`。
- **接點 2：** 檢視仍落在 `catalog/views.json`。本輪為帶 SQL 的新路徑加欄；空白 SQL 的舊文件維持十月行為。
- **接點 3：** 樣本驗證與執行期讀列都打二代平台資料源（`Annotation:PlatformConnection`）。註記站仍不讀業務列。
- **接點 4：** 樣式範本、Chat、報表生成紀錄只消費已發布檢視；不直接讀註記包，也不讀樣本。
- **接點 5：** 來源註記再確認的 `confirm_blocked` 納入僅此檢視的關聯端點；成功時不重驗 SQL。

**被本文件取代或收窄的舊句：**

- 十一月 PRD 第 5 節「用已確認註解，以 AI 輔助建立檢視與新的資料表關聯，再為檢視補註解」從非範圍改成這一輪的範圍。

## 8. Open Questions

1. 五種 `ServerType` 的 SQL 方言細節（引號、參數佔位、TOP／LIMIT／FETCH）由架構 AD 收束；產品約束仍是單句 SELECT、參數綁定、篩選下推。測試先打 Sqlite。
2. 樣本逾時的具體毫秒數由架構 AD 收束；產品約束仍是「有逾時，逾時即驗證失敗」。
3. 提案埠的宿主行程與提示詞組裝由架構決定；產品約束仍是可替換、測試可用固定提案、不綁廠商。

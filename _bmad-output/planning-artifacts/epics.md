# DBServices - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for DBServices, decomposing the requirements from the PRD, UX Design if it exists, and Architecture requirements into implementable stories.

編號 FR-1 至 FR-8、UJ-1 至 UJ-4 只指向 11-12 資料來源註記 PRD。資料平面的同名編號是約束，不是這份清單的流程編號。

## Requirements Inventory

### Functional Requirements

FR-1: 管理員可在既有入口指派為操作者加上或取消資料治理入口。未持有該入口的人打不開註記站。一人可同時持有資料治理與其他入口；打開某一站時只看到該站的工作內容。帳號與入口指派存在產品自己的存放，不在業務庫。入口代碼 `governance`、畫面名稱「資料治理」仍是假設。

FR-2: 資料治理人員可匯入符合 `Requirements/Samples.xlsx` 契約的 Excel 資料字典，產生註記草稿。同一工作表含 H 側與 S 側欄位、資料備註、允許空白；表級說明可出現在工作表內。匯入帶出實體表與欄、型別、允許空白、唯一索引勾記、已有描述與備註、個資去識別化處理文字（若有）。對不上契約時拒絕匯入，既有草稿不變。匯入不讀業務列，也不要求資料庫連線。「00.資料總表」不在這一輪。

FR-3: 資料治理人員可從已登記、組態完整的具名連線讀取結構，產生或更新註記草稿。恰有一筆二代平台資料源連線才讀取，帶出表、欄、型別、主鍵、外鍵，註解預設空白。零筆、多筆，或該筆是待轉資料庫時不讀取，讀列次數為 0，訊息可讀且不含連線字串。畫面沒有連線字串，也沒有選擇連線的動作。不提供自由 SQL，也不對來源庫做新增、更新、刪除。不使用待轉庫的 `GET /meta`。

FR-4: 資料治理人員可編輯整包功能說明、資料表註解、欄位註解與關聯。一份註記包可含多張表。關聯可包含庫裡沒有外鍵、由人聲明的關係，理由可以空白。欄註可以空白。索引保留唯一索引勾記的語意，人可在說明裡寫明它不是真正的唯一鍵。個資去識別化處理只保存自由文字，不執行遮罩。保存後重開，四層內容仍在，空白欄註仍是空白。

FR-5: 資料治理人員可儲存草稿、匯出 DBML，並確認註記包。未確認的草稿不進入模組設計工具。確認前每個實體表名與實體欄名都必須存在於二代平台資料源；對不上、沒有恰好一筆可對帳連線、說明空白、零張表或零個欄時拒絕確認，草稿與已確認包維持原樣。對帳通過後，若已保存檢視的來源表、輸出欄或關聯端點會落到新包之外，拒絕確認並列出檢視名稱；舊包與檢視不取消發布、不改寫。通過後這一份成為唯一啟用的已確認包，先前的包退出設計目錄但保留不刪。確認成功的訊息指出被取代的包。確認不修改來源庫結構，也不把註解寫回來源庫。草稿、已確認包與匯出檔都不含業務列與連線字串。匯出檔以 `Requirements/LH_TXN_MLST.sample.dbml` 作為 `Samples.xlsx` 的驗收對照。設計階段不讀確認前匯出的舊檔。

FR-6: 資料治理人員可再讀一次來源（Excel 再匯入或資料庫再讀），並在保留同名註記的前提下處理差異。比對鍵是實體表名加實體欄名，去掉首尾空白後原樣比較，區分大小寫。兩種再讀用同一條規則，結果寫進目前草稿，不改已確認包。草稿已有的同鍵註記保留；草稿沒有、上一份已確認包有的同鍵註記抄進草稿。改名就是刪除再新增，註記不跟著搬家。另列可見新增、刪除、型別、可否空白、主鍵、外鍵、唯一索引勾記。人寫過的註解不被來源蓋掉。未再次確認前，模組設計工具仍用上一份已確認包。放棄草稿時，已確認包維持原樣。再讀不讀業務列。

FR-7: 模組設計工具的資料表清單只來自已確認的註記包，含表、欄、型別、註解與已聲明關聯。欄註空白的欄標成「尚未註記」。沒有已確認包時清單是空的，並說明資料來源尚未註記。這兩句不是同一句話。模組設計工具不連二代平台資料源，也不連待轉資料庫來組這份清單。系統分析師不能選註記包以外的表或欄。兩張以上來源表時，每一段關聯必須等於註記包內某一條已聲明關聯的兩端表與欄，否則拒絕保存，既有檢視定義不變。分析師在這一階段不另造關聯。

FR-8: 檢視文件仍含名稱、目的、來源表、關聯、輸出欄與參數，不含業務列與連線字串。發布後 MCP 目錄才出現它。樣式範本、Chat 報表生成器與報表生成紀錄的行為維持不變。兩張以上來源表時，關聯是否合法以 FR-7 為準。已確認註記包同時經 MCP 提供給後續設計階段引用，該表面不讀業務列。

### NonFunctional Requirements

NFR-1: 操作者看得到的介面文字、空狀態與註記站自己產生的錯誤，使用繁體中文。

NFR-2: 錯誤至少含穩定代碼與給人讀的訊息。訊息不含連線字串、密碼與堆疊中的秘密。

NFR-3: 註記站任一路徑不讀取業務列。確認對帳只核對表名與欄名是否存在，不讀列。業務列讀取次數為 0。

NFR-4: 匯入失敗、再讀失敗、確認失敗、保存失敗或匯出失敗時，已確認的包與已保存的檢視定義不變。

NFR-5: 不在二代平台來源庫執行結構變更，也不把註解或 DBML 寫回來源庫。

NFR-6: 註記站沿用工作台既有配對的對比：正文為 ink-primary 在 surface-base 或 surface-raised；主要按鈕為 action-foreground 在 action；錯誤為 danger 在 surface-raised；尚未註記為 caution 在 surface-sunken。這一輪不新增前景／背景組合，也不做深色模式。

NFR-7: 互動控制項最小高度 36px。鍵盤焦點沿用 `:focus-visible`。`prefers-reduced-motion: reduce` 時取消過渡。沒有只靠懸停才看得到的操作。差異列除顏色外要有「新增」「刪除」或「已改變」文字。

### Additional Requirements

- 沒有綠地 starter template。註記站加在既有 Workbench.Web，不新建宿主專案。
- 可管理的 DBML 放哪一座資料庫留給架構。產品約束是草稿與已確認可區分，設計端與 MCP 都只把已確認註記包當目錄，內容不含連線字串與業務列。
- 如何判定一筆具名連線是二代平台資料源留給架構。待轉資料庫不能用來讀結構或通過確認。
- 註記站錯誤碼的拼法留給架構，可與工作台既有未定項一併收束。資料平面架構 AD-7 的 MCP 錯誤碼清單不套用到註記站。
- 連線字串只存在伺服器組態與既有連線工廠。請求、草稿、已確認包、DBML、日誌與畫面都不新增連線字串欄位。
- Excel 列如何收成 DBML 的 note、表 Note、索引名稱 `ix_` + 表名全小寫 + `_append`，以及索引說明「S_唯一索引 以 V 勾記。此組合不是唯一鍵，因為異動為 append」，以 addendum 與 `Requirements/LH_TXN_MLST.sample.dbml` 為驗收。表級 Note 忽略計數公式列，也忽略指向別張工作表的超連結。
- 資料平面約束繼續有效：不提供自由 SQL、不提供確認後寫入、錯誤不含秘密、執行期讀列仍走已發布檢視。註記站不實作 Discovery、匿名呼叫者或 MCP 工具畫面。

### UX Design Requirements

UX-DR1: 註記站只做在 Workbench.Web 的 `WorkbenchLayout`。入口代碼 `governance`，顯示名稱「資料治理」，左軌文字與頁面標題「註記」，路徑 `/governance`。未持有入口時沿用「沒有權限。」Avalonia 這一輪不新增資料治理入口。

UX-DR2: 只有資料治理一個入口時直接進入註記站。兩個以上入口時，換工作列出「資料治理」。資料治理左軌在「現在的工作」下只有「註記」，人在註記站時該連結使用 rail-link-active。不與檢視、樣式、產生報表排在同一組工作內容。

UX-DR3: 入口指派沿用既有頁，多一個核取方塊「資料治理」。非管理員看到「沒有權限。」保存失敗時用 status-message，勾選回到保存前，不因此新增管理員帳號。

UX-DR4: 註記站是同一頁的區塊：package-bar、purpose-field、table-list、table-note、column-editor、link-editor、diff-list、dbml-block、progress-line、result-line、status-message。寬度大於 1099px 時左欄是表清單、右欄是編輯，左軌 240px。1099px 以下改單欄，左軌仍 240px。720px 以下表單一欄，左軌 200px。

UX-DR5: 視覺只沿用 `Workbench.Web/wwwroot/tokens.css`，不新增色票。尚未註記用 caution 徽章。新增差異列用 action-soft。刪除差異列用 danger，且不靠刪線單獨表達。型別、可空、主鍵、外鍵、唯一索引勾記的改變用 caution。錯誤只用 status-message。進行中只用 progress-line，文案是「正在讀取結構。」或「正在匯入。」確認成功只用 result-line。

UX-DR6: 固定文案為：資料來源尚未註記；尚未註記；草稿；已確認；無法匯入。這份活頁簿對不上字典契約。既有草稿沒有改。；無法確認。這些檢視會落到新包之外：{檢視名稱}。；已確認。設計目錄改看這一包。若有被取代的包，成功句接「取代了{舊包名稱}。」放棄草稿的對話框寫：「放棄這份草稿？已確認的包維持原樣。」

UX-DR7: 零筆連線的訊息說明沒有讀取結構。多於一筆時說明註記站不能選擇連線，而且沒有讀取結構。該筆是待轉資料庫時說明不能用它讀結構或確認。三句都可以出現連線名稱，不可以出現連線字串。

UX-DR8: 確認與放棄各先經過一層 confirm-dialog。確認前若已有將被取代的已確認包，對話框寫出它的名稱。Esc 關閉對話框，不儲存該次確認或放棄。讀取或匯入進行中，匯入、讀結構與確認按鈕停用。

UX-DR9: 同時只有一份工作中的草稿。重開後四層與草稿徽章都還在。被取代的已確認包可從註記站唯讀打開、可再匯出，不能編輯，也不再進入設計目錄。放棄草稿後，若仍有已確認包就打開那一份唯讀，否則回到冷開啟。

UX-DR10: 匯出檔名是 `{包名}.dbml`。畫面上先顯示 dbml-block，同時下載該檔。匯出不要求已對上活庫，也不要求已確認。dbml-block 唯讀，不含連線字串或業務列。

UX-DR11: 無障礙地板：介面繁體中文；Tab 順序為左軌、package-bar、整包功能說明、表清單、表註、欄註、關聯、差異、DBML；錯誤 `role="alert"`，確認成功 `role="status"`；徽章與差異列都有文字，不只靠顏色。

UX-DR12: 模組設計工具左側清單改接已確認註記包。沒有已確認包時只顯示 empty-catalog「資料來源尚未註記」。欄註空白顯示 unmarked-badge。清單不提供包外的表或欄。要的關聯不在已聲明清單時，保存被拒絕，既有檢視定義不變，status-message 說明這段關聯不在註記包裡。檢視編輯器的其餘行為維持現況。

## Epic 1: 方晴把來源註記成可確認的 DBML

方晴能打開註記站，從 Excel 或資料庫結構做出草稿，補上整包說明、表註、欄註與關聯，匯出並確認一份 DBML。管理員能把資料治理入口交給她。確認後的包已保存；模組設計工具的目錄還沒改。

### Story 1.1: 指派資料治理入口並打開註記站

As a 管理員,
I want 在既有入口指派替操作者加上或取消資料治理，並讓持有的人打開註記站,
So that 方晴進得了自己的工作，沒有這個入口的人進不去。

**Acceptance Criteria:**

**Given** 管理員打開既有入口指派頁
**When** 她為一名操作者勾選或取消「資料治理」並保存
**Then** 勾選寫進產品自己的存放，不寫進業務庫，也不因此新增管理員帳號
**And** 入口代碼是 `governance`，畫面上的名稱是「資料治理」
**And** 非管理員打開這頁時看到「沒有權限。」

**Given** 保存這次指派失敗
**When** 頁面回應
**Then** 用 status-message，第一行是繁體中文，第二行是穩定代碼
**And** 勾選回到保存前。訊息不含連線字串、密碼或堆疊中的秘密

**Given** 操作者未被指派資料治理
**When** 她直接前往 `/governance`
**Then** 她看不到註記站，畫面沿用「沒有權限。」
**And** 左軌沒有「註記」

**Given** 操作者只持有資料治理
**When** 她登入
**Then** 直接進入註記站，路徑是 `/governance`，頁面標題是「註記」
**And** 左軌在「現在的工作」下只有「註記」，該連結使用 rail-link-active
**And** 這時沒有註記包，畫面不出現連線字串，也不讀業務列

**Given** 同一人同時持有資料治理與另一個入口
**When** 她在換工作選「資料治理」
**Then** 進入註記站，只看到註記，不與檢視、樣式、產生報表排在同一組
**And** 改開另一個入口時，左軌不出現「註記」

**Given** 這一輪的交付範圍
**When** 檢查 Avalonia 殼
**Then** 不新增資料治理入口。註記站做在 Workbench.Web 的 `WorkbenchLayout`

### Story 1.2: 匯入 Excel 產生草稿

As a 資料治理人員,
I want 在沒有工作中草稿時匯入符合字典契約的活頁簿，並在註記站看到表、欄與註解,
So that 方晴不用連資料庫，就能從 `Samples.xlsx` 這類字典做出一份可核對的草稿。

**Acceptance Criteria:**

**Given** 方晴已在註記站，而且沒有工作中草稿
**When** 她匯入 `Requirements/Samples.xlsx`
**Then** 產生一份狀態為「草稿」的註記包，package-bar 顯示包名與「草稿」
**And** 表清單有 `LH_TXN_MLST`。欄序、欄名、型別與是否 not null 對得上 `Requirements/LH_TXN_MLST.sample.dbml`
**And** `TABLE_DATE` 的 S 側空白，欄名仍用 H 側 `TABLE_DATE`，型別 `text`，欄註不含「H 欄名」
**And** `SSO_ID` 允許空白為 `Y`，沒有 not null；其餘樣品欄為 not null
**And** 六個勾記 `V` 的欄組成一條索引，名稱 `ix_lh_txn_mlst_append`，索引說明是「S_唯一索引 以 V 勾記。此組合不是唯一鍵，因為異動為 append」

**Acceptance Criteria:**

**Given** 林可依 Story 2.1 或 Story 2.2 保存一筆檢視
**When** 讀取這筆檢視文件
**Then** 仍含名稱、目的、來源表、關聯、輸出欄與參數
**And** 不含業務列，也不含連線字串
**And** `ViewDocument` 的欄位集合不增不減。兩張以上來源表時，關聯是否合法以 Story 2.2 為準

**Given** 這筆檢視尚未發布
**When** 外部 MCP 客戶端列出已發布檢視
**Then** 目錄沒有它

**Given** 她發布這筆檢視
**When** 外部 MCP 客戶端再次列出
**Then** 目錄出現它。未發布的檢視仍不在目錄
**And** 執行期讀列仍走這筆已發布檢視，不改走註記包，也不提供自由 SQL
**And** 沒有已確認註記包時，既有已發布檢視仍留在目錄

**Given** 有一份啟用中的已確認註記包
**When** 後續設計階段經 MCP 引用註記包
**Then** 回傳的是這一份啟用包的表、欄、型別、註解與已聲明關聯
**And** 草稿與已退出啟用的包不在這次回傳
**And** 回傳不含連線字串與業務列。業務列讀取次數為 0
**And** 這個表面不讀列、不接受 SQL、也不寫入來源庫。工具名稱留給架構
**And** 沒有啟用包時，不回退成即時結構或表級工具

**Given** 樣式範本、Chat 報表生成器與報表生成紀錄
**When** 這則完成
**Then** 三者的行為維持不變，仍只消費已發布檢視，不直接讀註記包

這則不實作 AI 輔助建立檢視，也不實作註記站的 Discovery 或 MCP 工具畫面。

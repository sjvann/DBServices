- (decision) User chose P0 transport: Streamable HTTP only. The MCP host is a long-running ASP.NET Core net10.0 project, sibling to WebService, using ModelContextProtocol.AspNetCore 2.2.0. SessionMode stays HttpServerSessionMode.Stateless (SDK default). Legacy SSE stays off. Tool handlers do not reference the transport. A stdio host is deferred and would wrap the same tool library.
- (decision) ADOPTED from FunctionRegistry: the connection name is resolved by the host before IQuerySession.Execute. It is stripped from the argument dictionary. query, count, exists, insert, and update treat every non-reserved key as a column filter, so a connection argument that reached the registry would become a filter.
- (direction) User chose open exposure: AllowedHosts * like WebService, listen address decided at deploy time, missing caller identity still recorded as anonymous and the call still runs. Not adopted yet. Coach is pushing back on AllowedHosts * before it becomes a rule, because ModelContextProtocol.AspNetCore 2.2.0 tells local HTTP servers to list host names and not use *.
- (decision) ADOPTED after one pushback the user declined: P0 ships AllowedHosts *. Listen URLs come from host configuration, not a hardcoded address. A call with no caller identity is anonymous and still runs. Accepted risk: host-header filtering is off, so the operator network is the trust boundary, including DNS rebinding if a browser can reach the port. WebService already uses AllowedHosts *.
- (decision) ADOPTED from existing product language (EZIE, docs/guides/security.md, docs/architecture/layers.md): the tool argument that selects a named connection is connectionId. The host removes connectionId before IQuerySession.Execute so the function registry cannot treat it as a column filter.
- (direction) Caller identity header proposed as X-DBServices-Caller. Absent or blank becomes anonymous. Stated with the exposure decision so the user can rename it; not a separate fork.
- (decision) User chose the Connections dictionary. ADOPTED: the MCP host's own configuration has a Connections object keyed by connectionId. Each value has ServerType and ConnectionString only. It does not read WebService ConnectionStrings:default or ServerType:Name. appsettings, environment variables, and user secrets all bind to that shape; there is no custom catalog file.
- (decision) ADOPTED from PRD FR-12 assumption: when a call omits connectionId, the host selects the connection only if exactly one usable entry exists. Zero or more than one returns a structured error and does not fall through to another connection.
- (decision) ADOPTED from FR-13: a bad entry (unknown ServerType, missing connection string, or a connection that fails to open) does not stop the host. The host caches an IDbService only after a successful create. A failed create is not cached, so a later call can succeed. The audit store is not a Connections entry.
- (decision) User chose JSONL. ADOPTED: one append-only JSONL file on the host. Each line is one call with UTC timestamp, caller, connectionId, tool, arguments, and rowCount or error code. Result rows and connection strings are never written. Concurrent appends must not tear a line. Path is configurable; retention days stay deferred and the operator deletes old files. The file is not a Connections entry and not an MCP tool.
- (decision) User chose nested filters. ADOPTED: query, count, and exists take an optional filters object. Host parameters stay connectionId, table, id, and includeView. The host flattens filters into the session argument dictionary after removing connectionId. A column named connectionId or table cannot collide with a host parameter.
- (decision) ADOPTED result shape from the session, with the PRD unwrap: tables, fields, get, and query return JSON columns and rows from QueryResult. An empty row list is success. count returns the single number. exists returns the single boolean. The host does not recompute or reshape the row set.
- (direction) Closed error codes proposed for the tool result and the JSONL error field: tool_disabled, unknown_tool, unknown_connection, connection_required, connection_failed, invalid_arguments, unknown_table. Forbidden argument names connectionString and connectString are invalid_arguments and the message does not echo the value. Shown to the user with the missing-table question.

# 報表工作台 — Experience Spine

`DESIGN.md` 是視覺身份。本檔是行為。衝突時以這兩份骨架為準，不以草圖或口頭補充為準。

## Foundation

多表面：瀏覽器裡的 Blazor（`Workbench.Web`）與 Avalonia 桌面殼（`Workbench.Avalonia`）。部署恰好一個 `Workbench` 進程。Avalonia 不嵌入 Blazor，殼只知道工作台基底網址。沒有命名的 UI 元件庫；兩殼實作同一套行為，視覺差值只寫在 `DESIGN.md`。

這是內部營運工具。旅程裡出現庫存、銷貨與薪資範本，資料敏感。產品不是對外申報系統，也不是消費產品。

帳號與角色分開，而且只由管理者帳號負責。帳號是可登入的操作者，建立時只有顯示名稱與登入秘密，沒有工作種類。安裝完成後恰好一個管理者帳號。這個帳號在「角色指派」把角色加到別的帳號上，也可以加到自己的帳號上。畫面上不能再建立第二個管理者。

工作角色可以同時多個：資料層級 MCP 的規劃設計師、善用 MCP 制訂智慧報表的範本編輯師、用語句取得動態報表的終端使用者。左軌依已指派的工作角色出現，不依帳號種類。範本群組上的設計角色與檢視角色也只在角色指派裡指定。一個帳號對一個群組至多一筆；設計角色包含檢視角色的讀取能力。

活資料預覽只出現在有「規劃設計師」的帳號。這覆蓋來源裡「任何已登入操作者都能預覽全部具名連線」的假設。群組角色仍然只限制範本，不另外做資料表級授權。

介面文字、空狀態、確認清單與工作台自己產生的錯誤使用繁體中文。MCP 已回傳的訊息維持宿主原文。工作台自己的錯誤是穩定英文蛇形碼加繁體中文訊息。

三片都要通過才算完成：片 1 活資料預覽，片 2 編輯器與範本庫，片 3 交談套版、常用清單、匯出與列印。前一片是下一片的閘門。本骨架描述三片都在時的完整體；實作順序仍守閘門。來源沒有路由表，下列表面是依三類工作排的。

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 登入 | 未持有工作階段時 | 取得工作階段。沒有註冊 |
| 活資料預覽 | 左軌，僅當帳號有規劃設計師 | 選取數表面、看具名連線、瀏覽表與欄、列出填數呼叫並確認 |
| 範本庫 | 左軌，帳號有範本編輯師或終端使用者 | 只列出自己有群組角色的範本。有設計角色才能改；只有檢視角色時只讀 |
| 編輯器 | 範本庫中一列範本，且該群組為設計角色 | 由上到下排元件、繫結、接受或忽略建議、存入有設計角色的群組 |
| 交談套版 | 左軌，僅當帳號有終端使用者 | 輸入語句，看到意圖與確認清單。確認後進入預覽 |
| 常用清單 | 左軌，僅當帳號有終端使用者 | 自己的常用項目。再開時用範本目前的版面，確認後才進入預覽 |
| 預覽 | 左軌，帳號有任一工作角色；確認後由活資料預覽、編輯器、交談套版、常用清單進入 | 獨立頁。顯示該次預覽快照。匯出 PDF、列印、匯出 CSV 在這一頁 |
| 帳號 | 左軌，僅管理者帳號 | 建立與列出操作者。表單沒有角色 |
| 角色指派 | 左軌，僅管理者帳號 | 選一個已存在的帳號，再指派工作角色與群組角色 |
| 模型設定與測試 | 左軌，僅管理者帳號 | 設定一份模型並測試連線。測試不先儲存 |

預覽是獨立頁。沒有快照時，這一頁是空的。確認成功後才進入，並顯示該次的列或計數。匯出 PDF、列印、資料表匯出 CSV 只在該次預覽快照還在時可按。以後這一頁可以再加註解、背景與圖片；這一版不做，因為來源的元件只有標題、文字、參數、資料表、計數，畫布也不保存座標。

取數軌跡不是左軌目的地。每一次結構呼叫與填數呼叫在發出呼叫的表面上留一列 `trace-row`。寬度足夠時在主欄右側，否則在主欄下方。

對話框只疊一層。不做資料表級授權。非管理者帳號的左軌沒有帳號、角色指派、模型設定與測試。直接指定這些表面時拒絕，不建立操作者，也不變更角色。

畫面參考：`mockups/key-live-preview.html`（活資料預覽，確認前）、`mockups/key-editor.html`（編輯器）、`mockups/key-preview.html`（預覽的空頁與確認後）、`mockups/key-role-assign.html`（角色指派）。

[NOTE FOR UX] 登入與模型設定與測試還沒有具名人物的旅程。角色指派的旅程用「管理者帳號」這個安裝時的帳號，來源沒有再給個人名字。

## Voice and Tone

微文案。品牌姿勢在 `DESIGN.md` 的 Brand & Style。用詞與來源詞彙相同：報表工作台、操作者、管理員、設計角色、檢視角色、具名連線、ServerType、取數表面、等值篩選、結構呼叫、填數呼叫、元件、畫布、繫結、參數、報表範本、範本群組、範本庫、建議、語句、意圖、確認、預覽、預覽快照、常用項目、常用清單、取數軌跡、工作台儲存。

| Do | Don't |
|---|---|
| 「確認之前，這裡沒有業務列。」 | 「預覽即將為你準備好！」 |
| 「沒有符合的列。」 | 「找不到資料，請再試一次。」 |
| 「沒有資料表。」 | 「這裡空空如也。」 |
| 「此表面只接受單鍵。」 | 「篩選太多了，系統已自動忽略。」 |
| 錯誤碼保持原樣，人話另起一行 | 把 `unknown_table` 翻譯成另一個代碼 |

## Component Patterns

行為。外觀在 `DESIGN.md` 的 Components。

| Component | Use | Behavioral rules |
|---|---|---|
| confirm-button | 活資料預覽、編輯器、交談套版、常用清單再開 | 標籤只限：查詢、計數、範本預覽、確認。按下代表同意執行畫面上 `call-list` 已列明的填數呼叫，並進入預覽頁。改選連線、範本或候選不是確認。`ready` 以外不可按 |
| secondary-button | 全表面；匯出三顆只在預覽頁 | 接受建議、忽略建議、加入關鍵字、儲存、匯出 PDF、列印、匯出 CSV。接受建議只把元件加到畫布末尾，不取業務列。匯出與列印不發出新的填數呼叫 |
| canvas-block | 編輯器 | 五種：標題、文字、參數、資料表、計數。拖曳只改變由上到下的 `order`。每個區塊另有上移、下移。沒有座標。刪除後保存結果不再含該元件。檢視角色只能看 |
| preview-well | 預覽頁 | 獨立頁的本文。沒有快照時沒有業務列。確認成功後顯示該次列或計數，空結果也是結果，計數可以是 0。人留在這一頁時，上一筆成功的列留到下一次成功確認才換。離開這一頁後，舊快照不能再匯出。這一版沒有註解、背景、圖片 |
| call-list | 確認前 | 列出將執行的填數呼叫。MCP 上恰好一筆已發布模組視圖。Web API 上是零鍵或單鍵 GET。實際呼叫集合必須與清單相同。任一筆失敗時，預覽只有該錯誤，不用其他呼叫的舊列湊成成功報表 |
| error-block | 呼叫失敗、拒絕確認 | 顯示代碼與人話。不含連線字串、密碼、金鑰、堆疊秘密。MCP 代碼原樣：`unknown_table`、`connection_failed`、`invalid_arguments`、`execution_failed`。出現後仍可改選其他連線或資料表 |
| trace-row | 發出呼叫的表面 | 每筆結構呼叫與填數呼叫一列。不含業務列與連線字串。MCP 錯誤碼原樣 |
| connection-row | 活資料預覽、交談與常用所選的連線 | 只顯示名稱與 `ServerType`。切換取數表面會換掉整份清單。Web API 的顯示名固定為 `default`。不能輸入連線字串 |
| account-row | 帳號 | 一列一個操作者，只顯示名稱。建立與編輯都不收集角色。不能把操作者改成管理者 |
| role-badge | 角色指派 | 工作角色可多選：規劃設計師、範本編輯師、終端使用者。群組角色在選定的範本群組上單選設計角色或檢視角色，或清空。同一群組不並存兩筆。設計角色在讀取時視同檢視角色。儲存角色不是確認，不發出填數呼叫 |
| intent-status | 交談套版 | 只顯示宿主重算後的 `ready`、`ambiguous`、`incomplete`。多候選或缺參數時停在補齊，填數次數是 0 |

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 未登入 | 任何工作台表面 | 停在登入。不回傳連線、欄位、列、範本或常用項目，不以 `anonymous` 呼叫 MCP |
| 帳號尚無工作角色 | 登入後 | 左軌沒有三類工作的表面。說明：「尚未指派工作角色。」帳號仍然存在 |
| 非管理者 | 帳號、角色指派、模型設定與測試 | 左軌不出現。直接進入時拒絕 |
| 沒有資料表 | 活資料預覽 | 清單空，畫面是空狀態：「沒有資料表。」 |
| 結構呼叫失敗 | 活資料預覽 | error-block 顯示代碼與人話。仍可改選其他連線或資料表。不進入預覽頁 |
| 沒有快照 | 預覽 | 「確認之前，這裡沒有業務列。」不下載列來當佔位。匯出與列印不可按 |
| 沒有符合的列 | 預覽 | 空結果，不是未處理錯誤。計數顯示 0 |
| 連線或查詢失敗 | 預覽上的 error-block | 人留在預覽頁。可讀錯誤。宿主仍在。先前成功的列留在這一頁，直到下一次成功確認才換。這次錯誤不把它們換成未處理例外。舊快照若已因離開或新的確認而失效，匯出不可按 |
| 意圖未就緒 | 交談套版 | `ambiguous` 列出候選；`incomplete` 指出缺連線、缺範本或缺參數。確認按鈕不可按 |
| Web API 能力不足 | 確認當下 | 兩個以上篩選：拒絕並說明「此表面只接受單鍵」，不發送。範本含計數元件：整次確認拒絕 |
| 建議含未知欄 | 編輯器 | 不能接受。忽略或建議失敗都不改畫布 |
| 無權限範本 | 範本庫、交談、預覽 | 清單與建議裡不出現。以識別直接預覽時拒絕，填數次數 0 |
| 常用項目對不齊 | 常用清單再開 | 範本已刪、失去檢視角色，或參數欄對不齊：指出差異，停在未確認，填數次數 0 |
| 快照已離開 | 匯出、列印 | 舊識別不能再匯出。同一快照連續匯出時，業務數字相同 |
| 模型未啟用 | 交談套版 | 只走關鍵字規則。模型測試的碼只會是 `model_ok`、`model_invalid_settings`、`model_unreachable`、`model_timeout`，訊息繁體中文，不帶回模型回覆內文 |
| 零個操作者且缺初始密碼 | 登入 | 不提供工作台功能 |

[NOTE FOR UX] 來源沒有載入中的畫面規格，也沒有「未儲存變更」的對話。快速路徑不補儲存提示框。儲存是明確的 secondary-button。

## Interaction Primitives

- 點按執行動作。會取業務列的動作只有 confirm-button。
- 拖曳只在編輯器的 canvas-block 上改變上下順序。每個區塊另有上移、下移。
- 改選取數表面、具名連線、範本或意圖候選，本身不是確認。
- 語句欄的 Enter 只送去解析，不確認填數。Esc 關閉最上層對話框，不確認。
- 確認成功後進入預覽頁，焦點移到該頁標題。
- 匯出與列印只吃目前預覽快照。
- 來自 AI 的關鍵字規則，要等這次意圖已確認，再按一次「加入關鍵字」才寫入。開啟常用項目不查詞庫。

禁止：自由座標畫布、自由 SQL、區間條件、跨表 join、圖表、結果敘事、連線字串欄位、寫入業務庫、公開註冊、資料表級授權、用讀全表的方式替 Web API 補計數、對話框疊兩層。

## Accessibility Floor

行為。對比在 `DESIGN.md` 的 Colors。上移、下移已確認。來源沒有對比等級的契約，WCAG 那一條仍是 [ASSUMPTION]。

- [ASSUMPTION] Blazor 以 WCAG 2.2 AA 為底。Avalonia 用同一閱讀順序、同一控制項名稱，可全鍵盤操作。
- confirm-button 的可否按下，除了顏色，還有標籤與 `intent-status` 文字。錯誤同時有代碼與訊息。
- 拖曳改序不是唯一手段；上移、下移必須在。
- 停用墨對比不足，不能單獨表示原因。
- 焦點順序等於閱讀順序。Esc 關閉最上層對話框。
- 進入預覽頁時宣告頁名。頁內的列或錯誤更新用可被讀屏發現的區域，不把焦點從人正在讀的錯誤上扯走。

| 表面 | 行為 |
|---|---|
| Blazor，寬度 ≥ 1280px | 左軌展開。取數軌跡在主欄右側 |
| Blazor，1100–1279px | 左軌仍在。軌跡改到主欄下方 |
| Blazor，< 1100px | [ASSUMPTION] 不另做手機版。允許橫向捲動，不把確認清單藏進只有懸停才看得到的地方 |
| Avalonia | 與 Blazor 同一資訊架構。最小視窗 1100×720。登入持有 bearer；Blazor 持有 cookie。兩者都只帶同一個 `sessionId`。登出後兩邊同時失效 |

Avalonia 與 Blazor 功能相同。片 1 到片 3 的表面都在，包含獨立的預覽頁。

## Inspiration & Anti-patterns

來源已經拒絕的做法，視覺與互動都不接回來：

- 拒絕自由座標、預印表單、分欄帶、子報表。畫布是順序。
- 拒絕圖表、結果敘事、跨來源簡報。
- 拒絕在瀏覽器放置連線字串，或在確認前把業務列畫出來。
- 拒絕第二套查詢引擎、自由 SQL、區間與跨表。
- 拒絕把 GraphQL、操作台或 CLI 放進 v1 填數路徑。

[ASSUMPTION] 不借用儀表板的卡片牆，也不借用套印軟體的頁面畫板。

## Key Flows

### UJ-1. 林可換一座庫，確認工具沒有變。

林可維護公司庫存。正式庫是 SQL Server，測試庫是 PostgreSQL。管理者帳號已在角色指派裡給她「規劃設計師」。她的帳號本身沒有這個種類。她已登入。

1. 她開啟活資料預覽，看到 `inventory`（`SqlServer`）與 `inventory_pg`（`PostgreSQL`）。畫面上沒有連線字串。
2. 她對 `inventory` 選 `products`，看欄位，設等值篩選。結構瀏覽不產生填數清單。
3. 她在 MCP 上確認一個已發布模組視圖。`call-list` 恰好一筆該視圖。
4. 確認後進入預覽頁，出現列。她也可以回到活資料預覽另按計數，清單恰好一筆 `count`，再進入預覽頁。`trace-row` 留下這次呼叫。
5. 她回到活資料預覽，只把連線改成 `inventory_pg`，表與篩選不變，再按查詢，再次進入預覽頁。
6. **高潮：** 預覽頁上兩次都得到該次呼叫回傳的列。模組視圖的名稱與參數鍵不變。畫面上沒有連線字串。單表瀏覽若保留，只出現在 Web API。

失敗：連線改到 `ServerType` 無法建立的名稱。預覽頁顯示可讀錯誤，工作台與 MCP 宿主都仍在。先前那次成功查詢的列留在預覽頁，不會被這次錯誤覆蓋成未處理例外。

### UJ-2. 周寧做出一份不含資料列的月報範本。

周寧負責銷貨報表的版面。管理者帳號已指派「範本編輯師」，並在目標群組給了設計角色；她要看欄位，所以同一個帳號上還有「規劃設計師」。表是 `sales`，欄 `yearMonth` 例如 `2026-10`。活資料預覽已能看見 `sales` 的欄位。

1. 她從範本庫開啟編輯器，選定 `sales`。
2. 她依 `fields` 取得建議。最小建議是一個資料表元件，欄名等於該次欄位集合。
3. 她接受建議。新的 canvas-block 加到畫布末尾。她拖曳調整順序，加上標題、文字、綁 `yearMonth` 的參數，以及計數。
4. 她命名，存進她有設計角色的群組。
5. **高潮：** 她重新打開這份範本。畫布上是她留下的元件與繫結。畫面上沒有任何業務列。

失敗：建議含 `fields` 沒有回傳的欄位。她無法接受。忽略建議不會改動已經排好的畫布。

她若要看列，必須另按範本預覽並確認，然後進入預覽頁。範本庫裡這份範本只含版面、繫結與參數定義。編輯器的畫布上仍然沒有業務列。

### UJ-3. 陳安用語句叫出月報，確認後才列印。

陳安每月要看銷貨月報。管理者帳號已指派「終端使用者」，並在該群組給了檢視角色。沒有設計角色，也沒有規劃設計師，所以左軌沒有活資料預覽，編輯器也不能改。他說「庫存庫的銷貨月報，年月 2026-10」。範本有參數 `yearMonth`，至少有一個可選的具名連線。

1. 他在交談套版輸入語句。
2. 畫面列出連線、範本與參數值。多個候選時他選定一個。改選不是確認。
3. 意圖成為 `ready` 後，`call-list` 列出將執行的填數呼叫。在這之前，預覽頁沒有業務列，填數次數是 0。
4. 他按確認，進入預覽頁。頁上出現表與計數，數字來自該次唯讀呼叫。
5. 他存成自己的常用項目，在預覽頁匯出 PDF 並列印。PDF 預設 A4，以元件為界換頁。PDF、列印與預覽頁上的數字一致。
6. **高潮：** 確認之前，預覽頁沒有業務列。確認之後，這一頁才有。隔天他從常用清單再開：用範本目前的版面，加上常用項目裡的連線與參數，重新產生清單，再確認才進入預覽頁。不讀舊的列。

失敗：語句對不到。畫面停在候選或請他補齊，填數次數是 0。他若失去檢視角色，這份常用項目無法再執行。

### UJ-4. 陳安看不到周寧的另一組範本。

周寧有一份薪資範本，放在陳安沒有群組角色的群組。兩人的工作角色都是管理者帳號另行指派的，不是帳號種類。兩人都已登入，各自有常用清單。

1. 陳安打開範本庫，並在交談套版看建議。
2. 周寧打開自己的常用清單。
3. **高潮：** 陳安的清單與建議裡沒有薪資範本。周寧的常用項目沒有出現在陳安的清單。管理員也不能從常用清單介面讀到別人的常用項目。

失敗：有人用薪資範本的識別直接要求預覽。工作台拒絕，不進入帶有列的預覽頁，並且不執行填數呼叫。周寧若要把銷貨範本移入她沒有設計角色的群組，移動被拒絕，範本仍留在原群組。

### 管理者帳號把角色指派到帳號

安裝完成後的那一個管理者帳號。來源沒有再給這個人的名字。

1. 管理者登入，左軌出現帳號、角色指派、模型設定與測試。
2. 開啟帳號，建立一個操作者。表單只有顯示名稱與登入秘密。儲存後，account-row 上沒有角色徽章。
3. 開啟角色指派，選剛才那個帳號。
4. 勾選一個或多個工作角色，並在一個範本群組上指定設計角色或檢視角色。儲存。這一步不發出填數呼叫。
5. **高潮：** 該操作者重新登入。左軌只出現被勾選的工作段。帳號頁仍然沒有角色欄位。要再改能力，只有管理者回到角色指派。

失敗：另一個已登入的帳號直接打開角色指派。工作台拒絕，角色與帳號都保持原狀。

# 模組設計工作台 — Experience Spine

`DESIGN.md` 是視覺身份。本檔是行為。衝突時以這兩份骨架為準，不以 `imports/views-current.png` 或計畫裡已被本檔改寫的畫面句子為準。

## Foundation

單一表面：瀏覽器裡的報表工作台，既有的檢視頁 `/views`。不另建產品，不新增路由。

視覺值在 `DESIGN.md`，對應 `Workbench.Web/wwwroot/tokens.css`。這一輪沒有命名的元件庫。左欄指定用 TreeView 元件呈現資料表，元件的供應套件沒有在這輪選定。

這一頁給系統分析師定義一份檢視：畫布上的表、勾選的欄、欄位之間的 JOIN，加上右邊屬性表，編成一句 SQL。查詢結構仍是 SQL 的來源。SQL 區塊顯示編成的語句，不在這塊裡自由改字。這條沿用計畫，這輪沒有改口。

被樣式引用時的鎖定、儲存時由伺服器重編 SQL、預覽最多 100 列，沿用計畫，這輪沒有改這些規則。

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 檢視頁 | 工作台左軌「檢視」 | 定義一份檢視的表、欄、JOIN 與整份查詢屬性 |
| 資料表樹 | 檢視頁左欄 | 只列出資料表，拖到畫布 |

## Voice and Tone

文句短，用這一頁已經在用的詞：資料表、欄位、主鍵、Select、inner、left join、right join、SQL、查詢結果。

| Do | Don't |

| 還沒有可以編成的 SQL | 半句 SQL 配一行抱歉 |

## Component Patterns

行為如下。外觀在 `DESIGN.md` 的同名元件。

### 資料表樹

TreeView。節點只有資料表，不能展開出欄位。拖曳的是整張表。點表名的效果與拖到畫布相同：畫布上出現該表。已在畫布上的表，樹列保持可辨認，再拖一次不複製第二張。

### 畫布表卡

表進入畫布後才列出欄位。每個欄位前方有勾選框。剛放上時只勾主鍵，主鍵因此進入 Select 欄位清單，其餘欄位不勾、不進 Select。之後勾哪個欄，哪個欄就進 Select；取消勾選就離開 Select。主鍵可以取消勾選。

欄位列可以拖。拖的起點不限主鍵。

### JOIN 線

從一張表卡的欄位拖到另一張表卡的欄位，兩端之間出現一條線。這條線的意義是這兩張表 JOIN。新線一律是 inner join。右鍵點在線上，選 inner、left join 或 right join，該線改成所選種類。選單不拿來編輯筆數、篩選或其他整體屬性。

同一對欄位不重複拉第二條線。拖回同一張表的欄位不產生線。

### 屬性表

筆數、不重複、篩選、分組、彙總、排序屬於整份查詢，不屬於某一張表。改任何一項都會重編 SQL。這些控制只出現在畫布右邊的屬性表。

### SQL 區塊

與畫布同時呈現，沒有切換。表、勾選、線、屬性表任一改變，這塊改顯示新的語句。結構還不能編成時，這塊說明原因，不顯示半句 SQL。人不能在這塊直接改字。

### 查詢結果

在 SQL 下面。有可執行的語句時顯示列。沒有列時顯示「沒有符合的資料。」失敗訊息用繁體中文，不含連線字串。未設筆數時最多 100 列並標明已截斷。這段沿用計畫。

### JOIN 選單

只在右鍵點到線時打開，列出三種種類。選完即關閉，線與 SQL 一起更新。

## State Patterns

| Surface | Empty | Loaded | Failure |
|---|---|---|---|
| 資料表樹 | 沒有可綁定的註記時，顯示「資料來源尚未註記」，畫布不接受拖放 | 列出資料表 | 讀取失敗時顯示訊息與代碼，樹是空的 |
| 畫布 | 還沒有表。不使用一大塊教學用虛線區當作主體 | 一張以上的表卡，欄位與勾選如同上節 | 拖到同一張表時不新增線，畫布維持原樣 |
| 屬性表 | 筆數空著代表預覽用 100；不重複未勾；篩選、分組、彙總、排序為空 | 顯示目前整份查詢的值 | 有分組或彙總卻無法編成時，SQL 區塊說明原因，屬性表保留人剛填的值 |
| SQL 區塊 | 畫布沒有表時，說明還沒有可以編成的 SQL | 顯示完整的一句 SELECT | 無法編成時只顯示原因 |
| 查詢結果 | 尚未有語句時不顯示業務列 | 顯示欄名與列 | 執行失敗時顯示中文原因，不顯示業務列 |
| 檢視頁 | 沒有權限時只顯示「沒有權限。」 | 樹與設計區同時在 | 環境尚未完成時沿用既有的前置提示，不打開畫布 |

## Interaction Primitives

- 從樹拖資料表到畫布，或點樹列，把表放到畫布。
- 在表卡上勾選或取消欄位，改變 Select 清單。
- 從表卡的一個欄位拖到另一張表卡的欄位，建立 JOIN 線。
- 右鍵點線，選擇 inner、left join 或 right join。
- 在屬性表改整份查詢的屬性。
- 上述任一改變都重編 SQL，SQL 區塊立即改顯示。
- 鍵盤：勾選框與右鍵選單必須能用鍵盤完成同等操作。樹必須能展開到資料表並把選中的表放到畫布。這輪沒有另定快捷鍵。

## Accessibility Floor

- 樹是 TreeView，表列有名稱。畫布上的表卡有表名。每個勾選框的名稱包含表名與欄名。
- 主鍵除了 `{typography.pk}` 的粗體，勾選框名稱裡也要能知道它是主鍵。不能只靠字重。
- JOIN 線要有文字替代：兩端的表、欄，以及目前種類。右鍵選單的三種種類是文字，不只靠線的顏色。
- SQL 區塊是活區域。語句或失敗原因更新時，使用輔助技術的人聽得到。
- 對比沿用 `DESIGN.md` 的既有墨色與表面，這輪不改色。
- 拖曳不是唯一路徑。點樹列可以放表。右鍵選單的種類也可以用鍵盤選定。欄位之間的連線若無法拖曳，必須仍有鍵盤路徑把兩個欄位連起來。這條路徑的具體控制這輪還沒有指定，實作前要補。

## Key Flows

主角是系統分析師。這輪沒有給個人名字。

### 放上兩張表並連成 inner join

1. 系統分析師打開檢視頁。左欄樹只看到資料表。
2. 把一張表拖上畫布。表卡列出欄位，只有主鍵被勾選，主鍵是粗體。SQL 區塊出現含該主鍵的語句。
3. 再拖進第二張表。第二張同樣只勾主鍵。
4. 從第一張表的一個欄位拖到第二張表的一個欄位。兩張卡之間出現一條線。
5. 高潮：線的種類是 inner join，SQL 區塊同時改成這兩張表的 inner join，人不需要切換畫面才看得到這句。
6. 失敗：欄位拖回同一張表。不產生線，SQL 維持上一句成功的語句。

### 把線改成 left join 或 right join

1. 畫布上已有一條 inner join。
2. 系統分析師在那條線上按滑鼠右鍵。
3. 選單列出 inner、left join、right join。
4. 高潮：選了 left join 或 right join 之後，線的種類改過來，SQL 區塊的 JOIN 關鍵字同時改成對應的那種。
5. 失敗：沒有點在線上。不打開這個選單，線與 SQL 都不變。

# 資料來源註記 — Experience Spine

`DESIGN.md` 是視覺身份。本檔是行為。衝突時以這兩份骨架為準。

詞彙條目與 11-12 PRD 第 3 節逐條相同，定義以該節為準，本檔不重寫：資料來源註記、註記站、資料治理入口、註記包、DBML、H 側、S 側、二代平台資料源、實體表名／實體欄名、已聲明關聯、確認、模組設計工具／檢視／樣式範本／MCP。

## Foundation

單一殼：瀏覽器裡的報表工作台（Workbench.Web，版面是 `WorkbenchLayout`）。沒有命名的元件庫。視覺值全部在 `DESIGN.md`，對應 `Workbench.Web/wwwroot/tokens.css`。

這是內部工具。註記站不讀業務列，個資去識別化處理只保存文字、不執行遮罩。連線字串留在伺服器。

本骨架的 UJ-1 至 UJ-4、FR-1 至 FR-8 只指向 `prd-DBServices-2026-11-12`。資料平面 PRD 與 2026-10-11 架構裡的同名編號是另一份契約，不是本介面的流程編號。從那兩份借用的只有約束：不讀業務列，連線字串不進畫面，錯誤不含秘密。

[ASSUMPTION] 入口代碼是 `governance`，畫面上的名稱是「資料治理」。左軌連結與頁面標題是「註記」。路徑是 `/governance`。一人可同時持有資料治理與系統分析師等其他入口；打開某一站時只看到該站的工作內容。

[ASSUMPTION] 這一輪只改 Workbench.Web。Avalonia 不新增資料治理入口。

三個既有入口的左軌維持現狀。資料治理的左軌在「現在的工作」下只有「註記」。管理員的「環境設定」「帳號」「入口指派」仍在「管理」區，不放進註記站。

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 登入 | 未持有工作階段 | 沿用現況。沒有註冊 |
| 換工作 | 持有兩個以上入口時的左軌 | 選「資料治理」進入註記站。只有資料治理時直接進入註記站 |
| 註記站 | 資料治理入口、左軌「註記」 | 匯入 Excel、讀結構、編輯四層說明、看差異、匯出 DBML、保存草稿、確認 |
| 入口指派 | 管理員左軌 | 沿用現況，多一個可勾選的「資料治理」 |
| 模組設計工具 | 系統分析師入口的「檢視」 | 左側清單只來自已確認註記包。檢視編輯其餘行為維持既有檢視與報表 |

註記站內部不是獨立網址的子站，而是同一頁的區塊：

| 區塊 | 用途 |
|---|---|
| package-bar | 包名、草稿或已確認、匯入、讀結構、匯出、放棄草稿、確認 |
| purpose-field | 整包功能說明 |
| table-list | 這一包的表 |
| table-note | 選中那張表的表註 |
| column-editor | 選中表的欄、型別、欄註、個資處理文字 |
| link-editor | 已聲明關聯與理由 |
| diff-list | 再讀之後的新增、刪除、型別與鍵的改變。沒有差異時不佔版面 |
| dbml-block | 最近一次匯出的 DBML，唯讀 |
| progress-line | 讀取進行中 |
| result-line | 確認成功 |
| status-message | 註記站自己產生的錯誤 |

沒有業務列預覽，沒有連線選擇，沒有自由 SQL。

## Voice and Tone

介面文字、空狀態與註記站自己產生的錯誤使用繁體中文。句子短，說結果與下一步。錯誤同時帶穩定代碼；代碼拼法留給架構。MCP 已回傳的訊息維持宿主原文。

| Do | Don't |
|---|---|
| 資料來源尚未註記 | 尚無資料、請先同步結構 |
| 尚未註記 | 待補、空白、未完成 |
| 草稿 / 已確認 | 未發佈、已上線 |
| 正在讀取結構。 | 正在連線至…，或把這句畫成錯誤 |
| 無法匯入。這份活頁簿對不上字典契約。既有草稿沒有改。 | 只寫「匯入失敗」 |
| 無法確認。這些檢視會落到新包之外：{檢視名稱}。 | 只寫「確認失敗」 |
| 已確認。設計目錄改看這一包。 | 恭喜、成功圖示 |

[ASSUMPTION] 若確認取代了上一份已確認包，成功句接「取代了{舊包名稱}。」零筆連線的訊息說明沒有讀取結構。多於一筆時說明註記站不能選擇連線，而且沒有讀取結構。該筆是待轉資料庫時說明不能用它讀結構或確認。三句都不含連線名稱以外的秘密；連線名稱可以出現，連線字串不可以。

## Component Patterns

行為。視覺在 `DESIGN.md` 的 Components。

| Component | Use | Behavioral rules |
|---|---|---|
| rail-link | 資料治理左軌 | 只有持有資料治理入口才出現「註記」。未持有者沒有這個連結。人正在註記站時，這條使用 rail-link-active。 |
| package-bar | 註記站頂部 | 草稿可編。已確認且仍是設計目錄那一份時，可再讀、可匯出，編輯會進入新的草稿，不直接改已確認內容。被取代的舊包以唯讀打開。 |
| purpose-field | 整包功能說明 | 必填才能確認。可先空白著保存草稿。 |
| table-note | 選中的表 | 可改表註，可以空白。空白不阻擋保存或確認。換表時顯示該表自己的表註。 |
| import-excel | 註記站 | 只接受活頁簿。讀入後帶出實體表與欄、型別、允許空白、唯一索引勾記、描述與個資處理文字。不讀業務列。已有草稿時，再匯入與 read-structure 共用 FR-6 的比對鍵。 |
| read-structure | 註記站 | 沒有連線選擇。恰有一筆組態完整、且是二代平台資料源的具名連線才讀。帶出表、欄、型別、主鍵、外鍵；註解留空。外鍵預填成已聲明關聯。 |
| table-list | 註記站左欄 | 一列一張表。選中後右欄改顯示該表。 |
| column-editor | 選中的表 | 可改欄註。欄註空白允許保存與確認，並顯示 unmarked-badge。個資處理文字可改，不執行遮罩。索引勾記隨來源顯示，人只在說明裡補充，不在這裡改勾記。 |
| link-editor | 註記站 | 可改理由，理由可空白。可補一條庫裡沒有外鍵的已聲明關聯，兩端必須是本包的表與欄。可刪除本包裡的關聯。 |
| diff-list | 再讀之後 | 比對鍵是實體表名加實體欄名，去掉首尾空白後原樣比較，區分大小寫。Excel 再匯入與資料庫再讀用同一條規則，結果寫進目前草稿，不改已確認包。草稿裡已有的同鍵註記保留。草稿沒有、上一份已確認包有的同鍵註記，抄進草稿。改名就是刪除再新增，註記不跟著搬家。另列可見的差異：新增、刪除、型別、可否空白、主鍵、外鍵、唯一索引勾記。人寫過的註解不被來源蓋掉。 |
| dbml-block | 匯出之後 | 顯示這次匯出的 DBML。匯出不要求已對上活庫，也不要求已確認。設計階段不讀這份確認前的檔。 |
| confirm-dialog | 確認、放棄草稿 | 一層。確認前提示若有將被取代的已確認包，寫出它的名稱。放棄草稿寫：「放棄這份草稿？已確認的包維持原樣。」 |
| progress-line | 讀結構或匯入進行中 | 一句「正在讀取結構。」或「正在匯入。」不用 danger，不帶連線字串。 |
| result-line | 確認成功 | `role="status"`。使用 Voice 的成功句。不用 danger。 |
| status-message | 註記站錯誤 | `role="alert"`。人讀的訊息在上，穩定代碼在下。不含連線字串、密碼、堆疊中的秘密、業務列。確認成功與進行中不用這個元件。 |
| unmarked-badge | 欄註空白 | 文字就是「尚未註記」。出現在註記站欄位旁，也出現在模組設計工具的設計清單。 |
| empty-catalog | 模組設計工具左側 | 沒有已確認註記包時只顯示「資料來源尚未註記」。這句與「尚未註記」不是同一句。 |

[ASSUMPTION] 同時只有一份工作中的草稿。再讀更新這份草稿，不另開第三份。被取代的已確認包保留、可從註記站打開唯讀、可再匯出，不能編輯，也不再進入設計目錄。

[ASSUMPTION] 匯出檔名是 `{包名}.dbml`。畫面上先顯示 dbml-block，同時下載該檔。

這一輪只驗收 `Requirements/Samples.xlsx` 的欄位契約。表頭對不上就拒絕匯入，既有草稿不變。「00.資料總表」這類第二種版型不在這一輪；與樣品衝突時以樣品為準，新版型另開需求。

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 未登入 | 登入 | 沿用現況 |
| 沒有資料治理入口 | 任何註記站網址 | 不顯示註記站。沿用工作台「沒有權限。」 |
| 只有資料治理一個入口 | 換工作 | 不停留在換工作，直接進入註記站 |
| 兩個以上入口 | 換工作 | 列出「資料治理」。選了才進入註記站 |
| 無權限 | 入口指派 | 沿用「沒有權限。」不顯示核取方塊 |
| 保存失敗 | 入口指派 | status-message。勾選回到保存前。不新增管理員帳號 |
| 冷開啟、尚無草稿 | 註記站 | package-bar 在，編輯區空。說明可以匯入 Excel 或讀取結構。不顯示空的 diff-list |
| 重開已保存草稿 | 註記站 | 整包功能說明、表註、欄註、關聯與「草稿」徽章都還在。空白欄註仍是空白 |
| 讀取中 | 註記站 | read-structure 與 import-excel 停用。progress-line 顯示「正在讀取結構。」或「正在匯入。」沒有進度百分比，沒有連線字串 |
| 草稿 | 註記站 | 四層可編：整包功能說明、表註、欄註、關聯。徽章「草稿」 |
| 匯入被拒 | 註記站 | status-message。既有草稿的表、欄、註解不變 |
| 零筆、多筆或待轉庫 | 註記站 | 不讀結構。status-message 使用 Voice 裡的三句之一。讀列次數是 0 |
| 差異待處理 | 註記站 | diff-list 出現在編輯區上方。關閉這份草稿之前都留著 |
| 確認被拒 | 註記站 | 對話框關閉，status-message 留下原因。草稿與已確認包都維持原樣。檢視會落到包外時列出檢視名稱 |
| 確認成功 | 註記站 | result-line 顯示成功句。徽章改「已確認」。若有被取代的包，成功句寫出它的名稱。設計目錄改看這一包 |
| 放棄草稿之後 | 註記站 | 若仍有已確認包，打開那一份唯讀。若沒有，回到冷開啟。已確認包不變 |
| 保存或匯出失敗 | 註記站 | status-message。草稿內容與已確認包都不改 |
| 唯讀舊包 | 註記站 | 可讀、可匯出。匯入、讀結構、編輯、確認、放棄都停用 |
| 設計清單為空 | 模組設計工具 | empty-catalog：「資料來源尚未註記」 |
| 欄註空白 | 註記站與設計清單 | unmarked-badge。不阻擋確認，也不阻擋選為檢視輸出欄 |
| 焦點 | 所有上述表面 | 沿用工作台 `:focus-visible`，2px `{colors.ink-primary}` |

離線不在這一輪。讀結構與確認都要打到伺服器；失敗時已確認包與已保存檢視不變。

## Interaction Primitives

- 滑鼠點選與鍵盤 Tab 沿用工作台。主要動作是按鈕，不是拖曳。
- Esc 關閉最上層的 confirm-dialog，不儲存該次確認或放棄。
- 確認與放棄都先經過 confirm-dialog。保存草稿不必再問。
- 讀結構與匯入進行中，這兩個按鈕與確認按鈕停用，避免疊兩次寫入。
- 模組設計工具不能選註記包以外的表或欄，也不能新造關聯。兩張以上來源表時，每一段關聯必須等於註記包裡某一條已聲明關聯的兩端。
- 禁止：連線選擇、自由 SQL、業務列預覽、把註解寫回來源庫、遮罩執行、把資料治理和檢視／樣式／報表收成同一套左軌。

## Accessibility Floor

行為。對比在 `DESIGN.md` 的 Colors，沿用工作台既有配對。

- 介面語言是繁體中文。
- 互動控制項沿用工作台最小高度 36px。
- Tab 順序：左軌、package-bar 的動作由左至右、整包功能說明、表清單、欄註、關聯、差異、DBML。
- 錯誤與確認結果使用 `role="alert"`。徽章「尚未註記」是文字，不只靠顏色。
- 差異列除了顏色，文字要寫「新增」「刪除」或「已改變」。
- `prefers-reduced-motion: reduce` 時沿用工作台，取消 160ms 過渡。
- 不新增只靠懸停才看得到的操作。

只有工作台這一個殼。桌面是主要用法。

## Inspiration & Anti-patterns

來源沒有點名要模仿的產品。下面是這份入口明確拒絕的做法。

- 拒絕把註記站做成第二套查詢工具：沒有自由 SQL，沒有業務列，沒有連線字串欄位。
- 拒絕在註記站選擇「走 MCP 還是走 Web API」，也拒絕讓人選擇具名連線。
- 拒絕把資料治理、檢視、樣式、產生報表收成同一套左軌工作內容。
- 拒絕執行個資遮罩，或把註解寫回來源資料庫。
- 拒絕在模組設計工具讀即時結構來代替已確認註記包。

## Key Flows

### UJ-1. 方晴用 Excel 把清單異動表註記成可確認的 DBML。（FR-2、FR-4、FR-5）

1. 方晴已登入，持有資料治理入口，打開註記站。
2. 她在 import-excel 選 `Samples.xlsx` 這種 H 側／S 側字典。
3. table-list 出現 S 側實體表與欄，column-editor 帶出 H 側型別、描述、唯一索引勾記、允許空白與表級說明。
4. 她在 purpose-field 寫整包功能說明，必要時改 table-note、欄註與 link-editor 的關聯說明，保存草稿。
5. 她匯出 DBML，在 dbml-block 核對。
6. **高潮：** 她按確認。工具把每個實體表名與實體欄名對上二代平台資料源。都對得上，confirm-dialog 通過，徽章改成已確認。模組設計工具的資料表清單出現這份結構與註解。未確認前設計端看不到它。

失敗：活頁簿對不上契約，status-message 拒絕匯入，既有草稿不變。確認時對不上實體名、說明空白、零張表或零個欄，拒絕確認，草稿維持。當時沒有恰好一筆可對帳的二代平台連線，或該筆是待轉資料庫時，也拒絕確認；草稿與已確認包都維持原樣，讀列次數為 0。匯出檔與畫面都沒有業務列和連線字串。來源庫結構沒有被改。

### UJ-2. 方晴從資料庫讀結構，補完註解後才交給設計。（FR-3）

1. 方晴沒有完整 Excel。伺服器已有一筆組態完整的具名連線，而且是二代平台資料源。
2. 她按 read-structure。畫面上沒有連線選擇。
3. 工具帶出表、欄、型別、主鍵、外鍵。欄註是空的，unmarked-badge 出現。外鍵已在 link-editor。
4. 她補整包功能說明、table-note、欄註，並為庫裡沒有外鍵的關係補上已聲明關聯。理由可以空白。
5. **高潮：** 她存草稿、匯出 DBML、確認。確認後的包含她手寫的語意與關聯，設計端看得到。

失敗：零筆連線、多於一筆、或那一筆是待轉資料庫。不讀結構，status-message 說明原因，讀列次數是 0。讀取過程不顯示連線字串，也不讀業務列。

### UJ-3. 林可只依已確認註記包定義檢視。（FR-7、FR-8）

1. 林可已登入，持有系統分析師入口。方晴已確認一份註記包。
2. 她打開模組設計工具。左側清單是這份包的表、欄、型別、註解與已聲明關聯。
3. 欄註空白的欄帶 unmarked-badge。
4. 她選來源表與已聲明關聯，寫名稱、目的、輸出欄與參數，保存並發布檢視。
5. **高潮：** 她選的來源與關聯都在註記包裡。發布後 MCP 目錄出現該檢視。她沒有在這一階段新造資料表關聯。

失敗：還沒有已確認包時，左側只有 empty-catalog「資料來源尚未註記」，不能選表。清單不提供註記包以外的表或欄。她要的關聯不在已聲明清單裡時，保存被拒絕，既有檢視定義不變；status-message 說明這段關聯不在註記包裡。檢視文件仍是名稱、目的、來源表、關聯、輸出欄與參數，沒有業務列與連線字串。

### UJ-4. 來源結構變了，方晴再讀一次並保留舊註記。（FR-6）

1. 方晴先前已確認一包。來源庫新增一欄、刪掉一欄，並改了一欄的型別。林可的設計目錄仍是上一份已確認包。
2. 她再讀一次來源：再按 read-structure，或再用 import-excel 匯入同一份契約的活頁簿。兩條路共用比對鍵：實體表名加實體欄名，去掉首尾空白後原樣比較，區分大小寫。結果寫進目前草稿，不改已確認包。
3. 草稿裡已有的同鍵註記保留。草稿沒有、上一份已確認包有的同鍵註記，抄進草稿。改名就是刪除再新增，註記不跟著搬家。新增、刪除、型別改變進 diff-list。
4. 她調整後保存草稿。在她再次確認前，林可左側仍是舊包。
5. **高潮：** 再次確認時，每一筆已保存檢視的來源表、輸出欄與關聯端點都還在新包裡。設計端改看新包。舊包不再進入設計目錄，但保留不刪，已保存檢視也不改寫。

失敗：再讀失敗時，已確認包與檢視定義不變。確認會讓某些檢視落到新包之外時，拒絕確認，status-message 列出那些檢視的名稱，草稿與已確認包維持原樣。她也可以放棄草稿，已確認包維持原樣。

### FR-1. 管理員可為操作者指派或取消資料治理入口。

1. 管理員打開入口指派，選方晴。
2. 核取方塊多一項「資料治理」。其餘入口照舊。
3. 他按保存。
4. **高潮：** 方晴下次進入工作台，換工作裡出現「資料治理」；若這是她唯一的入口，她直接進註記站。管理員自己若也被指派，同樣看得到，畫面上不能因此出現第二個管理員帳號。

失敗：非管理員打開入口指派，沿用「沒有權限。」取消勾選後保存，方晴再打開時沒有註記站，已確認註記包仍留在設計目錄給仍持有系統分析師入口的人。

## 敏感資料

註記站任一路徑都不讀業務列。確認對帳只核對實體表名與實體欄名是否存在。草稿、已確認包、匯出的 DBML、檢視定義與 status-message 都不含連線字串、密碼、堆疊中的秘密或業務列。個資去識別化處理是欄位上的自由文字，這一輪只保存與顯示，沒有執行按鈕。

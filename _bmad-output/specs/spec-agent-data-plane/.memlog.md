- (decision) 可執行能力只覆蓋 P0。後續階段沒有可測試的成功條件，不編成能力，只記下它們不得跨越的邊界。
- (capability) CAP-1 外部 Agent 能發現固定的唯讀工具，並在已支援的引擎上用相同名稱與參數查詢，而不必得知引擎種類。成功：有測試庫的每個 ServerType 都以相同工具名稱與參數鍵完成 tables、fields、query；客戶端不傳引擎種類；公開 IDbService 與 IDbServiceAsync 簽名不變；既有 REST 與 GraphQL 路徑與查詢形狀不變。
- (capability) CAP-2 呼叫者能對一個具名連線列出資料表與欄位、依整數 id 取一列、依等值條件查列、計數，並判斷列是否存在。成功：回傳與同一條件下的既有 Session Call 一致；空列、計數 0 與存在與否的布林都是成功；參數、缺表與篩選見 readonly-tools.md。
- (capability) CAP-3 營運者只在伺服器組態登記具名連線；呼叫端用名稱選定資料來源，不能交出連線字串。成功：工具輸入沒有連線字串欄位；帶入連線字串時拒絕、不依該字串建立連線、錯誤訊息不回顯該值。
- (capability) CAP-4 每一次呼叫使用恰好一個具名連線。成功：已登記名稱落在該連線；未登記則拒絕且不改落其他連線；省略名稱時只在恰有一個組態完整的連線時採用，否則要求指定名稱。
- (capability) CAP-5 某一個具名連線無法建立或無法開啟時，宿主與其他連線仍接受呼叫。成功：該呼叫回傳連線錯誤且程序不結束；其他連線的唯讀工具仍可呼叫；沒有組態完整的連線時宿主仍能啟動並廣告工具。
- (capability) CAP-6 整合方能事後回答每一次工具呼叫是誰、對哪個具名連線、用了什麼條件、回了多少列或什麼錯誤。成功：成功與被拒絕的呼叫都有紀錄，含時間、呼叫者、連線名稱、工具、參數、列數或錯誤碼；連線字串、密碼與結果列不在紀錄或宿主日誌；紀錄寫不進去時客戶端得不到本次的列、數字或布林。
- (capability) CAP-7 呼叫端不能經由此宿主執行新增、更新、刪除或自由 SQL。成功：廣告清單沒有 insert、update、delete、sql；以這些名稱呼叫得到 tool_disabled 且資料無變更；沒有確認後寫入的入口。
- (constraint) 本產品線不改寫公開的 IDbService／IDbServiceAsync，也不修改 Core、FunctionRegistry 或 Provider，不把 Core 做成會話伺服器。SQL、連線與方言留在現有 C# 路徑。
- (constraint) REST、GraphQL 與 MCP 只經 DbServiceFactory 取得 IDbService。宿主不建立 Provider、不在工具裡分支引擎、不新增 SQL planner。
- (constraint) P0 不部署 Python、不呼叫語言模型、不交付側車。日後側車不執行 SQL、不持有連線字串；失敗時資料層沒有副作用。
- (constraint) 連線字串只存在伺服器組態與既有工廠。工具結構、錯誤訊息、稽核、宿主日誌與日後側車輸入都不攜帶它。結果列不寫進稽核或宿主日誌，也不外送。
- (constraint) P0 的工具是六個唯讀 Session Call，不是八條 REST 路由的包裝。REST 與 GraphQL 的路徑和查詢形狀維持不變。
- (constraint) P0 只提供 Streamable HTTP。日後若做 stdio，必須沿用同一套工具且不改工具參數。這覆寫 PRD 第 8 節第 3 點與 addendum 仍寫的傳輸未決；使用者已在架構階段選定 HTTP。
- (constraint) 沒有呼叫者身分時記為 anonymous，呼叫仍執行。P0 不加入驗證。信任邊界是營運者的網路，出貨時不依 host 名稱過濾。
- (constraint) 等值篩選放在一個 filters 物件，不與 table 同層，避免欄位名與宿主參數碰撞。這覆寫 PRD 把其餘參數直接當成篩選鍵的寫法。篩選值原樣送進 Session，不拼進 SQL。
- (constraint) 關閉工具維持關閉，直到新的需求打開。P0 沒有設定開關可以打開它們，也沒有確認後寫入。
- (constraint) P0 不新增健康檢查、指標，或稽核以外的第二個紀錄出口。不實作稽核保留天數；舊檔由營運者刪除。
- (constraint) 錯誤是結構化物件，含穩定 code 與中文 message，message 不含連線字串、密碼與堆疊中的秘密。宿主不重算列，也不對計數或布林做第二次彙總。碼的閉集、稽核欄位與結果編碼以架構骨架為準。
- (decision) 缺表只對 fields 回 unknown_table。get、query、count、exists 不把缺表改成這個碼。這收窄 PRD 第 11 節對未知資料表一體使用結構化錯誤的寫法。

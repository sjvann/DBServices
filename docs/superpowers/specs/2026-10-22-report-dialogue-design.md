# 對談產生報表

日期：2026-10-22

狀態：待審閱

## 目的

使用者用一句話要報表。工作台先抽出關鍵字，推出已發布模組，再列出涵蓋這些模組的範本讓人挑選。選定後向各模組的 MCP 取數，套進範本。一份範本最多兩個模組。兩個模組可以有 Master-Detail：點第一個模組的一列，才取第二個模組。

對談使用的模組就是已發布檢視。發布之後，該檢視已是 MCP 工具，工具名稱是檢視名稱。這次不把未發布檢視放進工具清單。

## 架構

一次對談的進度放在工作階段，由 `Workbench.Core` 的對話狀態機推進。模型只做兩次判斷。取數沿用 `IViewCaller`，一次一個已發布檢視，引數是連線與該檢視的條件，不送 `filters`。恰好一筆可用連線才呼叫。

新增端口 `ILanguage`。核心只看它的結果，不碰 HTTP。轉接器讀取環境裡已設定的模型，打現有的對話端點。

- `ReadAsync(句子)` 回傳關鍵字與條件值。呼叫失敗或內容打不開時回傳 null。
- `MapModulesAsync(關鍵字, 已發布模組清單)` 回傳模組名稱。呼叫失敗或內容打不開時回傳 null。

工作階段依序是：抽詞、等候挑選、等候補條件、已取出。`Leave` 清掉對談進度與尚未另存的列表。

三個動作：

| 動作 | 輸入 | 時機 |
| --- | --- | --- |
| 送出句子 | `text` | 新的一句、補條件，或在等候挑選時打範本名稱 |
| 挑選範本 | `styleId` | 按下候選按鈕 |
| 點列 | `row`，模組一目前列的 0 起算索引 | 範本有關聯且模組一已取出 |

每次回應都有 `status`、`reason`、`readCount`。`status` 是 `choose`、`need_parameters`、`ready`、`not_ready` 其中之一。`readCount` 等於這一次請求裡檢視呼叫器被呼叫的次數。挑選、補條件未齊、對不上，都是 0。

`ready` 時帶回範本區塊，以及依模組順序排列的結果。每個結果有 `viewId`、欄名、列。環境未完成時，在呼叫模型之前就拒絕，沿用現有的環境訊息。

## 對話步驟

### 抽出關鍵字與條件值

每句新的話都先呼叫 `ReadAsync`。只採用這兩個欄位：`keywords` 是詞的清單，`values` 是條件名對值。空白詞丟掉。條件名必須等於某個已發布模組的查詢條件，大小寫不拘；對不上的值丟掉。

句子裡的 `條件名=值`、`條件名:值`、`條件名：值` 也收。值到空白為止，同一條件採句子裡第一次出現的值，並蓋過模型給的同一個條件。

模型沒有回傳、回傳打不開，或沒有任何關鍵字時，`status` 為 `not_ready`，`reason` 為「模型沒有給出可用的結果。」

### 對模組

一個關鍵字和一個模組的名稱、用途、欄位名或條件名，較短的那一方至少兩個字，而且完整出現在另一方裡，大小寫不拘，這個模組就命中。任一個關鍵字命中即可。

有命中就只用字面結果，不再呼叫 `MapModulesAsync`。同一個模組只算一次。完全沒有命中時才呼叫它，清單只含已發布模組的名稱、用途、欄位與條件。回傳的名稱必須是清單裡的檢視名稱，大小寫不拘。不存在的名稱丟掉。同一個模組只算一次。

`MapModulesAsync` 回傳 null，或清掉之後是空的，`reason` 為「沒有對上的模組。可以用的有：」後面接已發布模組名稱，以頓號分隔。沒有已發布模組時，整句改為「沒有對上的模組。還沒有已發布的模組。」

對上的模組超過兩個時停下來，`reason` 為「對上的模組超過兩個，目前一份範本最多兩個。」

### 列範本

一份使用者讀得到的範本（自己的或共享的）涵蓋這次結果，條件是它綁定的模組包含這次對上的每一個模組。範本可以多帶一個模組，最多仍是兩個。多帶的那個模組仍會在後續取數。模組順序以範本為準：第一個檢視是模組一，第二個是模組二。

候選即使只有一份，也先列出來。`status` 為 `choose`，`reason` 為「要用哪一份範本。」候選含 `id` 與 `name`。沒有候選時，`reason` 為「沒有涵蓋這些模組的範本。這次對上的模組是：」後面接模組名稱。

按下按鈕以 `styleId` 挑選。下一句裡，候選名稱完整出現才算命中，大小寫不拘。同時命中多份時，若較長的名稱包含較短的名稱，只留較長的那一份。剩下恰好一份就選定它。剩下仍多份時停在挑選，`reason` 為「對上不只一份：」後面接那些名稱，再接「請點選其中一份。」一句裡對不上任何候選名稱時，當成新的一句，重新抽關鍵字，並清掉上一份列表。

直接送出讀不到的 `styleId` 時拒絕，代碼 `forbidden`，訊息「不能讀取這個樣式。」讀列次數是 0。

### 補條件

選定範本後，收集這次就要用到的查詢條件：

- 只有模組一時，收集模組一的全部條件。
- 有關聯時，收集模組一的全部條件，以及模組二除了關聯條件以外的條件。關聯條件由點列帶入，句子裡就算寫了也不拿來用。
- 沒有關聯且有模組二時，收集兩邊的全部條件。

兩個模組的條件名稱必須不同，這條在採用範本時就拒絕。已得到的值直接用。還缺的條件使 `status` 成為 `need_parameters`，`reason` 為「還缺」加上條件名，以頓號分隔，例如「還缺姓名。」不呼叫 MCP。

只缺一個條件時，下一句整段去掉前後空白就是那個值，中間可以有空白。缺好幾個時，下一句只認 `條件名=值`、`條件名:值`、`條件名：值`。一個都沒補到，就當成新的一句，重新抽關鍵字。有補到一部分就留下，繼續問還缺的。

### 取模組一，以及沒有關聯時的模組二

條件齊、且恰好一筆可用連線時才呼叫。連線不是恰好一筆時不呼叫，`reason` 沿用「無法決定連線，沒有讀取資料。」

有關聯，或只有一個模組時，只呼叫模組一。工具名稱是檢視名稱，條件是補齊後的條件名與值。

沒有關聯且有模組二時，先呼叫模組一，再呼叫模組二。兩次都成功才把報表放進工作階段。第二次失敗時，工作階段不留下半份報表，不寫生成紀錄；這一次的 `readCount` 仍算進已發出的呼叫。第一次就失敗時不呼叫第二次。

呼叫失敗的 `reason` 沿用 MCP 帶回的訊息，不寫生成紀錄。檢視已不存在時，`reason` 沿用「這份報表現在產生不了。」

成功時 `status` 為 `ready`。畫面套上固定標題、固定文字、條件標籤與值，以及已取回的列表。零列仍是成功。

已取出之後再送出一句新的話，重新抽關鍵字，並清掉這份尚未另存的列表。

### 點列取模組二

只有範本寫了關聯，而且模組一已在工作階段裡，點列才呼叫。`row` 必須落在模組一的列範圍內。超出範圍時不呼叫，`reason` 為「沒有這一列，沒有讀取第二個模組。」

從該列取出關聯欄位的值。欄位不存在時不呼叫，`reason` 為「這一列沒有這個關聯欄位，沒有讀取第二個模組。」欄位存在就呼叫，值照儲存格送出，空字串也送。這個值與事先補好的模組二其他條件一起送出。成功時換掉模組二的列表，模組一保持不變，點中的列記在工作階段。失敗時模組一保持不變，模組二維持點之前的內容，不寫生成紀錄，`reason` 沿用 MCP 的訊息。

沒有關聯時若收到點列要求，不呼叫，`reason` 為「這份範本沒有關聯，沒有另外取數。」

## 範本

範本仍存在樣式。既有欄位保留。新增：

| 欄位 | 意思 |
| --- | --- |
| 第二個檢視 | 選填。空白表示只有模組一 |
| 關聯欄位 | 模組一的欄位名稱。空白表示沒有關聯 |
| 關聯條件 | 模組二的查詢條件名稱。與關聯欄位成對 |

資料庫在啟動時為 `styles` 補上 `second_view_id`、`link_column`、`link_parameter`，既有列為空白。不刪除既有資料表。

表格區塊新增所屬檢視識別。讀到舊區塊時，空白的所屬檢視視為模組一。標題與說明只存固定文字。條件區塊仍存條件名與標籤，執行時顯示這次帶進去的值；關聯條件在點列成功後才有值。

採用時拒絕這些情況，已存的那份不變：

| 情況 | 訊息 |
| --- | --- |
| 名稱空白 | 沿用「名稱不可空白。」 |
| 第一個檢視不存在 | 「找不到檢視。」 |
| 第二個檢視有值但不存在 | 「找不到檢視。」 |
| 兩個檢視相同 | 「兩個模組不能是同一個檢視。」 |
| 關聯欄位與關聯條件只填一邊 | 「關聯要同時指定模組一的欄位與模組二的條件。」 |
| 沒有模組二卻填了關聯 | 「關聯要同時指定模組一的欄位與模組二的條件。」 |
| 關聯欄位不是模組一的欄位，或關聯條件不是模組二的條件 | 沿用「建議含有未知欄名，不能接受。」 |
| 兩個模組有相同條件名 | 「兩個模組的條件名稱重複。」 |
| 某個已綁定模組的表格不是恰好一個 | 「每個模組恰好一個表格。」 |
| 表格欄位不屬於該區塊的模組，或條件區塊的條件不屬於這兩個模組 | 沿用「建議含有未知欄名，不能接受。」 |
| 區塊種類不是標題、說明、條件、表格 | 沿用「建議含有未知欄名，不能接受。」 |

樣式畫面的兩個檢視下拉都只列已發布檢視。換任一個檢視都清掉報表紙上的區塊。選了第二個檢視後，左側條件與欄位分成兩組，各標模組名稱。新增表格時掛到還沒有表格的那個模組。關聯用兩個下拉選單，可以留白。

排出初稿時，只有模組一就沿用現在的標題、說明、條件與一個表格，表格標上模組一。兩個模組都在時，標題用模組一的名稱，說明把兩邊非空白的用途依序接上，中間空一格。每個模組各放一個帶自己全部欄位的表格，條件區塊照各模組的條件排出。關聯不自動填。

終端使用者存回樣式時，新樣式帶上兩個檢視、關聯與區塊，不含列與條件值。

## 對談畫面

仍是產生報表這一頁，文字框保留。

- `choose`：狀態句下面列出候選名稱按鈕。
- `need_parameters`：狀態句寫出還缺的條件，下一句在同一個文字框回答。
- `ready`：依區塊順序畫出標題、說明、條件與值，然後是各模組的表。有關聯時模組一的列可點，點中的列標出來；模組二尚未取回時，表下寫「點一列以讀取第二個模組。」
- 列表出現之後才提供留下紀錄、與其他人共享、存回樣式、匯出 PDF、清掉這次。

## 紀錄與 PDF

工作階段裡的報表與生成紀錄都保存依序的模組結果。`generation_records` 啟動時補上 `modules_json`。舊紀錄這個欄位是空陣列，PDF 與再開仍用既有的那一組欄與列。

留下紀錄時，寫入當時已取回的模組結果。有關聯但還沒點列時，紀錄裡只有模組一。PDF 依區塊順序：標題與說明印固定文字，條件印標籤與值，表格印所屬模組這次的欄與列；該模組還沒取回時，表格為空。再開與匯出不再呼叫 MCP。

## 測試

測試放在現有的工作台測試主機。檢視呼叫用假的呼叫器核對次數、工具名稱、連線與條件。模型用假的 `ILanguage` 回傳，不連真實模型。既有「句子裡要出現樣式名稱」的檢查改為下列對話檢查。

單模組、表格沒標所屬檢視的既有範本：

- 關鍵字字面命中檢視後列出範本並等待，讀列次數 0。只有一份候選也等待。
- 回覆範本名稱後，缺條件則停在「還缺狀態。」這類句子，呼叫次數 0。
- 補上值後恰好呼叫該檢視一次，條件是補上的值，參數裡沒有 `filters`。零列仍是 `ready`。
- 私有範本不出現在別人的候選裡。直接送出讀不到的 `styleId` 得到 `forbidden`，呼叫次數 0。

關鍵字與退路：

- 字面有命中時，`MapModulesAsync` 的次數是 0。
- 字面沒有命中時才呼叫對應，只留下真實的已發布名稱。
- 模型回傳空、或沒有關鍵字，訊息是「模型沒有給出可用的結果。」
- 沒有模組時列出已發布模組名稱。沒有已發布模組時，訊息是「沒有對上的模組。還沒有已發布的模組。」超過兩個模組時停下來。有模組但沒有範本涵蓋時，訊息帶出模組名稱。
- 候選名稱「Users」與「Users明細」同時出現在句子裡時，只留下較長的那一份。兩份都叫 Users 時停在挑選，並請使用者點選。
- 較短的一方只有一個字不算命中。`Users` 對 `Users` 算命中。
- 句子裡的 `條件名=值` 會收下，並蓋過模型給的同一個條件。模型給的未知條件名丟掉。

兩個模組：

- 有關聯時，條件補齊後只呼叫模組一。點列才做第二次呼叫，帶入該列指定欄位的值與事先補好的其他條件。
- 索引超出範圍，或這一列沒有關聯欄位時，不發出第二次呼叫。
- 沒有關聯時，兩邊條件都齊才依序呼叫兩次。第二次失敗時不留下半份報表，也不寫生成紀錄。
- 採用時拒絕：兩個檢視相同、關聯只填一邊、沒有模組二卻填關聯、條件名稱重複、同一模組的表格不是恰好一個、欄位不屬於該模組。既有單模組範本仍可採用。

失敗與留下的結果：

- 可用連線不是恰好一筆時不呼叫，訊息是「無法決定連線，沒有讀取資料。」
- 呼叫失敗時不寫生成紀錄，訊息是呼叫器帶回的那句。
- 離開後再開不呼叫。兩張表都取出後，紀錄與 PDF 含兩邊的欄與列，且不再呼叫檢視。還沒點列就留下的紀錄只有模組一。
- 等候挑選時，對不上候選的新句子會重新抽關鍵字。只缺一個條件時，下一句整段成為那個值。

## 範圍

這次做到最多兩個模組、固定標題與說明、一個模組一張表、可選的一條 Master-Detail，以及上面的對談步驟。檢視的執行方式、發布後才成為 MCP 工具、恰有一筆可用連線才取數，都維持現狀。
